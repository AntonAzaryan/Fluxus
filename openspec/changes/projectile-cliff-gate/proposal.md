# projectile-cliff-gate: нулевой допуск направленного гейта обрыва

## Why

Снаряд демо должен вести себя на рельефе как юнит: лететь по склонам, пролетать с верхнего уровня на нижний и взрываться о подъём. PHYS-11 уже даёт направленный гейт («спуск свободен с любой высоты»), но включается он только при `cliffRise > 0`, а допуск — целое число уровней: для одноуровневых возвышенностей «вниз можно, вверх нельзя» невыразимо — `cliffRise: 1` пропускает и подъём на один уровень, `cliffRise: 0` блокирует обе стороны.

## What Changes

- Отрицательный `cliffRise` активирует гейт с нулевым допуском подъёма: любой подъём блокируется, спуск свободен. Правило блокировки не меняется (`rise > cliffRise`), меняется только условие «гейт выключен»: с `cliffRise <= 0` на `cliffRise == 0`. Существующий контент (`cliffRise` 0 или положительный) ведёт себя байт-в-байт как раньше.
- Контент демо: снаряд получает `cliffRise: -1` — летит по склонам и вниз с обрывов, взрывается о подъём; четыре возвышенности арены становятся одноуровневыми с сохранением подъёмов-рамп (отдельные контентные коммиты в этом же чейндже).

## Impact

- `engine/core-ts/src/systems/collisionGeometry.ts` — условие активации гейта в `cliffGateOpen`; тесты PHYS-11 на отрицательный допуск.
- Golden-эталоны: без изменений — ни один существующий сценарий не несёт отрицательный `cliffRise`.
- Контент: `content/scenes/duel.scene.json` (коллайдер снаряда, карта уровней), тесты демо.
- Отклонение, найденное при реализации: нормировка `cliffRise < −1` к `−1` потребовала строки кода, вопреки исходной записи в design.md («формула даёт это сама») — без неё голое `rise <= cliffRise` блокировало бы спуск на единицу при `cliffRise = −4`. Пункт design.md исправлен по факту; поведение спеки (PHYS-11) не менялось.
