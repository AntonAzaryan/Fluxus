# Design: projectile-cliff-gate

## Context

См. proposal.md. `cliffGateOpen` (`engine/core-ts/src/systems/collisionGeometry.ts:159-166`) уже реализует направленность: `rise = знак шага → levelPos/levelNeg`, блокировка при `rise > cliffRise`, спуск свободен. Единственное препятствие — условие активации `if (cliffRise <= 0) return false;`, из-за которого «гейт с нулевым допуском» невыразим: `0` зарезервирован под «гейта нет», а допуск — целые уровни.

## Goals / Non-Goals

**Goals:** выразить «спуск свободен, любой подъём блокирован» одним значением поля, не меняя поведения ни одного существующего значения (`0`, положительные).
**Non-Goals:** новые поля коллайдера; изменение формулы блокировки; изменение семантики уровней террейна.

## Decisions

- **`cliffRise < 0` вместо нового булева поля.** Условие активации меняется с `cliffRise <= 0` на `cliffRise === 0`; формула `rise > cliffRise` при `cliffRise = −1` даёт ровно требуемое (подъём ≥ 1 блокирован, спуск ≤ −1 разрешён). Одна строка в ядре, ноль новых полей, схема компонента не меняется (`i32` уже допускает отрицательные). Альтернатива — отдельный флаг `cliffGate: bool` — чище читается, но расширяет схему коллайдера и все зеркала (схемы, i18n редактора) ради семантики, которую знак уже выражает.
- **Значения < −1 эквивалентны −1** — нормируется в спеке, кода не требует (формула даёт это сама).
- Контент: снаряд получает `cliffRise: −1`; карта — четыре плато уровня 1 с рамповыми коридорами (флаги `^`), геометрия коридоров сохраняется.

## Risks / Trade-offs

- [Отрицательное число в поле «допуск» читается неочевидно] → семантика проговорена в спеке (PHYS-11) и в подсказке поля в бандлах редактора, если таковая есть — проверить ED-28-гейт.
- [Golden-эталоны] → ни один существующий сценарий/фикстура не несёт отрицательный `cliffRise` (проверить grep'ом); поведение `0`/положительных не меняется байт-в-байт.
