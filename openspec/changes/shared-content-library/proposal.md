# Proposal: shared-content-library

## Why

Базовые геймплейные понятия — «юнит» с параметрами передвижения (скорость, разгон, торможение), «летает или нет», «есть атака» — нужны каждой арене, а конфиг сцены самодостаточен (SER-7): компоненты, prefabs и системы живут внутри одного документа. Пока сцена одна, это не болит; со второй сценой общие понятия начнут молча расходиться копипастой — механизма «это пришло из общей базы, и база уехала» не существует. Нужна общая библиотека контента и правило её доставки в сцены, зафиксированные до того, как появится второй потребитель.

## What Changes

- Библиотека авторского контента в дереве контента (`content/lib/`): триады «схема компонента + JSON-системы, её читающие + базовые prefabs», вместе с парными записями манифеста визуалов (таксономия юнита — ED-19). Аналогия — стандартный ростер Warcraft 3, доступный любой карте.
- Деривация в сцене: prefab сцены объявляет базу из библиотеки и переопределения полей — по семантике CMD-6 (состав компонентов задаёт база, переопределение задаёт только значения); кастомный объект карты из той же аналогии.
- Мёрж — на этапе авторинга, не загрузки: инструмент вливает библиотечные фрагменты в `*.scene.json` через операционный слой `editor/core-ts` и канонический save (ED-29, ED-21) — тем же путём, что Blender-импорт (BLND-5). Сцена на диске остаётся самодостаточной, SER-7 не меняется, `contentPackHash` (NET-17), битовые id компонентов и совместимость снапшотов не затрагиваются. Ядро о библиотеке не знает; WC3-модель «мёрж базы и дифа на загрузке карты» отвергается сознательно — она же источник его боли «патч поменял баланс под старыми картами».
- Синхронизация — по канону `bots:sync` (BOT-13): CLI — перо дизайнера, а расхождение сцены с библиотекой ловит тест внутри `npm run check`.
- Маркировка происхождения в документе сцены: что влито из библиотеки, что локально, — иначе sync не отличит ручную правку от дрейфа базы.

## Capabilities

### New Capabilities

- `content-library`: формат библиотеки, правила деривации и переопределения, мёрж на этапе авторинга, инструмент синхронизации и его гейт-тест. Префикс требований — LIB- (свободен, сверено 2026-08-30).

### Modified Capabilities

- `game-content`: поддерево библиотеки в дереве контента и его отношение к сценам (новое требование, следующий свободный — CONT-7).
- `editor`: операции авторинга над библиотекой и деривацией (новое требование, следующий свободный — ED-33).
- `serialization`: намеренно НЕ меняется — самодостаточность конфига сцены (SER-7) — опора этого изменения, а не его жертва; если design обнаружит обратное, это повод пересмотреть design, а не SER-7.

## Impact

Новое поддерево `content/lib/`; формат маркировки в `content/scenes/*.scene.json` (деталь — в design); `editor/core-ts` (операции, sync); CLI по образцу `npm run bots:sync`; тест синхронизации в гейте. Пакеты движка не затрагиваются: загрузчик ядра библиотеку не читает.

## Notes

Стаб: артефакты specs/design/tasks пусты намеренно, продолжение — `/opsx:update shared-content-library`. Отложено сознательно: пока общего контента нет (одна сцена, ростер базовых юнитов не начат), реализация ценности не несёт — предложение фиксирует решение, а не запускает работу. Триггер продолжения — вторая сцена или первый переиспользуемый юнит.

Решить в design: формат деривации (extends + overrides; может ли деривация добавлять компоненты сверх базы — CMD-6 для спавна это запрещает, для авторинга вопрос открыт); хранит ли сцена диф или запечённые значения (склонность — запечённые значения плюс маркировка, диф живёт в библиотечной связи); формат маркировки происхождения и её судьба при ручной правке влитого; устойчивость порядка компонентов при вливании (битовые id — формат снапшота, SER-7); связь с парной записью манифеста визуалов (ED-19: юнит расщеплён на sim-prefab и запись манифеста — библиотека обязана нести обе половины); имя и место CLI.

**Резервация номеров (сверена 2026-08-30).** Требование `game-content` метится CONT-7, требование `editor` — ED-33: это следующие свободные номера своих префиксов. Основание — main занят по CONT-6 и ED-32 (`openspec/specs/game-content`, `openspec/specs/editor`), открытые чейнджи номеров выше не держат (сверены proposal и дельты всех открытых). Префикс LIB- в спеках и коде не встречается. При превращении стаба в настоящее предложение номера и префикс сверяются заново (`openspec/specs/` плюс дельты открытых чейнджей): резервация в стабе живёт ровно до следующего заархивированного чейнджа в тех же capability.
