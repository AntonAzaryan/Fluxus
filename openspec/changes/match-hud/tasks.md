- [ ] 1.1 Завести `engine/hud-ts` (`@game-mvp/hud`) в workspace: package.json (зависимость только `@game-mvp/client`), tsconfig, vitest; `npm run check` зелёный с пустым `src/index.ts`

## 2. Модель композиции и реестры

- [ ] 2.1 Тип `HudComposition` — JSON-сериализуемое значение (виджет-вид, зона, params, bindings и actions по именам); тест сериализуемости round-trip (HUD-4)
- [ ] 2.2 Реестры видов виджетов, именованных селекторов и именованных действий; резолв композиции с внятной ошибкой на неизвестное имя
- [ ] 2.3 Интерфейс `HudWidget` (mount/update/dispose): виджет получает отрезолвленные значения селекторов и фасад действий; тест «смена композиции не трогает код виджета» (HUD-4, сценарий «другой арене — другой HUD»)

## 3. Оверлей-хост и подписка на доставку

- [ ] 3.1 Оверлей-хост поверх canvas: словарь зон, `pointer-events: none` на корне и `auto` на интерактиве; тест прохождения указателя вне интерактивных элементов (HUD-3)
- [ ] 3.2 Подписка на доставку `remoteHost`: обновление по каденсу доставки, reliable-события списком с номерами тиков ровно один раз, снап по признаку разрыва; тесты сценариев HUD-5 («пять пропущенных тиков», «перемотка»)
- [ ] 3.3 Фасад действий поверх отправителя обратного канала: именованное действие → тот же семантический ввод, что у клавиатурного биндинга; тест «кнопка неотличима от клавиши» (HUD-2)
