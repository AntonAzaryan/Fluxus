- [x] 1.5 Проверить, что диапазон сообщения не пересекает границу эпохи: `from`/`to` относятся к одной эпохе, объявленной сообщением

## 3. Сервер

- [ ] 3.1 `engine/net-ts/src/server/matchServer.ts`: на каждом исполненном тике, на том же месте порядка обработки, где формируются персональные снапшоты (NTR-3), отобрать события тика по каждому активному `viewpoint` вызовом фильтра ядра; накопить уже отобранное
- [ ] 3.2 Пометить `ponytail` место вызова: отбор идёт через `filterSnapshot`, копирующий мир; узкий вход ядра — отдельное изменение по NTR-1
- [ ] 3.3 Накопитель — кольцо пачек по `viewpoint` (не по соединению), глубиной «период рассылки × (глубина повтора + 1)» тиков; при совпадении `viewpoint` у двух соединений пачка одна
- [ ] 3.4 На рассылке отправить каждому соединению `Events` с объявленным диапазоном — тики текущей рассылки плюс повторяемые; сообщение уходит и тогда, когда событий в диапазоне нет
- [ ] 3.5 Наблюдатель (`VIEWPOINT_ALL`, NTR-9) получает поток тем же путём, без отдельной ветки
- [ ] 3.6 Перед `End` слить накопленное: `Events` уходит раньше `End` в том же `drain()`, соединение закрывается после
- [ ] 3.7 Проверить, что `Snapshot` не изменился ни полем, ни смыслом, и что канонический `inputs[]` (NTR-8) от потока событий не зависит
- [ ] 3.8 Штамповка эпохи текущей ветви (NTR-16) в каждое исходящее `Events`; на смене эпохи текущий диапазон закрывается, следующее сообщение открывает новый
- [ ] 3.9 На смене эпохи кольцо накопленных пачек сбрасывается: пачки стёртой эпохи не повторяются — по паре они меньше курсора получателя и приняты быть не могут
- [ ] 3.10 Тики, исполненные внутренним реплеем (`isReplay = true`, `snapshot-rewind` REW-4), в накопитель не попадают: сетевой слой — потребитель `TickResult` и дедуплицирует их по `tick-loop` OBS-5
- [ ] 3.11 Шов с `filter-ownership`: шина, уезжающая в кадре `Snapshot`, — отобранная проекция NET-18, отобранная тем же вызовом фильтра и на том же тике, что и поток `Events`; своего второго отбора здесь не заводить (NET-13)

## 4. Клиент

- [x] 4.1 `engine/net-ts/src/client/matchClient.ts`: курсор потока событий — номер последнего применённого тика, отдельный от курсора применённого снапшота (NTR-10)
- [x] 4.2 Применение `Events`: пачки тиков больше курсора — по возрастанию тика, внутри тика — в присланном порядке (EVT-2); тики не больше курсора отброшены; курсор двигается до конца объявленного диапазона, а не до последнего непустого тика
- [x] 4.3 Разрыв диапазона (`from` больше `курсор + 1`) — отдельный счётчик, курсор перескакивает; догадок и запросов нет
- [x] 4.4 Наблюдаемый выход потребителю — рядом с принятыми снапшотами и счётчиками (NTR-12); шину снапшота для представления не открывать вовсе
- [x] 4.5 Проверить, что отброшенный устаревший снапшот не двигает курсор событий и наоборот
- [x] 4.6 Курсор потока событий — пара `(эпоха, тик)`, сравнение лексикографическое (NTR-16); пачки с парой не больше курсора отбрасываются, остальные применяются по возрастанию пары
- [x] 4.7 Рост эпохи в `Events` разрывом диапазона не считать: курсор перескакивает на начало диапазона новой эпохи, счётчик разрывов не растёт

- [ ] 6.5 Повторно доставленный тик применяется один раз
