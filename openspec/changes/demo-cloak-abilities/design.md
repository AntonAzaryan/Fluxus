# Design: demo-cloak-abilities

## Context

Мотивация — `proposal.md`. Всё, что нужно, уже есть механизмом: каналы и списки источников (FOW-3), таблица мягких каналов сцены (FOW-12, `softStealthChannels`), бафф со статовой правкой в `StealthSources`, реакциями на события и различимой причиной снятия (BUFF-2/5/6), фазы каста с `onEnter`/`timeout` (ABIL-4), слот-компоненты и события как триггеры босса (NPC-7, `BossCharge`), состояния локомоушена в компоненте (`LocomotionState.state`: 0 normal, 1 dodge, 2 roll, 3 airborne, 4 window), `forEachEvent` и запросы по слотам в JSON-системах (`BossCastHold` — образец обхода слотов владельца). Тик — 60 в секунду (`duel.match.json`).

Механизм/политика: весь change — политика: числа, фазы, каналы, кто и когда снимает невидимость — данные сцены; ядро и рендер не меняются. Подача — за `stealth-render-looks`; до него работает плейсхолдер `stealthTint.ts`.

## Goals / Non-Goals

**Goals:**

- Обе способности целиком в JSON сцены; ноль правок `engine/`.
- Один механизм разрыва невидимости на героя и босса — событие, на которое баффы реагируют сами.
- Затухание как доставленное состояние, пригодное и плейсхолдеру, и будущему стелс-виду.
- Бот умеет нажать «инвиз» хотя бы наивно (BOT-13 требует аннотации на каждую способность героя).

**Non-Goals:**

- Детекция в сцене (способность-детектор, вард) — отдельный контент.
- Отдельная логика бота «под невидимостью» — бот жмёт по общей модели скоринга.
- Подача — секция `stealth` парного документа не добавляется: умолчания плейсхолдера, затем умолчания FOW-13.

## Decisions

1. **Каналы: 0 — мягкий «силуэт», 1 — жёсткий «полный».** `softStealthChannels: [0]`; маски источников — `1` и `2`. Босс и миньоны ходят только каналом 0; герой — 0, затем 1. Иерархии детекции сцене не нужны — детекторов нет.

2. **Затухание — фаза каста, стелс — баффы, переход фаз — цепочкой `onExpire`.** `cloak`: фаза `fade` (`trigger: auto`, 60 тиков, `onEnter` кладёт `Cloaking { startTick: tick, ticks: 60 }`, `timeout → commit`); эффекты коммита — при ещё стоящем `Cloaking` (иначе каст сорван разрывом): снять `Cloaking`, положить `Cloaked`, заспавнить инстанс `heroCloakSoft` (60 тиков, `statMods` → `StealthSources` со значением `1`). `heroCloakSoft.onExpire` при `dispelled == 0` спавнит `heroCloakHard` (300 тиков, значение `2`), при снятии — убирает `Cloaked`; `heroCloakHard.onExpire` убирает `Cloaked` всегда. Итого 60 + 60 + 300 = 420 тиков = 7 с от каста. Бафф вместо ручной системы «тикнуть и снять» — BUFF-6 прямо запрещает удаление инстанса мимо признака; два баффа вместо одного с перевешиванием — у баффа нет действия «сменить статовую правку на середине», а цепочка через `onExpire` — штатный путь и ровно сценарий FOW-12.

3. **Разрыв — событие `CloakBreak { entity }`, баффы снимают себя сами.** Каждый бафф невидимости несёт `triggers: [{ type: "CloakBreak", as: "ev", do: [если `eventField(ev, entity) == target` → `dispelled: 1` на инстансе] }]`. Так тому, кто рвёт невидимость, не нужно знать ни индекса определения, ни идентификатора источника (BUFF-4 выводит его из инстанса), ни того, сколько баффов висит. Альтернатива — снимать по `class: positive` — сняла бы и щит.

4. **Кто эмитит `CloakBreak` у героя — JSON-система `CloakBreak`.** Запрос: герой с `Cloaked` либо `Cloaking` (два запроса или один с `hasComponent` в теле). Разрыв, если: `LocomotionState.state ∈ {1, 2, 3}` (рывок, перекат, прыжок); у любого слота владельца, кроме слота самого `cloak`, `phase >= 0` (фазовые касты — заряд фаербола, прицел захвата — ловятся в тик начала фазы); в шине тика есть событие мгновенного каста, называющее героя (`ShieldCast`, `SlowDomeCast`, `CastFireball` броска — по полю `entity`; `$rewind/request` — по `initiator`). При разрыве система эмитит `CloakBreak`, снимает `Cloaking` и `Cloaked`; фаза `fade` при снятом `Cloaking` коммитится вхолостую (решение 2). Порядок `order` — после платформы способностей и локомоушена (их якоря DET-9) и до системы баффов того же тика, чтобы снятие случилось в тик разрыва; точное число — по шкале сцены, проверяется тестом «разрыв в тот же тик». Альтернатива — `triggers` баффа на каждый тип события каста — не ловит рывок, прицел захвата и ульту без события; альтернатива «действие снятия в каждой способности» — семь копий одного снипета.

5. **Босс: `bossCloak` тем же составом, разрыв — из `bossCharge`.** Триггер — событие `BossCloak` от поведения `arenaBoss` (новое действие `cast`, слот 6: соображения — `abilityReady`, `targetKnown`, дистанция средняя; вес ниже разгона, чтобы босс не прятался вместо атаки); кулдаун 1200 тиков. Фаза `fade` 60 тиков кладёт `Cloaking` на босса и на каждого живого миньона (`forEach` по `BossMinion` без `Dead`); коммит спавнит `bossCloak` (240 тиков, значение `1`) и `Cloaked` на босса и на тех же миньонов, снимает `Cloaking`. Разгон: `onEnter` фазы `aim` эмитит `CloakBreak` для босса и каждого миньона и снимает с них `Cloaking`/`Cloaked` — баффы гаснут своими реакциями. Прочие касты босса и атаки миньонов невидимость не трогают: у них нет ни события, ни системы. Миньоны, заспавненные после каста, баффа не получают (решение владельца).

6. **Босс без детекции останавливается.** Детекции никому не даём: по NPC-10 скрытый герой выпадает из выбора целей босса и миньонов, а `seekTarget` без цели даёт стояние. Это желаемое поведение, тест фиксирует: герой под мягким каналом в радиусе `sense` — босс без цели.

7. **Слоты, ввод, HUD.** Хвост слотов: герой — `SlotCloak` (`slotIndex 7`, `abilityId` по позиции в таблице), босс — `SlotBossCloak` (`slotIndex 6`); оба спавнятся в `GrantSlots`/`GrantBossSlots`. Бит действия `cloak: 8` в `ACTION_BITS` (`sim.ts`), `bindings.json`: `KeyC`, геймпад `10`, тач-кнопка; иконка `visuals/icons/cloak.svg` в `ABILITY_ICONS` HUD. Биты 8 и 9 сегодня — `confirmBit`/`cancelBit` захвата: сверить раскладку, при коллизии взять следующий свободный бит.

8. **Доставка затухания.** `extractor.ts`: статы `cloakStart` (`Cloaking.startTick`) и `cloakTicks` (`Cloaking.ticks`), состояния `Cloaking`/`Cloaked` в словаре состояний (CAM-6) — для клипов манифеста и будущего вида. Плейсхолдер `stealthTint.ts` ведёт непрозрачность по `(tick − startTick) / ticks` из доставленного тика — тот же контракт, что примет `stealth-render-looks`.

9. **Боты.** `duel.bots.json`: `cloak: { target: "threat", range: 8 }` — «прятаться при угрозе»; `npm run bots:sync` дописывает записи в профили; `botsSync.test.ts` — гейт. Бот под невидимостью ведёт себя как прежде — кастует и тем самым снимает её; умнее — не задача этого change.

10. **Журнал и анимация.** `duel.dictionary.json`: `HeroCloak` (каст героя), `BossCloakStart`, `CloakBreak` — с семантикой и полями цели (DIAG-10). Манифест: `HeroCloak → "Spell"`, `BossCloakStart → "Spell Defend"` (клипы модели `SkeletonBarbarian.mdx`).

## Risks / Trade-offs

- [Порядок систем: `CloakBreak` раньше эмита событий каста или позже системы баффов] → разрыв опоздает на тик или не случится; тест «щит под невидимостью снимает её в тот же тик» и «рывок — в тот же тик».
- [Слот `cloak` сам в фазе `fade` — система приняла бы его за чужой каст] → исключение по `slotIndex` слота `cloak`; тест «затухание не рвёт само себя».
- [Коммит после разрыва во время `fade`] → эффекты коммита под условием `hasComponent(owner, Cloaking)`; тест «каст щита на 30-м тике затухания — баффа нет, кулдаун взведён».
- [`removeComponent` отсутствующего компонента] → тотален (no-op, `commands.ts`), лишних проверок не нужно.
- [Бот жмёт `C` невпопад и тут же снимает кастом] → допустимо; аннотация `threat` держит частоту низкой.
- [Свободных слотов `StealthSources` четыре по умолчанию] → у героя одновременно не больше одного источника, у миньона — одного.
- [Число миньонов в `forEach` фазы босса] → десятки, один раз на каст; в счётчики PERF-3 демо не входит.

## Migration Plan

Только контент и сборка демо; матчи прежних записей — фикстуры движка и не меняются. Откат — удаление записей сцены, биндинга и иконки; ни один эталон не трогается.
