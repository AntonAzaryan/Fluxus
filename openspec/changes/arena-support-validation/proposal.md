# Proposal: arena-support-validation

## Why

ARENA-3 нормирует: значение `ArenaState.support` вне диапазона `[0, 1]` SHALL отвергаться валидацией, и сценарий требования явно покрывает обе дороги — «в prefab **или мутацией**». Реализация проверяет только префабы сцены (`sim/scene.ts` — `checkArenaSupport(def.prefabs ?? [])`): override размещения — часть того же пути загрузки по SER-8 (`initial` сцены, сценарий, конфиг матча) — проходит лишь общую проверку представимости, а рантайм-мутация поля (`setField`/`modifyComponent`) не проверяется вовсе. Эмпирически подтверждено код-ревью 2026-08-24: `initial: [{prefab: 'Unit', overrides: {ArenaState: {support: F(3)}}}]` грузится без ошибки, после чего `standsOnFloor` молча считает опорный диск в 3× инрадиуса коллайдера — сущность над дырой «стоит на полу». По CORE-3 дефект в реализации; изменение закрывает разрыв и нормирует точку принуждения для половины «мутацией», которую сценарий называет, но ни одно требование не приземляет.

## What Changes

- Проверка диапазона `support` на всём пути загрузки: overrides размещений `initial` сцены, сценария и конфига матча (SER-8) — той же валидацией, что уже отвергает префаб (единый валидатор поля, не вторая копия правила).
- Решение и норма для рантайм-мутации: отвергать при записи, клампить или ловить статической проверкой DSL (SYS-3) константные значения вне диапазона — что именно, решает design; сегодня сценарий ARENA-3 обещает отказ, а реализация не даёт ничего.
- Тесты сверх префабного пути: сегодня `arena.test.ts` пинит только его.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `arena`: уточнение ARENA-3 — где живёт проверка каждой из двух дорог сценария; если design решит вынести точку принуждения мутаций в отдельное требование — следующий свободный номер ARENA-7.

## Impact

Пакет `engine/core-ts`: `sim/scene.ts` (валидация размещений), `systems/arena.ts` (владелец правила), возможно `dsl/` (статическая проверка констант). Контент не затрагивается: ни один отгруженный документ не держит `support` вне диапазона, golden-базлайны не меняются.

## Notes

Стаб: артефакты specs/design/tasks пусты намеренно, продолжение — `/opsx:update arena-support-validation`. Решить в design: (1) единая точка валидации — field-валидатор `ArenaState.support`, который зовут и префабный чек, и размещения, — или проверка в каждом вызове `applyPlacement`; (2) судьба рантайм-мутации — отказ при записи ломает симметрию «`setField` проверяет только представимость», кламп молча правит замысел дизайнера, статическая проверка DSL ловит лишь константы; (3) не повторить вторую копию правила диапазона (сегодня оно живёт в `systems/arena.ts`). **Резервация номера (сверена 2026-08-24):** новое требование, если понадобится, метится ARENA-7 — main занят по ARENA-6, дельты открытых чейнджей номеров ARENA не держат. Скорее всего хватит модификации ARENA-3 без нового номера. При превращении стаба в настоящее предложение номер сверяется заново.
