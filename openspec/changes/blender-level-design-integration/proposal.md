# Proposal: blender-level-design-integration

## Why

Инвестиция в собственный редактор как в инструмент level-дизайна оказалась слишком дорогой: качество расстановки, снаппинга и организации сцены, которое даёт Blender, своими силами недостижимо в разумный срок. Отчёт `docs/reviews/2026-08-09-blender-level-editor.md` (импорт исследования) рекомендует проверенный индустрией путь — DCC-как-редактор-уровня через glTF: авторинг арены в Blender, экспорт `.glb` с custom properties, тонкий TypeScript-импортёр в наши sim/presentation-документы. Blender становится полноценным редактором level-дизайна; собственный редактор остаётся превью и инструментом data-driven-авторинга (системы, схемы, prefabs, манифест), но в сторону level-дизайна больше не развивается.

## What Changes

- Новая capability `blender-pipeline`: строго одно-направленный конвейер «Blender → движок». Источник `.blend` парен сцене по имени (по образцу PRES-1), экспорт — glTF с custom properties, импортёр переписывает **только** производные данные пространственного слоя: поле `initial` конфига сцены (SER-7, SER-8), `decorations` парного presentation-документа (PRES-2), а при соответствующих объектах источника — ассет террейна (TERR-3) и карту кривизны (ASSET-7); остальные поля документов импорт не трогает байт-в-байт.
- Полный level-дизайн в Blender: расстановка юнитов/props/decorations (BLND-3), террейн — дискретные уровни, рампы и пол с клеточных данных terrain-объекта (BLND-9; cliff-геометрия остаётся производной, TERR-5), кривизна — сэмплирование и квантование в алфавит ASSET-7 (BLND-10).
- Импорт детерминирован и атомарен: повторный импорт — пустой дифф; порядок записей — детерминированная функция источника; квантование (Q16.16 для сим, шаг PRES-3 для decorations, целые уровни для террейна) выполняет импортёр; ошибка — ничего не записано (BLND-4, BLND-6).
- Импортёр — headless-потребитель слоя операций `editor/core-ts` (ED-29) и канонического сохранения (ED-21): второй реализации валидации, сериализации и правил порядка не появляется (дух ED-1).
- Аддон Blender — основная поверхность авторинга (BLND-8): панели типизированных свойств, операторы, кисти террейна/кривизны с превью производных клифов; перечни и правила приходят из опубликованных схем и каталогов (SER-5, ED-30) и dry-run импортёра — аддон правил не владеет; гарантия остаётся за импортом.
- Паритет визуала (BLND-11): модели контента — glTF (один файл для Blender и движка; загрузчик по ASSET-3, MDX остаётся историческим форматом реестра); камера превью Blender — из машинного адреса единого конфига камеры; превью террейна — приближение, правда — кадр движка.
- Цикл hot-reload (BLND-12): «сохранил в Blender — увидел в кадре движка» за секунды, переподачей документных источников (REND-11/14/17/18, CAM-7) без перезапуска.
- Единый конфиг камеры получает машинный адрес — секцию манифеста визуалов (**MODIFIED** CAM-1, новый ASSET-10): закрывает известную дыру «у конфига CAM-1 нет адреса» (ревью 2026-08-06, Т5).
- Рантайм движка и клиента не читает `.blend`/`.glb`; тесты движка, редактора и импортёра не зависят от Blender (BLND-7).
- Пространственный слой Blender-сопряжённой сцены — производные данные: правка мимо импорта подсвечивается валидацией через существующие реестры вкладов (ED-25, ED-8) — без новых требований к `editor`.
- **Ревизия кросс-зависимостей**: `editor` нормативно не меняется — ED-требования описывают сохраняемое поведение; «заморозка» level-дизайн-направления — роадмап. Стаб `terrain-texturing` пересматривается: клауза «кисть заливки в editor» снимается в пользу конвейера Blender (правка его `proposal.md` — задача этого change).

## Capabilities

### New Capabilities

- `blender-pipeline`: Blender как полноценный редактор level-дизайна и одно-направленный импорт glTF → sim/presentation-документы: парность источника по имени, конвенции экспорта и метаданных, детерминизм и квантование импорта, владение пространственным слоем (расстановка, decorations, террейн, кривизна), аддон как основная поверхность авторинга, паритет визуала, цикл hot-reload, изоляция от рантайма и тестов движка. Префикс требований — `BLND-`.

### Modified Capabilities

- `presentation-scene`: PRES-2 — правила порядка записей `decorations` оговариваются для производного (Blender-сопряжённого) слоя: порядок задаёт импорт, а не «дописывание в конец»; PRES-3 — квантование выполняет записывающий инструмент авторинга (редактор **или** импортёр), а не только редактор.
- `game-content`: новый CONT-6 — авторские источники (`.blend`, экспортированный `.glb`) в дереве контента: где лежат, ни один канал загрузки (SER-7, ASSET-1) их не читает, читает только импортёр; производные документы остаются тем, что пиннит `worldInit` и голдены.
- `camera`: CAM-1 — единый конфиг камеры получает машинный адрес (секция манифеста визуалов, ASSET-10); значения игрового кадра все потребители читают из одного документа.
- `assets`: новый ASSET-10 — необязательная секция конфига камеры в манифесте визуалов; presentation-данные, неизвестный параметр — предупреждение и пропуск (симметрия с ASSET-8).

## Impact

- **Новые инструменты**: пакет импортёра (Node/TS, зависимости — `editor/core-ts`, `engine/core-ts`; парсинг glTF с бинарными буферами — свой, без three.js); Python-аддон Blender в `tools/blender-addon/` вне npm-workspace и вне гейта; watch-процесс hot-reload. CI/`npm run check` получает тесты импортёра на закоммиченных `.gltf`/`.glb`-фикстурах — без Blender-бинаря.
- **`engine/assets-ts`**: glTF-загрузчик моделей — регистрация по ASSET-3, приведение к каноническому представлению ASSET-5; миграция контента моделей с MDX на glTF (MDX-загрузчик остаётся).
- **`engine/render-ts` / `client-ts`**: чтение секции конфига камеры из манифеста (CAM-1/ASSET-10); переподача документов для hot-reload уже существует (REND-17, CAM-7).
- **`editor/core-ts`**: регистрация операции импорта и правила валидации вкладами (ED-25, ED-29, ED-30) — расширение реестров, не правка каркаса и не level-дизайн-функциональность.
- **Дерево контента**: рядом со сценой появляются `<base>.blend` и `<base>.glb`; модели переезжают на glTF; git-политика бинарей — решение design.
- **Ядро симуляции и netcode**: не затрагиваются ни строкой; импортированная сцена неотличима от написанной редактором (SER-6..8, PRES-1..4, TERR-2..7), хеши `worldInit` и контент-пака работают как прежде.
- **Спеки/доки**: `openspec/specs/blender-pipeline/` (новая), дельты `presentation-scene`, `game-content`, `camera`, `assets`; роадмап `docs/architecture.md`, `CLAUDE.md`, стаб `terrain-texturing` (ревизия + перенумерация его ASSET-10 → ASSET-11).
