## Why

Стелс сегодня бинарный: `Stealth { active }` (FOW-3) гасит биты всех чужих команд разом. Дизайну нужны *виды* невидимости — слабая/сильная лестница, невидимость у деревьев, особая невидимость от способности, видимая только избранным, — и детекция как отдельное свойство наблюдателя. Нужна и HotS-механика «шиммера»: враг видит невидимку слабым преломлением, но не может взять его в таргет. Одно поле-флаг этого не выражает, а городить по нативной системе на каждый вид — путь в несовместимые частные механизмы.

## What Changes

- **Канальная модель стелса.** Вид невидимости — канал, бит в 32-битной маске (прецедент FOW-2). У цели — маска активных стелс-каналов, у наблюдателя — маска детекции; цель скрыта от наблюдателя, когда есть хотя бы один невскрытый канал (`stealth & ~detection ≠ 0`). Лестница «слабая < сильная» — контентная конвенция битов детекции, не механизм ядра.
- **Жёсткие и мягкие каналы.** Свойство канала, объявленное сценой и фиксированное на матч. Невскрытый жёсткий канал гасит бит команды в `Visibility` — сущность вырезается из снапшота (как сейчас). Мягкий канал маску `Visibility` не трогает: сущность доставляется по обычным правилам обзора, её стелс-состояние едет в снапшоте, и клиент рисует шиммер/силуэт. Принятое следствие: мягкий стелс чит-прозрачен по построению — это осознанная информационная граница, а не дыра.
- **BREAKING: `Stealth { active }` заменяется** слотовым списком источников стелса по паттерну TIME-7 (маска канала как значение слота, сведение через OR, нейтраль 0). Детекция — такой же список у наблюдателя. Динамика — только перевешивание источников (`addModifier`/`removeModifier`, TIME-8/ACT-1): двухфазный инвиз «мягкий → жёсткий» — это снятие источника одного канала и добавление в другой по таймеру, политика способности в JSON.
- **Таблица каналов — поле конфига сцены** (SER-7): какие биты объявлены и какие из них жёсткие. Смысл канала в рантайме не мутирует — иначе «какие каналы жёсткие» стало бы ещё одним изменяемым состоянием снапшота, обязательным к повторению в каждом порте ядра (CLI-6).
- **Пересчёт видимости** (FOW-5): фильтр «скрыт ли кандидат» становится пер-наблюдательным сравнением масок вместо глобального флага; в маску `Visibility` вносят вклад только жёсткие каналы. Бит своей команды по-прежнему взводится безусловно первым шагом.
- **DSL-ручки**: управление источниками уже есть (`addModifier`/`removeModifier`); для условий таргетинга («нельзя выбрать целью невскрытого») выражениям нужен оператор покрытия маски — `bitTest` (EXPR-2) читает один бит, а условие «все активные каналы вскрыты» требует битового И/НЕ.
- **NPC**: восприятие платформы поведения уважает те же маски — NPC не видит невидимого без детекции, наравне с ботами, которые получают это бесплатно через фильтрованный снапшот.
- **Презентация**: своя команда рисует своего невидимку полупрозрачным, враг — мягко-скрытого шиммером; маппинг «стелс-состояние → подача» — данные presentation-слоя в духе FOW-10. В этом изменении — минимум (прозрачность своих); шейдер преломления — отдельная работа рендера.

## Capabilities

### New Capabilities

Нет: всё ложится в существующие capabilities.

### Modified Capabilities

- `fog-of-war`: FOW-3 переписывается (каналы, списки источников стелса и детекции вместо `Stealth { active }`); FOW-5 — пер-наблюдательный фильтр по маскам, вклад только жёстких каналов; новые требования — таблица каналов сцены (жёсткость как статичное свойство), мягкий стелс (не влияет на `Visibility`, доставляется, презентация состояния).
- `netcode`: NET-15 — «под стелсом отсутствует в чужих снапшотах» уточняется до жёстких каналов; мягко-скрытая сущность доставляется штатно.
- `serialization`: SER-7 — новое поле конфига сцены (таблица стелс-каналов), списки источников стелса/детекции в перечне порождённых компонентов `fog` и под общим `modifierSlots`.
- `data-driven-systems`: EXPR-2/EXPR-6 — оператор(ы) битовой арифметики масок для условий таргетинга (закрытый набор расширяется правкой спеки).
- `npc-behavior`: восприятие/выбор цели платформы уважает сравнение стелс-маски цели с детекцией агента.

## Impact

- `engine/core-ts`: `systems/visibility.ts` (фильтр по маскам), `systems/modifiers.ts` (OR-редьюсер для масочных списков: значение слота i32, нейтраль 0 — рядом с `product`), `sim/scene.ts` (таблица каналов, новые списки), `sim/filter.ts` (без изменений по построению — режет по `Visibility`), `dsl/expr.ts` (оператор масок), `systems/npc/*` (восприятие).
- Формат снапшота сцен с `fog` меняется (BREAKING): схема `Stealth` уходит, приходят списки источников. Контент компонент не использует; тестовые фикстуры `net-ts`/`integration-ts` и golden-базлайны регенерируются (`npm run schemas`, `npm run golden`), `editor/ui-ts` (objectsSchemas) правится.
- `engine/render-ts` / `game/demo-ts`: минимальная подача (прозрачность своих под стелсом); шиммер-шейдер — за пределами этого изменения.
- Rust-порт: одна новая нормированная раскладка (масочный список источников), взамен убирается компонент-флаг.
