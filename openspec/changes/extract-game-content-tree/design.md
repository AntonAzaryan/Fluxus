## Context

Мотив — proposal.md «Why»; требования — specs/game-content/spec.md. Здесь только то, что нужно для выбора реализации.

Что есть сейчас в коде:

- `engine/net-ts/bin/matchFile.mjs` уже разрешает пути `contentPack` относительно самого файла матча (`dirname(file)`), то есть CONT-5 в CLI выполняется без единой правки — меняется только строка пути в `duel.match.json`.
- Демо клиента берёт байты presentation-ассетов через `fetch('/assets/' + id)`, где `/assets` — это `demo/public/assets`, раздаваемое vite как статика. ID ассета — путь внутри этой базы (`models/SkeletonBarbarian.mdx`).
- Сцену демо `worker.ts` импортирует статически: `import sceneJson from './scene.json'`.
- `vite.config.ts` уже расширяет `server.fs.allow` до корня `engine/` — механизм чтения за пределами `root` в конфиге присутствует.
- Кросс-слойная сюита строит сцену дуэли инлайном в TS (`integration-ts/test/fixtures.ts`, `duelScene()`), а не читает JSON. Именно поэтому `match-*` эталоны от переезда не зависят.
- `engine/tests/guard/scanner.ts` — общий сканер инвариантов с адаптер-тестами в пакетах (CLI-8); списки правил в нём лежат данными, чтобы попадать в дифф.

## Goals / Non-Goals

**Goals:**

- Раскладка внутри дерева, при которой ID ассета (`assets` ASSET-2) — однозначный путь от корня.
- Переезд без изменения поведения движка: ни один golden-эталон и ни одна JSON-схема не меняются.
- Механическая проверка CONT-1, встроенная в существующий приём guard-тестов, а не новый вид проверок.

**Non-Goals:**

- Многосценовый контент-пак и склейка хешей — запрещены нормой NET-17 и отдельным change'ем (см. комментарий в `net-ts/src/content/pack.ts`).
- Загрузка sim-контента демо в рантайме вместо статического импорта — см. решение 4.
- Вынос инлайновой сцены `integration-ts` — запрещено CONT-4.

## Decisions

### 1. Корень называется `content/`, лежит в корне репозитория

Термин уже введён спекой: `assets` ASSET-2 говорит «путь в дереве контента». Имя директории совпадает с термином, и требование CONT-2 читается буквально.

Альтернативы: `game/` — шире имени: подразумевает и код игровой логики, которого в проекте нет (вся логика — либо движок, либо JSON-системы внутри контента); `assets/` — уже: покрывает presentation, но не сцены, а класть сцены в «ассеты» значит спорить с ASSET-1, который «ассетами» называет ровно presentation-данные.

### 2. Раскладка: два поддерева, ID — путь от корня

```
content/
  scenes/duel.scene.json          # sim: SER-7
  matches/duel.match.json         # sim: конфиг матча, contentPack → ../scenes/…
  visuals/manifest.json           # presentation: ASSET-6
  visuals/models/SkeletonBarbarian.mdx
  visuals/textures/skin-steel.png
  visuals/textures/skin-ember.png
```

База ассетов у оболочки становится корнем `content/`, поэтому ID модели превращается из `models/…` в `visuals/models/…` — записи внутри `manifest.json` правятся один раз. Альтернатива — оставить `models/` и `textures/` прямо в корне дерева, чтобы манифест не трогать вовсе; отвергнута: тогда presentation-файлы лежат вперемешку с sim-поддеревьями, и «два соседних поддерева» из CONT-2 держится на честном слове. Один раз поправить пути дешевле, чем всё время объяснять раскладку.

Правило резолва остаётся одно и то же для всех: ID = путь от корня дерева. Вариант «пути внутри манифеста разрешаются относительно самого манифеста» отвергнут — это второе правило резолва, которого нет ни в одном требовании.

### 3. Слияние двух сцен: берётся надмножество клиентского демо

Клиентская сцена (201 строка) — надмножество сетевой (87 строк): те же компоненты плюс `Velocity`, `Collider`, `Lifetime`, `Dead` и физика; `capacity` берётся большая (128). Матч поднимается с более полной сценой — это меняет его `worldInitHash`, но не поведение: лишние компоненты без систем, которые их читают, — мёртвые данные, а хендшейк сверяет хеш обеих сторон, поднимаемых из одного документа.

Альтернатива — держать в дереве две сцены под разными именами (`duel` и `duel-lite`) — отвергнута прямо: CONT-3 написан против ровно этого, а разница между копиями возникла не по замыслу, а по недосмотру.

### 4. Сцена демо остаётся статическим импортом

`worker.ts` продолжает импортировать сцену как модуль, только путь ведёт в `content/scenes/`; `vite.config.ts` расширяет `root`/`fs.allow` до корня репозитория и раздаёт `content/` как `publicDir`.

Альтернатива — тянуть сцену тем же `fetch`, что и ассеты, — концептуально чище (контент — данные, а не модуль), но меняет старт демо (сцена нужна воркеру до первого тика, появляется асинхронная фаза) и не требуется ни одним требованием. Отложено до появления выбора сцены в демо, где асинхронность понадобится по существу.

### 5. Проверка CONT-1 — сканер файловой системы, адаптер в `integration-ts`

Правило «в пакетах движка нет контентных документов» проверяется обходом директорий `engine/*/`, а не AST: это вопрос расположения файлов, а не кода. Списки (расширения и имена контентных документов, разрешённые исключения) лежат данными рядом с существующим guard-сканером, чтобы правка попадала в дифф — тот же приём, что CLI-8 задаёт для инвариантов детерминизма.

Адаптер-тест живёт в `integration-ts`: правило репозиторное, а не про один пакет, и кросс-слойная сюита — единственное место, которому видны все пакеты сразу. Исключения на старте: `engine/tests/golden/**` и `**/test/fixtures/**` (CONT-4).

Альтернатива — расширить AST-сканер — отвергнута: он смотрит в исходники TS и про JSON/MDX/PNG ничего сказать не может.

## Risks / Trade-offs

- [`worldInitHash` матча меняется — старый записанный матч не поднимется новым конфигом] → Записанных матчей вне `engine/tests/golden/` нет, а те пишутся из инлайновой сцены сюиты и переезда не видят. Проверяется прогоном `npm run golden`: дифф эталонов обязан быть пустым.
- [Демо ломается тихо: `publicDir` за пределами `root` — редкая конфигурация vite] → Приёмка руками: `npm run dev`, сцена поднимается, модель и текстуры грузятся. Автотестом это не покрыть, поэтому шаг явный в tasks.md.
- [Guard с исключениями окаменеет: чтобы обойти правило, достаточно дописать путь в allowlist] → Списки — данные в дифф, и добавление исключения обязано объясняться в сообщении коммита. Тот же компромисс, что уже принят в CLI-8.
- [Пустое дерево контента у того, кто выкачал только `engine/`] → CONT-4 гарантирует, что тесты движка при этом зелёные; проверяется прогоном тестов с временно переименованным `content/`.

## Migration Plan

1. Создать `content/`, перенести файлы `git mv` (история переезда сохраняется).
2. Слить сцены в `content/scenes/duel.scene.json`, поправить `contentPack` в конфиге матча на `../scenes/duel.scene.json`.
3. Поправить ID внутри `manifest.json` (`models/…` → `visuals/models/…`).
4. Перенастроить оболочки: `vite.config.ts` (root статики), `worker.ts` (путь импорта), `main.ts` (база `fetch`).
5. Добавить guard-проверку CONT-1 и адаптер-тест.
6. Обновить документацию и примеры команд.

Откат — обратный `git mv` и revert коммита: изменение не трогает ни формат документов, ни генерируемые артефакты, поэтому состояния «наполовину мигрировано» у данных нет.

## Open Questions

- Как дерево устроится, когда контент-паков станет больше одного (`content/packs/<name>/…` против плоского корня). Ответ безопасно откладывается: он потребуется вместе с многосценовым паком, который упирается в отсутствующую норму склейки хешей (NET-17) и всё равно идёт отдельным change'ем.
