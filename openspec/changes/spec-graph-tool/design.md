# spec-graph-tool — design

## Context

Мотивация — proposal.md «Why». Существенное для подхода:

- Дерево спек регулярно по формату: `### Requirement: <ID> <заголовок>`, тело секции — до следующего заголовка, ссылки в теле — паттерн `[A-Z]{2,6}-[0-9]+`, иногда с именем capability в бэктиках рядом (`` `determinism-core` DET-1 ``). Формат принадлежит OpenSpec и прибит `openspec validate --specs --strict`.
- Префикс ID **не** определяет capability (исторические ID); карта ID→файл строится только из определений.
- Объём мал (~1 МБ, 7400 строк): полный парсинг дерева — миллисекунды, кэш не нужен.
- `openspec` CLI не даёт ни адресации по ID, ни графа; `doctor` проверяет только store-references. Дублировать его workflow нельзя и незачем.
- Editor сознательно «reaches into» rendering/camera/serialization — рёбра «снизу вверх» к ED-* там легитимны; наивное правило слоёв покраснело бы на принятом решении.

## Goals / Non-Goals

**Goals:**

- Ленивая навигация по спекам для агентов: контур задачи (~70 строк) вместо полных спек (~900), точка входа — `find`, раскрытие — `refs`/`show`.
- Граф ссылок как запрашиваемая структура: requirement-уровень и агрегат до capability.
- Линт целостности графа, ловящий классы дефектов, невидимые для `validate --strict` (RNG-8: неверная атрибуция capability; ED-10: требование без модальности).
- Композируемость: `--json` для сабагентов (`spec-coverage`, ревью).

**Non-Goals:**

- Не хранилище и не кэш: никакого стейта, никакой БД, никакого индекс-файла. Источник правды — markdown в git, каждый вызов парсит заново.
- Не замена `openspec`: workflow changes, валидация формата, дельты — его территория.
- Не suspect links (стейт «ссылка сверена»): отложено до доказанной нужды; при вводе — ритуал по образцу golden baselines (закоммиченный стейт + команда регенерации + дифф в коммите). Риск «резиновой печати» (`ack --all`) признан.
- Не массовая правка спек и не нормирование синтаксиса ссылок: 1606 упоминаний парсятся как есть.
- Не парсинг дельта-спек `changes/`: тул видит main specs; пока change не заархивирован, граф показывает «до». Ограничение честно пишется в `--help`.

## Decisions

**D1. Stateless-скрипт, а не БД/индекс.** Парсинг 1 МБ ≈ 30 мс — дешевле любого механизма инвалидации. БД и индекс-файл — второй источник правды с неизбежным дрейфом или гейтом регенерации; отвергнуты. Если Rust-порт умножит объём на порядки — скрипт отрастит `--cache`, интерфейс не изменится.

**D2. Место: `scripts/spec-graph.mjs`, zero-deps, plain Node.** Это dev-tooling уровня `npm run golden`, не capability движка и не workspace-пакет. Zero-deps — по той же логике, что у ядра: нечему устаревать и ломаться. Альтернатива (пакет `tools/spec-graph-ts`) отвергнута как церемония без выгоды. Запуск: `npm run spec-graph -- <cmd>` из корня.

**D3. Семантика графа.** Узел — требование (ID); ребро — упоминание чужого ID в теле секции, направление «цитирующий → цитируемый»; самоопределение исключается. Capability-уровень — агрегация рёбер. Имя capability в бэктиках перед ID парсится как *заявленная* атрибуция и сверяется с фактической — это данные для линта, не для графа.

**D4. Команды.** `find <текст>` (ID+заголовки), `where <ID>`, `show <ID…>` (секция + шапка/Purpose capability по умолчанию; `--capability` — вся спека), `refs <ID>` (in/out), `impact <ID>` (транзитивное замыкание зависимых), `deps <capability>`, `graph --mermaid`, `check`. Все — `--json`. Человеку — текст, агенту — структура.

**D5. Линт: инварианты — гейт, метрики — диагностика** (та же философия, что у coverage в этом репо). Инварианты `check` (exit 1): висячая ссылка; дубль ID; заявленная атрибуция ≠ факт; секция без SHALL/MUST NOT в собственном тексте; нарушение слоёв; цикл на capability-уровне. Метрики (`check --metrics`, всегда exit 0): fan-in, instability (Ce/(Ca+Ce)), сироты.

**D6. Слои — декларативный конфиг с явными исключениями**, `scripts/spec-graph.layers.json` (по образцу dependency-cruiser): порядок слоёв foundation → sim → net → client → editor/content (из `docs/architecture.md`), правило «вниз можно, вверх нельзя», mechanism не цитирует game-content. Исключения — списком рёбер с однострочным обоснованием; стартовый список — принятые рёбра editor↔(rendering, camera, serialization). Найденный `terrain → ED-10` в тройку не входит — в исключения **не** вносится, попадает в отчёт `check` как находка.

**D7. Ввод гейта — поэтапно.** `check` приземляется в режиме отчёта (не в `npm run check`): дерево заведомо красное — `spec-modality-and-refs` не применён, плюс возможные новые находки. Порядок: применить `spec-modality-and-refs` → остаток находок оформить новым change → на зелёном дереве добавить `check` в корневой `npm run check`. Шаги вне этого change; фиксация здесь — чтобы гейт не был красным с первого дня по чужой вине.

**D8. Устойчивость к формату.** Парсер завязан на `### Requirement:`; тест прогоняет его по текущему дереву и утверждает инварианты (317 требований найдено, ID уникальны, счётчик ссылок в ожидаемом диапазоне) — апгрейд OpenSpec, меняющий формат, роняет тест, а не молча пустой граф.

## Risks / Trade-offs

- [Ленивый контекст: секция без соседей может трактоваться уже, чем задумано] → `show` печатает Purpose по умолчанию; норма в CLAUDE.md: правишь capability — читай её целиком, лениво грузятся только чужие спеки; `refs` подсвечивает густой внутренний клубок как сигнал взять `--capability`.
- [Формат OpenSpec изменится при апгрейде CLI] → тест-на-формат (D8) падает громко.
- [Ложные срабатывания паттерна ID в прозе (例: `Q16.16` не матчится, но возможны аббревиатуры)] → паттерн требует дефис+число и сверяется со словарём определённых ID; неизвестный ID — это и есть находка «висячая ссылка», отдельного класса «шум» нет.
- [Правило модальности даст ложные срабатывания на секциях-преамбулах] → правило применяется только к телу `### Requirement:`-секций; формулировка правила калибруется на текущем дереве до ввода в гейт (D7).
- [Конфиг слоёв устареет относительно docs/architecture.md] → конфиг ссылается на §-источник; расхождение всплывёт в ревью change'а, меняющего слои, — то же место, где меняли бы docs.

## Open Questions

- Точный текстовый формат вывода `graph --mermaid` (направление стрелок, группировка по слоям) — подберётся по читаемости на реальном графе, интерфейс не меняет.
