## MODIFIED Requirements

### Requirement: TERR-7 Ограничения формата под навигацию

Реализация поиска пути по сетке введена (`pathfinding` NAV-7); модель террейна SHALL оставаться её носителем без смены формата. Шов, через который навигация входит в ядро, описан в capability `pathfinding` (NAV-1); здесь фиксируются ограничения формата террейна.

Рампа SHALL иметь ширину не менее двух клеток, иначе агенты клинят на переходе. Ограничение чисто геометрическое и SHALL проверяться валидацией ассета.

`tileSize` SHALL быть не меньше диаметра крупнейшего агента, ходящего по сетке, — иначе поиск пути по клеткам вернёт путь, непроходимый физически. Источником значения диаметра SHALL быть параметр сборки Navigation API — наибольший радиус агента, который игра намерена передавать в `agentRadius` запросов: радиус — величина контента, а не константа ядра (`pathfinding` NAV-1), и предел его — число геймдизайнера, как бюджет поиска (`pathfinding` NAV-5). Сборка навигации SHALL проверять `tileSize` против удвоенного этого параметра и отвергать сборку с находкой валидации, называющей оба значения; запрос с `agentRadius` больше заявленного предела остаётся тотальным (`pathfinding` NAV-5) и отвечает по карте зазора (`pathfinding` NAV-9) вплоть до `unreachable`.

#### Scenario: Рампа в одну клетку

- **WHEN** автор рисует рампу шириной в одну клетку
- **THEN** валидация ассета сообщает об ошибке

#### Scenario: Клетка мельче агента

- **WHEN** сборка навигации получает террейн, чей `tileSize` меньше удвоенного заявленного наибольшего радиуса агента
- **THEN** сборка отвергается с находкой валидации, называющей `tileSize` и радиус, а не возвращает физически непроходимые пути

#### Scenario: Запрос с радиусом больше заявленного предела

- **WHEN** `findPath` вызывается с `agentRadius` больше параметра сборки
- **THEN** запрос не падает: карта зазора исключает тесные клетки, и результат честен вплоть до `unreachable`
