## Why

Navigation API — шов без реализации: `NavigationApi` объявлен (NAV-1..6), но `findPath` в движке не существует, и NPC ходят прямым seek — упираются в обрывы и стены, если маршрут дизайнера не обводит их вручную. Исследование `docs/reviews/2026-08-22-nav-pathfinding.md` закрыло вопрос «use vs build»: готовых детерминированных решений нет (все на float), строим собственный целочисленный grid A* по образцу 0 A.D. Спека сама требует, чтобы change, вводящий реализацию, зафиксировал tie-break (NAV-2), связность сетки (NAV-6) и валидацию размера клетки против диаметра агента (TERR-7) — этот change это делает.

## What Changes

- Реализация `findPath` в `engine/core-ts`: A* по 4-связной сетке террейна, целочисленные стоимости, без float и sqrt (NAV-2, CORE-2).
- Навигационные данные печаются при сборке сцены из террейн-ассета (предикат проходимости границ — уровни и рампы, TERR-8) плюс целочисленная clearance-карта под `agentRadius`; всё — неизменяемая часть сборки (NAV-3), новых данных контента нет.
- Нормативные решения в спеке `pathfinding`: 4-связность, правило tie-break по результату (какой из равных по стоимости путей возвращается), детерминированное LOS-сглаживание пути в мировые Q16.16-координаты.
- Бюджет раскрытий узлов — параметр сборки Navigation API (NAV-5 уже требует), не константа ядра.
- Валидация TERR-7: `tileSize` не меньше диаметра крупнейшего агента сцены; источник диаметра назван нормативно.
- Снятый в бою пол (TERR-6, живой компонент) навигация не видит — зафиксировано явно как следствие NAV-3: обход дыры — политика геймплейной системы.
- NPC movement: seek к цели становится движением по `findPath`, когда `navigation` присутствует в контексте; без него прежний прямой seek (NAV-6, DI-4). Путь не хранится в компонентах — перезапрашивается чистым запросом в каденс-окне (NAV-2 делает это ненаблюдаемым).

## Capabilities

### New Capabilities

(нет — реализация входит в существующую capability `pathfinding`)

### Modified Capabilities

- `pathfinding`: новые требования, закрывающие оставленные спекой вопросы — представление (сетка террейна, 4-связность), нормативный tie-break равных по стоимости путей, clearance для `agentRadius`, LOS-сглаживание, место бюджета в сборке; NAV-6 остаётся в силе — контракт `findPath` не меняется.
- `terrain`: TERR-7 — добавляется требуемая им самим проверка `tileSize` против диаметра крупнейшего агента с названным источником значения.
- `npc-behavior`: NPC-6 — движение к цели поверх навигационного шва: seek через `findPath` при собранной навигации, прямой seek без неё; каденс перезапроса пути.

## Impact

- `engine/core-ts`: новый модуль навигации (`src/systems/nav/` или `sim/nav.ts` — по прецеденту физики), сборка в `sim/build.ts`/`sim/scene.ts`, правка `systems/npc/movement.ts` (seekTarget).
- Тесты: юнит-тесты всех сценариев NAV-1/NAV-2/NAV-5, golden-эталон путей; возможен пересчёт cost-baselines (`npm run golden:cost`), если NPC-сцены эталонных матчей начнут звать `findPath`.
- Контент и схемы сцены не меняются; документов поведения NPC правка не касается (обещание `movement.ts`).
- Потребители `NavigationApi` вне ядра отсутствуют — контракт NAV-1 не трогаем, ломающих изменений нет.
