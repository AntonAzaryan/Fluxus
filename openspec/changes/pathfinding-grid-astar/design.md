Исходное исследование use-vs-build — `docs/reviews/2026-08-22-nav-pathfinding.md` (вердикт: собственный целочисленный grid A* по образцу 0 A.D.; готовые библиотеки — float, для lockstep непригодны).

## Goals / Non-Goals

**Goals:**

- Рабочий `findPath` за существующим контрактом NAV-1: тотальный, чистый, детерминированный, с бюджетом раскрытий.
- Все данные — из террейн-ассета; ни новых полей контента, ни новых полей схемы сцены.
- NPC обходят обрывы, когда навигация собрана; без неё поведение байт-в-байт сегодняшнее (golden не шелохнутся).

**Non-Goals:**

- JPS, HPA*, navmesh, flow fields — названные будущие расширения; вводятся отдельными change'ами, когда `budgetExhausted`/cost-baselines покажут нужду (арены пока маленькие).
- Локальное избегание сверх существующего separation (ORCA/RVO) — не трогаем.
- Динамические препятствия (снятый пол, постройки) в навигационных данных — запрещено NAV-3; обход — политика.
- Использование навигации ботом (`bot-ts`) и игроком (click-to-move) — вне scope; потребитель здесь один — NPC movement.

## Decisions

1. **Модуль внутри `core-ts`, не новый пакет** (`src/systems/nav/`). Прецедент — физика: `PhysicsApi` реализован в ядре и вводится сборкой. Навигационные данные производны от террейна и живут рядом с ним в неизменяемой сборке (NAV-3). Отдельный пакет `nav-ts` (вариант исследования) отвергнут: capability ≠ пакет, а зависимостей у модуля нет — выносить нечего.

2. **Сборка: `buildNavigation(grid, { budget, maxAgentRadius }) → NavigationApi`** — вызывается там же, где строится `TerrainApi` (`sim/scene.ts`/`build.ts`), только когда сцена с террейном и хост попросил навигацию. `budget` (NAV-5) и `maxAgentRadius` (TERR-7) — параметры сборки, числа геймдизайнера; в ядре ни одной константы баланса. Валидация TERR-7 (`tileSize ≥ 2 × maxAgentRadius`) — здесь, находкой с обоими значениями.

3. **Запекание: passability + clearance один раз при сборке.** Проходимость клетки: `noFloor` из ассета → непроходима. Проходимость перехода — предикат `buildCliffs` (вынести в общую функцию, не дублировать). Clearance — целочисленный brushfire (BFS от непроходимого) в `Uint16Array`; перевод радиуса запроса в клетки — `ceil(radius / tileSize)` в fixed-point без float. Всё immutable, в снапшот не входит, при перемотке не трогается (NAV-3).

4. **A*: типизированные массивы, ноль аллокаций на запрос после прогрева.** `gScore`/`parent`/`state` — переиспользуемые typed arrays размера сетки (живут в замыкании API, между запросами очищаются поколенческим счётчиком, а не заливкой). Open list — бинарная куча на `Int32Array`. Приоритет — целое `f = g + manhattan`; tie-break — по NAV-8 (больший g, затем меньший линейный индекс; соседи в порядке `-W, -1, +1, +W`). Кэша путей нет: NAV-2 разрешает лишь ненаблюдаемый кэш, а перезапросы политики и так дешёвые — кэш добавим, только если cost-baselines попросят.

5. **Тотальность (NAV-5):** снап точки к ближайшей клетке — тем же правилом, что `levelAt` (TERR-4); старт == цель (одна клетка) → `found` + пустой список; старт в непроходимой клетке → поиск от неё честно (`unreachable`, если из неё нет переходов); бюджет считает раскрытия узлов, на исчерпании — `budgetExhausted` с пустым списком.

6. **Сглаживание (NAV-10): целочисленный LOS по сетке.** Жадное string pulling: от текущей опорной точки тянемся к самой дальней точке коридора, видимой целочисленным супер-обходом клеток отрезка (вариант Bresenham/DDA на fixed-point без деления, пересекаемые клетки проверяются на проходимость и clearance запроса). Точки — центры клеток, последняя — точная цель запроса (NAV-1).

7. **NPC movement: держимая точка, перезапрос в окне решений (NPC-6 дельта).** Компонент агента получает два поля Q16.16 «очередная точка пути» (+ признак валидности) — состояние симуляции, снапшотится, как вектор расхождения. В окне решений (NPC-4, окно уже есть) политика зовёт `findPath(pos, цель, { agentRadius: радиус коллайдера агента })` и держит `waypoints[0]`; между окнами — seek к держимой точке; не-`found` → сброс точки и прямой seek (деградация до сегодняшнего). `followRoute` и `seekTarget` разделяют этот механизм: меняется только источник очередной цели. Fallback-ветка без `ctx.navigation` — прежний код нетронутым.

8. **Перф-контур (PERF-3/4/5).** Единица работы навигации — раскрытие узла A* плюс проба клетки LOS-проходом: обе — та самая работа, которую ограничивает бюджет NAV-5 и наблюдает `budgetExhausted`. Счётчик `navNodes` — поле `TICK_COST` рядом с `npcNeighbors`: инкремент поля контекста диагностики, при отключённом стоке — ноль работы и ноль аллокаций (PERF-3). Навигационный записанный матч входит в cost-baselines (`*.cost.json`, PERF-4): рост стоимости поиска краснит `npm run check`, принятие роста — только явным `npm run golden:cost`. Wall-time сторож в `bench.test.ts` ядра — `findPath` на синтетической большой сетке (лабиринт + открытое поле), ассерт только на порядок величины (PERF-5): ловит константные замедления на узел, которых счётчик не видит. Оси нагрузки бенча — размер сетки и число запросов (PERF-6).

9. **Нити пути в отладочном рендере — источник демо-приложения, не дельта спеки.** Механизм `render-debug` готов: реестр источников (RDBG-1), состав — политика сборки игры. Демо регистрирует источник `demo.navPaths`: проба — по каждой ДОСТАВЛЕННОЙ сущности с полями держимой точки пути (RDBG-6: чужие невидимые NPC до клиента не доезжают — wallhack исключён по построению) ломаная «позиция → держимая точка», плюс полный путь, пересчитанный клиентом через `findPath` над собственной сборкой навигации из того же террейн-ассета — законно и точно: запрос чист и детерминирован (NAV-2), клиентский пересчёт побитово равен серверному. Пересчёт живёт в пробе источника — вне оплачиваемого пути и счётчиков (RDBG-8), выключенный источник бесплатен (RDBG-4). Рисование — ломаными закрытого словаря примитивов (RDBG-3); дамп кадра получает ту же пробу (RDBG-2). Регистрация — в демо-приложении (`game/demo-ts`), рядом с существующими источниками.

10. **Схемы и голдены.** Новые поля компонента NPC → `npm run schemas`. Существующие golden-матчи собираются без навигации → байт-в-байт стабильны. Новый golden-сценарий с собранной навигацией (пути через рампу/вокруг обрыва) закрепляет NAV-7..10 побитово и входит в cost-baselines (решение 8); `npm run golden:cost` — отдельный явный шаг с диффом в коммите.

## Risks / Trade-offs

- [Пути огибают снятый в бою пол «как целый»] → осознанное следствие NAV-3, зафиксировано сценарием NAV-7; провал агента в дыру и так гейтится полом/физикой, политика получит обход дыр, только если геймплей потребует (тогда — отдельный change про динамический слой).
- [Перезапрос пути каждое окно решений: ~10 агентов × бюджет] → бюджет — параметр сборки, дефолт подбирается по аренам из `content/scenes/` (они маленькие); стоимость видна в `TICK_COST` и cost-baselines, рост не пройдёт молча (PERF-3/4).
- [Целочисленный LOS — единственное место с «геометрией» и риском off-by-one на границах клеток] → правило прохождения ровно по углу фиксируется тестом с обеих сторон; сомнительный угол считается непроходимым (безопасная сторона, как ceil у clearance).
- [Tie-break сформулирован операционно; JPS изменит выбираемые пути] → честно зафиксировано в NAV-7: замена представления обязана сохранить выбор путей или менять NAV-8 нормативно (с перегенерацией голденов) — молчаливой подмены не будет.
- [4-связность даёт «манхэттенские» маршруты] → сглаживание NAV-10 спрямляет их в мировых координатах; диагональная связность — возможное будущее расширение NAV-8, не дефект.
