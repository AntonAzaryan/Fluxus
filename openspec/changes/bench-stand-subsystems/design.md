# Design: bench-stand-subsystems

## Context

Мотивация — proposal.md. Существующая механика: сток `engine/render-ts/src/cost.ts` (плоские счётчики, `COST_COUNTER_STAGES`, тест тождества наборов ключей), стенд `engine/integration-ts/test/benchLoad.ts` (`PresentationBench`, генерическая сборка эталона по стадиям — новые счётчики попадают в голден автоматически при регенерации), эталоны с секциями `performance`/`ultra`.

## Goals / Non-Goals

**Goals:** регрессия внутри models/particles/terrain видна точным диффом эталона; ручки их пресетов двигают эталонные числа; детерминизм эталона сохранён (два прогона — побитово).

**Non-Goals:** не считать внутренности three.quarks (эмиссия там стохастическая — считаем объём своей работы: оболочки, синхронизации); не менять нормативный текст спек; не добавлять новых ручек качества.

## Decisions

- **D1. Имена счётчиков — префикс подсистемы** (`modelsLodSelections`, `particlesShellsStepped`, `terrainChunksRemarked`…), стадия по месту работы; контракт — как у fog-счётчиков.
- **D2. Контент стенда — фикстуры integration-ts**, не `content/` (CONT-4): минимальный манифест с batched-записью и LOD-цепочкой, документ эффекта по образцу фикстур render-ts, террейн — из сцены стенда. Значения подбираются так, чтобы performance/ultra различались и на этих счётчиках (ярус, LOD-множитель, плотность частиц, тесселяция).
- **D3. Детерминизм частиц:** счётчики не читают состояние quarks (число живых частиц — стохастика эмиссии); считаются наши вызовы: синки эмиттеров на доставке, шаги оболочек на кадре. Тест машинной независимости (двойной прогон) — арбитр.

## Risks / Trade-offs

- [Счётчик, зависящий от float-эволюции quarks, зашумит эталон] → D3 + существующий тест двойного прогона.
- [Рост стадийной бухгалтерии (`syncTickSubsystems` и др.) смешается с новыми счётчиками в одном диффе] → перегенерация отдельным коммитом с построчным объяснением в сообщении.
