# Proposal: npc-grid-optimization

## Why

Профиль стресс-нагрузки массы NPC (`engine/tests/golden/npc-stress.load.json`, 196 крипов, release `NODE_ENV=production`, медиана ≥10 прогонов) показывает, что соседский скан сетки платформы поведения — доминанта тика: `grid.ts` несёт 27.8% self-time (из них `collectCell` 23.4%), точное сравнение квадратов `distSqCompare`/`distSqLe` — ещё ~15%, и вместе с математикой вкладов (`lengthOf`, `div`) скан и его арифметика стоят ~43–49% тика (медиана тика — ~2.04–2.10 мс на замерной машине).

Разбивка по потребителям измерена изолирующим прогоном (`separationWeight=0` глушит запросы расхождения): расхождение (separation) платит ~723 мкс/тик — 35% тика и ~5160 из 8960 осмотров/тик, — потому что его платят ВСЕ агенты КАЖДЫЙ тик, тогда как perception-запросы идут только в окно решения каденса (NPC-4) и стоят вдвое меньше. Staggering решений на расхождение не распространяется — это главный неамортизированный расход платформы.

## What Changes

- Пересчёт вектора локального расхождения получает собственный каденс (NPC-6): вектор пересчитывается раз в `separationIntervalTicks` тиков на агента в детерминированном окне — функции состояния мира, — а между пересчётами применяется последний пересчитанный вектор. Интервал — параметр документа поведения с нормативным умолчанием 3 (паттерн умолчаний NPC-2); документу, которому нужен потиковый пересчёт, доступна единица.
- Держимый вектор — состояние симуляции: поля компонента агента, снапшот и перемотка возвращают его вместе с миром (SNAP-1); запись — через Command Buffer на общих основаниях.
- Остальные кандидаты оптимизации скана профилем ОТКЛОНЕНЫ и в change не входят (основания — design, D4): общая сетка на тик вместо двух построений (~2% тика против правки несущей нормы NPC-6 «один прогон одной системы»), подбор размера ячейки (меняет состав осмотренного, выигрыш профилем не подтверждён), ленивые строки ассертов (release их не платит).

## Capabilities

### Modified Capabilities

- `npc-behavior`: NPC-6 — локальное расхождение получает каденс пересчёта: интервал — параметр документа, окно — детерминированная функция состояния мира, держимый вектор — состояние симуляции в компоненте агента; исполнение решения (движение с уже держимым вектором) остаётся потиковым (NPC-4). NPC-2 — список нормативных умолчаний документа пополняется интервалом пересчёта расхождения (3 тика).

## Impact

- `engine/core-ts` — `systems/npc/`: документ (`document.ts`, `model.ts` — новое необязательное поле), компонент агента (`components.ts` — поля держимого вектора, состав полей `NpcAgent` входит в снапшот), `movement.ts` (окно пересчёта, чтение/запись вектора), `handles.ts`. Ноль новых зависимостей, ноль аллокаций на агента.
- `engine/schemas/` — регенерация (`npm run schemas`): схема документа поведения получает поле интервала.
- `engine/tests/golden/npc-stress.cost.json` — счётчик `npcNeighbors` падает (~8960 → ~5500–5900/тик), `commandsApplied` слегка растёт (записи вектора в окнах пересчёта); дифф принимается осознанно через `npm run golden:cost` и входит в коммит. `*.golden.json` НЕ меняются: сцены golden-матчей собираются в `integration-ts` и NPC не содержат — их неизменность есть критерий приёмки (design).
- Траектории NPC меняются (вектор расхождения свежее не каждый тик): демо-сцена с боссом проверяется штатными тестами демо (`npm run check`); расхождение босса пренебрежимо, каденс решений не затронут.
