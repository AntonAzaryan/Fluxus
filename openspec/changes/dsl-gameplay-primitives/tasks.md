## 1. Свёртка: изменяемый `let` и действие `set` (ACT-4)

- [ ] 1.1 Ввести ячейку изменяемой привязки в исполнителе (`dsl/actions.ts`): `let` связывает имена через ячейки, `var` в `dsl/expr.ts` разворачивает ячейку при чтении, `as`-привязки остаются голыми значениями (design D2); затенение из сценария ACT-1 не ломается
- [ ] 1.2 Действие `set { name, value }`: запись в ячейку ближайшего объемлющего `let`; добавить в `ACTIONS` и `requiredArgs`
- [ ] 1.3 Статическая проверка на регистрации (`dsl/evaluatedSystem.ts`, SYS-3): `set` на имя, связанное `as`, и на несвязанное имя — ошибка регистрации с путём до узла
- [ ] 1.4 Тесты: сумма по `forEach` видна после цикла; присваивание из вложенных тел (`forEach`/`forEachEvent`/`if`/вложенный `let`); смена типа значения; обе ошибки регистрации

## 2. Упорядоченная выборка `forEach` (ACT-5)

- [ ] 2.1 Аргументы `nearestTo`/`limit` в `forEach`: сортировка вставками по `(distSq, rawIndex)` в переиспользуемом буфере поверх материализованного результата (design D3); `distSq` — той же арифметикой, что `withinRadius`
- [ ] 2.2 `limit`: приведение к целому как у `bound`, обрыв обхода; отрицательный — ошибка вычисления (SYS-9), нулевой — пустой обход; `limit` без `nearestTo` — порядок QUERY-2
- [ ] 2.3 Тесты: ближайшая цель с `limit: 1`; тай-брейк равноудалённых по raw-индексу; сущность без Position в начале координат (ECS-7); отрицательный/нулевой `limit`
