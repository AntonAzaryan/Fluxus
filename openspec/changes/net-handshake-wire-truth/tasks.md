# Tasks: net-handshake-wire-truth

Требования — `specs/netcode-transport/spec.md` (**NTR-4**, **NTR-5**) и `specs/net-session/spec.md` (**SES-4**). Разбор решений — design.md (D1–D5). Гейт один и он локальный: `npm run check` из корня репозитория (CI нет).

Все задачи выполнены одним заходом вместе с правкой кода: изменение заводилось по факту сделанной работы — валидация спек против кода (`docs/reviews/spec-validation-2026-09-01/06-netcode.md`) назвала расхождение, а решение о том, какая половина чинится спекой, принято в design.md (D5).

## 1. Дельты требований (D1–D3)

- [x] 1.1 `specs/netcode-transport/spec.md`: MODIFIED NTR-4 — строка `Hello` таблицы «клиент → сервер» получает признак наблюдателя (NTR-9), строка `Welcome` таблицы «сервер → клиент» — упорядоченный список игроков матча (TICK-5). Абзацем ниже таблицы — почему признак наблюдателя отдельное поле, а не третье значение роли (D3). Блок MODIFIED несёт требование ЦЕЛИКОМ вместе со всеми сценариями действующей спеки: MODIFIED заменяет блок, и опущенный сценарий архивация молча выкинула бы. Проверка — `npx openspec validate net-handshake-wire-truth --type change --strict`.
- [x] 1.2 Там же: MODIFIED NTR-5 — состав `Welcome` перечислен вместе с ростером; отдельным абзацем сказано, зачем ростер нужен (без него клиент не поднимет `worldInit` и не сверит хеш) и что `seed` в сообщение MUST NOT входить (D1). Новые сценарии: «Клиент поднимает стартовый мир» и «Seed матча на проводе».
- [x] 1.3 `specs/net-session/spec.md`: MODIFIED SES-4 — запрет «Ростер и `seed` на провод … не едут вовсе» сужен до `seed`; про ростер сказано, что он едет в `Welcome` по NTR-5 и что расширением набора сообщений это не является — сервер отправляет тот же список, который лобби заморозило в конфиг (D2). Новый сценарий «Вошедший узнаёт состав матча» — про матч, в котором лобби не участвовало вовсе.
- [x] 1.4 Новый сценарий NTR-4 «Наблюдатель предъявляется на входе»: соединение объявляет себя признаком, а не третьим значением роли, и сервер без разрешения на наблюдателя отвечает `Reject` с именованным исходом (NTR-9).

- [x] 4.1 `engine/net-ts/src/protocol/messages.ts`: `observer` разбирается отдельной функцией `observerFlag` — небулево значение и отсутствие поля дают `ProtocolError`, как у роли рядом. Прежнее `source.observer === true` подставляло умолчание, то есть согласовывало возможности в рантайме (NTR-4).

## 5. Тесты (сценарии требований)

- [x] 5.1 `engine/net-ts/test/handshake.test.ts`: сценарий «Seed матча на проводе» — отправленное сервером `Welcome` не несёт поля `seed`, и разбор не заводит его даже у сообщения, которое поле привезло. Соседний тест состава дополнен ссылкой на закрытость набора (NTR-4).
- [x] 5.2 `engine/net-ts/test/protocol.test.ts`: убрать `seed` из литералов круга сообщений и проверок `pacing` — круг сверяется `toEqual`, и поле в литерале означало бы, что тест сверяет сообщение с самим собой мимо разбора.
- [x] 5.3 `engine/net-ts/test/reconnect.test.ts`, describe обязательных полей `Hello`: сценарий «поле обязательно» для признака наблюдателя, отвержение небулевых значений и разбор обоих булевых. Хелпер `wire` строит ПОЛНОЕ сообщение, а снятие поля выражается `undefined` — иначе тест роли и тест наблюдателя краснели бы друг за друга.
