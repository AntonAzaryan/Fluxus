## Context

Мотивация — в proposal.md (Why). Текущее состояние: инстанс = `holder: Group` → `root/body` → `SkinnedMesh` на каждую часть модели, со своим скелетом, `AnimationMixer` и клонированными материалами (`render-ts/src/subsystems/models.ts`, `model/build.ts`); `frustumCulled = false` у всех мешей; декорации идут тем же пер-инстансным путём. Требования нового поведения — в дельтах этого change (REND-3/6/18/20/21/22, ASSET-12/12).

Ограничения: three.js r185 (WebGL2), модуль ассетов рендер-агностичен и headless-тестируем (ASSET-5), модели контента — MDX через нормализованное представление, публичные потребители инстансов — picking (REND-15), наложения (REND-16), HUD-портрет (HUD-7), редактор (`instanceFor` в тестах).

## Goals / Non-Goals

**Goals**

- Стоимость кадра ~O(число моделей + число детальных инстансов), а не O(число инстансов).
- Один механизм сведения и одна запись манифеста на оба яруса и оба пула (сущности, декорации).
- Публичный контракт без `THREE.Object3D`.

**Non-Goals**

- WebGPU / `WebGPURenderer`, GPU-driven culling, тени, particles, fog-mask — не в этом change.
- Ручное авторство LOD в Blender и миграция MDX → glTF — отдельные работы; здесь LOD-цепочка приходит из данных ассета, если есть.
- Оптимизация террейна и оверлеев — их представление не меняется.

## Decisions

### D1. Батч-контейнер: `InstancedMesh` на (модель × LOD × материал)

`InstancedMesh` с кастомными пер-инстансными атрибутами (clip, phase, skin, доп. параметры) поверх `onBeforeCompile`-модификации `MeshStandardMaterial`. Против `BatchedMesh`: он объединяет разные геометрии, но кастомные пер-инстансные атрибуты и VAT-шейдер в нём заметно сложнее, а выигрыш (слить разные модели в один вызов) — второй порядок малости: draw calls уже не растут с числом инстансов. `BatchedMesh` — возможное развитие, не MVP.

### D2. VAT — по костям, не по вершинам

В текстуру запекаются матрицы костей по кадрам (bone-VAT), скиннинг в вершинном шейдере использует уже имеющиеся `skinIndex`/`skinWeight` из нормализованной модели. Против vertex-VAT (позиции вершин по кадрам): bone-VAT на порядки меньше (кости × кадры против вершины × кадры), одна текстура обслуживает всю LOD-цепочку (веса у упрощённой геометрии свои, кости общие), и запекание не зависит от тесселяции. Формат: float-текстура `RGBA32F`, строка = кадр, 4 текселя = матрица кости 3×4; таблица клипов (offset, length, fps, loop) — маленький uniform-массив/вторая текстура.

### D3. Запекание — в `assets-ts`, при первой загрузке, с кэшем модуля

Запекание (VAT-матрицы, границы по клипам, атлас скинов) — чистая функция `NormalizedModel → BakedDerivatives` в `assets-ts`: сэмплирование клипов форматно-нейтрально (кости + треки уже нормализованы), headless, тестируется в Node. Выполняется при первой загрузке модели и кэшируется по идентичности ассета (ASSET-2) — «один раз на ассет», как того требует ASSET-12. Против офлайн-CLI с артефактами в дереве контента: не плодит производные файлы и вопросы их синхронизации; если запекание станет заметным на загрузке — CLI добавляется позже без смены формата (та же функция, сериализованный результат). Детерминизм побитовый: фиксированный fps сэмплирования, никакого `Date.now`/рандома.

### D4. Ярус — из записи манифеста; детальный переиспользует нынешний код

`boneControls` в записи → детальный ярус; явное поле записи (ASSET-13) переопределяет. Детальный ярус — сегодняшний `createModelInstance` почти как есть (скелет, миксер, материалы); правки в нём — только шаринг материалов до первого скина и включение culling. HUD-портрет и превью крупных моделей — детальный ярус, их код не переписывается.

### D5. Анимационное состояние батчевого инстанса — скаляры на CPU

Логика REND-4 (состояние → клип, событие → one-shot, кроссфейд) остаётся на CPU, но её выход — не `AnimationMixer`, а пара (clip, phase) на запись батча. `AnimationController` рефакторится на два бэкенда за одним интерфейсом: mixer (детальный) и скаляры (батчевый). Кроссфейд в батче — вторая пара (clip, phase) + вес перехода в атрибутах, смешивание в шейдере; выпад — обычный one-shot.

### D6. Публичный контракт: прокси = трансформ + границы

`PickProxy` и `instanceFor` перестают отдавать узел сцены: прокси несёт позицию/кватернион/масштаб (или готовую `Matrix4` во внутреннем скретче) и `ModelBounds`. Picking уже считает по AABB — меняется источник трансформа, не алгоритм. Это первая, независимая фаза: выполняется до батчей и совместима с нынешним представлением.

### D7. Culling — CPU-тест по записям, компактация атрибутов

Каждый кадр: тест консервативных границ (по клипам, ASSET-12) против пирамиды камеры; видимые записи компактируются в начало инстанс-буферов, `instanceCount = visible`. Буферы преаллоцированы по ёмкости пула, аллокаций на кадр нет. Против per-mesh `frustumCulled` three: у батча один меш, three отсекает его целиком или никак — отсечение записей делаем сами.

### D8. Скины — `DataArrayTexture` на слот, индекс на запись

Варианты скинов записи запекаются слоями массива текстур; пер-инстансный атрибут выбирает слой. Смена скина = запись одного числа. Ограничение: все варианты слота одного размера — нормализуется при запекании (ресайз в ближайшую степень двойки максимума вариантов).

## Risks / Trade-offs

- [Bone-VAT не воспроизводит `BooleanKeyframeTrack` видимости частей] → видимость частей запекается в таблицу клипа (маска частей по кадрам) и применяется масштабом кости-родителя части либо schlop-масштабом в шейдере; крайний случай — запись переводится в детальный ярус явным полем.
- [Float-текстуры: `RGBA32F`-сэмплирование в вершинном шейдере] → WebGL2 гарантирует выборку float-текстур в vertex stage без фильтрации; фильтрацию не используем (выборка ближайшего кадра + смешивание двух кадров вручную).
- [Кроссфейд и наклон/доворот в батче усложняют шейдер] → yaw/tilt остаются в инстанс-матрице (CPU, дёшево — это уже сегодняшняя работа `poseAll` без скелетов); шейдер смешивает только позы VAT.
- [Расхождение картинки ярусов (skinning на GPU против mixer)] → голден-подобный тест: одна модель, один клип, одна фаза — сэмплированные позиции вершин обоих ярусов сравниваются с допуском в юнит-тесте запекания.
- [Память: VAT + массивы текстур скинов] → бюджет считается при запекании и логируется; LOD-геометрии разделяемы; при превышении бюджета художник переводит запись в детальный ярус (ASSET-13) — механизм деградации уже есть.
- [Регресс редактора: тесты и код, трогающие `instanceFor().holder`] → фаза D6 идёт первой отдельным PR; все потребители переводятся на трансформ+границы до появления батчей.

## Migration Plan

1. **Фаза 1 (контракт):** D6 — прокси и `instanceFor` без Object3D; culling детального яруса (D7 на holder'ах); шаринг материалов до первого скина. Спека уже позволяет (REND-3 modified). Поведение кадра неотличимо.
2. **Фаза 2 (данные):** ASSET-12/12 в `assets-ts` — запекание, кэш, тесты детерминизма и Node-headless.
3. **Фаза 3 (батчевый ярус):** пулы батчей в `models.ts`, VAT-материал, скаляры анимации, скины-массивы; выбор яруса по записи; декорации — в батчевый ярус.
4. **Фаза 4 (LOD):** цепочка в запекании (если данные есть), выбор уровня с гистерезисом.

Откат: ярус по умолчанию переключается на детальный одним умолчанием ASSET-13 — батчевый код остаётся за флагом данных, кадр возвращается к прежнему пути.

## Open Questions

- Источник LOD-цепочек для существующих MDX-моделей (авторские/децимация при запекании) — можно решить в фазе 4; до неё REND-22 покрыт веткой «модель без цепочки».
- Нужен ли офлайн-кэш запекания на диске (D3 допускает добавление CLI без смены формата) — решается по замерам времени загрузки.
