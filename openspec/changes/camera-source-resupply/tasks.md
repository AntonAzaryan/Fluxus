## 2. Реализация

- [x] 2.1 `engine/render-ts/src/camera/rig.ts`: тип `CameraSources` — переподаваемая часть инжекции (источник высоты и границы); `CameraRigOptions` наследует его, чтобы состав инжекции при создании и при переподаче был один по построению (Decision 1)
- [x] 2.2 Там же: `CameraRig.setSources(sources)` — отсутствующее поле оставляет прежнее значение, `null` снимает источник; поля `bounds` и `groundHeightAt` перестают быть `readonly`. Комментарий ссылается на CAM-7 и не пересказывает нормы (CORE-3)
- [x] 2.3 Там же: кламп точки наблюдения выносится в приватный хелпер и зовётся из двух мест — из кадра (CAM-3, как и раньше) и из `setSources` при переподаче границ (Decision 2); второго способа клампить не появляется
- [x] 2.4 Там же: запас, не влезающий в арену, даёт пустой интервал — хелпер отвечает его серединой, то есть центром арены (Decision 5); в области действия CAM-3 ни одно значение не меняется
- [x] 2.5 Там же: переподача источника поверхности НЕ сбрасывает накопленную высоту — первый же кадр тянет её к новой прежним сглаживанием (CAM-2); `hasGround` не трогается
- [x] 2.6 Там же: `terrainGroundApi(grid, heightStep)` перестаёт замыкать сетку — сетка живёт ссылкой, добавлен `setGrid(grid)`, `bounds` становится getter'ом над кэшированным значением, пересчитываемым в `setGrid`. Сигнатура и форма возврата прежние; `groundHeightAt` остаётся замыканием без `this` (Decision 3)
- [x] 2.7 `engine/render-ts/src/index.ts`: экспортировать новые типы (`CameraSources`, тип источника поверхности над сеткой) рядом с прежними экспортами камеры
- [x] 2.8 Проверить, что `engine/client-ts/demo/main.ts` не потребовал ни одной правки — это условие приёмки, а не наблюдение (Decision 3)
