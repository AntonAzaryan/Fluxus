# Три умолчания платформы, выбранные кодом, а не документом и не спекой

## Why

Валидация спек против кода (2026-09-01, `docs/reviews/spec-validation-2026-09-01/04-gameplay.md`) нашла три
места, где поведение при молчании — определения способности, определения баффа или требования — выбрала
реализация. Каждое из трёх наблюдаемо в снапшоте, то есть вторая реализация ядра, написанная по тексту,
разошлась бы с этой побитово, а `cli-testing` CLI-6 именно этого и не допускает.

- **ABIL-6: строка умолчаний для источника `release` не работает никогда.** Словарь источников закрыт, исход
  каждого — данные, и «определение SHALL переопределять только отличия — платформенные умолчания действуют
  на всё, чего оно не назвало». Для `release` умолчание в нормативной таблице есть — кулдаун целиком,
  прицеливание сбросить. В коде источник распознавался, только если определение упомянуло его в блоке
  `interrupts` (`systems/abilities/phase.ts`), то есть строка таблицы действовала лишь у того, кто её и так
  назвал. Для двух других «замковых» источников такое условие оправдано данными — `disable` нужна маска лока,
  `displacement` предикат, — а у `release` данных нет никаких.
- **BUFF-3: умолчание политики стакинга выбрал код.** Требование перечисляет закрытый набор политик и молчит
  о том, что значит отсутствие поля `stacking`; загрузчик читал молчание как `independent`
  (`systems/abilities/buffCatalog.ts`). Между тем `refresh`, `stack` и `independent` при одном и том же
  прочем определении дают три разных эффекта в игре: один инстанс с продлённой длительностью, один со
  стаками или два независимых. Это выбор дизайнера, а не реализации.
- **NPC-5: наименьшая угроза вытеснялась не всегда.** «При переполнении ёмкости SHALL вытесняться наименьшая
  угроза» — без оговорок; код вытеснял минимум, только если прибавка новичка весила больше него
  (`systems/npc/runtime.ts`). Следствие серьёзнее, чем расхождение с буквой: источник, начавший бить позже
  прочих, не попадал в таблицу НИКОГДА — накапливать ему негде, сколько бы урона он ни нанёс, — а состав
  таблицы становился функцией порядка появления источников.

## What Changes

- **ABIL-6:** названо прямо, что исключение у источника `release` ровно одно (фазы видов `hold` и `release`),
  а других условий распознавания платформа заводить MUST NOT; сказано, чем `release` отличается от `disable`
  и `displacement` (у тех молчание определения означает отсутствие ДАННЫХ, то есть отсутствие источника).
  Нормативно названо следствие для авторинга: «нажал и забыл» парой «триггер `input` + фаза, не потребляющая
  удержание» не описывается — для этого есть триггер `event` и доставка (ABIL-9). Новый сценарий.
- **BUFF-3:** поле `stacking` объявлено обязательным; его отсутствие — ошибка загрузки определения, а не
  умолчание. Новый сценарий.
- **NPC-5:** вытеснение названо безусловным, с обоснованием (иначе поздний источник не попадёт в таблицу
  никогда) и с указанием, где живёт защита от дребезга (порог смены цели и забывание — документ поведения,
  NPC-2). Тай-брейк равных минимумов — первый по порядку слотов. Новый сценарий.
- **Ядро:** снят «замок» распознавания `release` в `systems/abilities/phase.ts`; загрузчик баффов требует
  `stacking` (`systems/abilities/buffCatalog.ts`), схема `buffDef` получает его в `required`
  (`dsl/abilitySchemas.ts`, регенерация `engine/schemas/*.json` через `npm run schemas`); вытеснение в
  `systems/npc/runtime.ts` стало безусловным.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `ability-system`: ABIL-6 — распознавание источника `release` без «замка» по определению.
- `buff-system`: BUFF-3 — политика стакинга обязательна, умолчания у неё нет.
- `npc-behavior`: NPC-5 — безусловное вытеснение наименьшей угрозы и тай-брейк.

## Impact

- Поведение симуляции меняется намеренно в трёх местах. Golden- и cost-эталоны не затронуты: в записанных
  матчах (`engine/tests/golden/match-*.scenario.json`) способностей и баффов нет, а стресс-эталон NPC
  (`npc-stress`) переполнения threat-таблицы не даёт.
- Схемы `engine/schemas/scene.schema.json` и `scenario.schema.json` перегенерированы (`npm run schemas`):
  `buffDef.required` пополнен полем `stacking`.
- Демо-контент правки не потребовал: оба баффа `content/scenes/duel.scene.json` политику уже называют, а
  входные способности демо держат удержание фазами видов `release`.
- Новых номеров требований не заводится.
