# Design: water-render-subsystem

## Context

Вердикт исследования — `docs/reviews/2026-08-26-water-rendering-architecture.md`; мотивация и границы — `proposal.md`. Что уже есть и что ограничивает подход:

- Рендер — упорядоченный список подсистем за узким контрактом (REND-8): `init` со сценой и ассетами, `syncTick`, `updateFrame`; чужое владение — только портами из нейтрального модуля. Единое поле высот визуальной поверхности (REND-9) уже отдаётся портом источника поверхности (`surfaceSource.ts`) — им пользуются посадка инстансов, наложения и picking.
- Закрытый набор входов рендера (REND-1): секции парного presentation-документа уже легальный вход (`fog`/`lighting`/`postprocess`); узкий порт рендерера — только у подсистемы тумана (FOW-7), и расширять этот список нельзя без амендмента REND-1.
- Пост-цепочка фиксирована (REND-34): сцена → bloom → tone mapping → LUT → маска тумана; из материалов выходит линейный цвет.
- Пресеты качества — данные поверх реестра ручек (QUAL-1), обязанность объявить ручку — QUAL-3, пресетные эталоны счётчиков — QUAL-4; счётчики стоимости кадра — PERF-2/PERF-3, регенерация только `npm run golden:cost`.
- Duel: сетка 48×48, уровни 0/1, карта кривизны `content/visuals/arena-curvature.json` уже несёт лощины (узловые смещения до −4); сцена не Blender-сопряжённая, но секции парного документа импорт в любом случае не трогает (PRES-2).
- Целевое железо — Steam Deck: главный риск — fill-rate прозрачной воды; бюджет воды ~1.5–2.5 ms.

## Goals / Non-Goals

**Goals:**

- Подсистема воды с одним ядром материала и двумя источниками детали: чисто программным (без единого текстурного ассета — путь демо) и текстурным (tileable-ассеты по ID).
- Глубина, берег и пена — производные единого поля высот REND-9; никакого второго представления поверхности и никаких новых портов рендерера.
- Аналитическая рябь от движущихся сущностей, render-only, детерминированная от presentation-состояния.
- Авторинг — секция `water` парного документа: клеточная карта + список тел; правка в рантайме без пересборки.
- Ручки качества и счётчики стоимости с первой итерации; вода в duel входит в записанную нагрузку эталонов.

**Non-Goals:**

- Ping-pong height-RT, grab-pass refraction, отражения любого рода, каустика, Gerstner-волны с вершинным смещением — этапы polish за пределами change (пороги перехода — в исследовании).
- Blender-авторинг воды и всплеск-партиклы — отдельные change'и.
- Вода в симуляции — отложена по шву из proposal Notes.

## Decisions

**D1. Плоский меш на урезе; глубина — семпл текстуры глубины тела, запечённой CPU из поля.** Меш тела воды — горизонтальные квады на высоте уреза, greedy-объединение прямоугольников по клеточному региону; на поле вершины НЕ ставятся — вода плоская, рельефно дно. Глубина во фрагменте = урез − поле(x,z): поле семплируется из маленькой текстуры глубины тела (HALF_FLOAT, разрешение — параметр «текселей на клетку», по умолчанию 4, ручкой клампится вниз), которую подсистема заполняет на CPU выборкой того же порта поверхности, что геометрия террейна и посадка (REND-9, «поле одно на всех»). Альтернатива «глубина пер-вершинно» отклонена: у плоского меша вершин мало и берег вышел бы гранёным; альтернатива «depth-текстура сцены» отклонена как требующая второго порта рендерера (REND-1). Инвалидация — теми же затронутыми клетками, что у поля: кривизна, walkable-вклады, догрузка ассетов, переподача документа террейна (REND-14) перезаполняют текстуру не позже следующего кадра.

**D2. Одно ядро шейдера, деталь — два источника за общим интерфейсом семпла.** Фрагментное ядро (глубинный цвет → пена → нормаль → Fresnel-tint → specular) написано против функции `sampleDetail(uv, t) → (normalXY, foamNoise)`; её реализацию выбирает `#define`: `procedural` — 2 октавы value-noise с независимым скроллом (без текстурных ассетов вовсе), `textured` — 2–3 tileable-нормали с разными скоростями/масштабами + текстура шума пены, опционально flow map (Vlachos, две фазы через frac(time)). Наблюдаемое поведение ядра (глубина, берег, бэндинг, рябь) от источника детали не зависит — это и есть требуемая «и tileable-текстуры, и чисто программная вода». Вариант «два материала» отклонён: разъехались бы пена и берег.

**D3. Stylized и semi-realistic — не режимы кода, а параметры.** Один параметр `banding` (0 — плавный градиент глубинного цвета, N≥2 — cel-бэнды со smoothstep-краями) + порог/градиент пены + сила Fresnel покрывают обе колонки таблицы §5 исследования. Дефолты подобраны под stylized (демо): `banding: 3`, procedural-деталь, жёсткий cutoff пены. Semi-realistic достигается данными (banding 0, textured-деталь, мягкая пена) без `#define`-ветвления, кроме источника детали из D2.

**D4. Секция `water`: одна клеточная карта на сцену + список тел.** Формат секции (норму несёт REND-35):

```json
"water": {
  "cells": ["................", "...000....11....", …],
  "bodies": [ { "surfaceLevel": -0.1, "shallowColor": "#4db8c4", "deepColor": "#16505e",
                "maxDepth": 0.5, "banding": 3, "foam": {…}, "detail": {…}, "ripples": {…} } ]
}
```

`cells` — текстовые ряды размером с сетку террейна: `.` — нет воды, цифра `0`–`9` — индекс тела в `bodies` (десяти тел на сцену достаточно; ряд другой длины и символ вне алфавита отвергаются адресно, как TERR-3). Одна карта, а не карта на тело: тела не пересекаются по построению, и карта читается глазами. `surfaceLevel` — десятичное число в шкале уровней террейна (может быть отрицательным и дробным: −0.1 — чуть ниже пола нулевого уровня, в лощине кривизны); в мировую высоту его переводит рендер своим шагом высоты (REND-7) — абсолютной высоты в документе нет, смена шага высоты сцену не ломает. Цвета — линейные sRGB-хексы, конвертация на приёме. Величины — десятичные числа presentation-слоя (PRES-3), fixed-point в документе нет.

**D5. Рябь: кольца от N источников через uniforms; выбор детерминирован.** Источник — сущность presentation-состояния, чья интерполированная позиция лежит в клетках воды (или в кольце в одну клетку вокруг) и чья скорость выше порога; амплитуда — от скорости. Выбор N ближайших к камере/телу при переполнении — сортировкой по квадрату расстояния с tie-break по устойчивому ключу инстанса: кадр воспроизводим от presentation-состояния, мигания источников нет. `N` авторское ≤ 16 (гарантированные лимиты uniform-векторов WebGL2), ручка клампит вниз до 0 — рябь выключена. Формула — затухающие по возрасту и расстоянию кольца `sin(k·d − ω·t)`, суммируются в возмущение нормали; вершины не двигаются. Часы — презентационные (REND-25): пауза/скраб останавливают и ведут воду вместе с остальной картинкой, live-анимация идёт от кадра, а не от тика (REND-2).

**D6. Прозрачность и порядок.** Вода — `transparent: true`, `depthWrite: false`, `renderOrder` ниже прочих прозрачных (частицы, превью каста рисуются поверх). Пишет линейный цвет; bloom/tone map/LUT/маска тумана применяются к ней штатной цепочкой REND-34 — отдельного прохода вода не добавляет, sparkle при желании поднимается в bloom существующим layer-механизмом. Оверлеи и picking воду не видят: поле REND-9 она не меняет, посадка юнитов в лощине идёт по дну — юнит в воде стоит на дне, что и требуется мелководью.

**D7. Ручки качества и счётчики.** Реестр QUAL-1 получает: `water.rippleSources` (потолок числа источников ряби, 0 — рябь выключена), `water.detailLayers` (потолок слоёв текстурной детали / октав шума), `water.depthTexelsPerCell` (потолок разрешения глубинной текстуры тел). Семантика — `min(авторское, потолок)`, документ не мутируется (QUAL-3, как FOW-10). Счётчики в сток стоимости (PERF-2/PERF-3): тел нарисовано, водных инстансов-мешей, активных источников ряби, текселей глубинных текстур заполнено за доставку — детерминированные величины, не wall-time. Duel с водой входит в записанную нагрузку: эталоны `performance`/`ultra` регенерируются `npm run golden:cost` отдельным осознанным диффом (QUAL-4, PERF-4).

**D8. Вода в duel — лощина кривизны, сим-слой не трогается.** Водоём кладётся в существующую отрицательную область карты кривизны (`arena-curvature.json`, смещения до −4): урез подбирается между дном лощины и полом нулевого уровня. Ни `duel.scene.json`, ни golden симуляции, ни записи матчей не меняются — подтверждает пункт «вода — чистая презентация» на живом контенте. Глубокая непроходимая река через уровни/рампы — контент будущих арен, механизм уже готов.

**D9. Тесты — данные и геометрия, не пиксели.** Юнит-тесты: валидация секции (алфавит, длина рядов, индекс вне `bodies`, небулевы/нечисловые поля — адресные находки), greedy-меш из клеток (число квадов, покрытие), заполнение глубинной текстуры (контрольные точки: урез − поле, включая кривизну и walkable), инвалидация по затронутым клеткам, клампы ручек, детерминированный выбор источников ряби. Шейдер покрывается компиляцией материала в обоих `#define`-вариантах и счётчиками стоимости; картинка — руками через `npm run demo` и `npm run bench:demo` (PERF-7).

## Risks / Trade-offs

- **Fill-rate на Deck**: вода прозрачна и не пишет z. Митигация — меш строго по клеткам региона (не полноэкранный квад), одна выборка глубинной текстуры и ≤3 семпла детали на фрагмент, рябь без вершинных смещений; замер — `bench:demo` на профиле устройства.
- **Лимиты uniform**: N≤16 источников ряби укладывается в гарантированные 224 fragment uniform vectors с запасом; проектируем на минимум спецификации.
- **Глубинная текстура тел устареет относительно поля** при пропущенной инвалидации — визуальный артефакт берега. Митигация — единый канал «затронутые клетки» уже существует у потребителей поля; тест D9 закрепляет подписку.
- **`surfaceLevel` в шкале уровней** привязывает документ к шагу высоты рендера семантически (0.5 — «полшага»); это осознанный выбор против абсолютных высот — смена шага высоты масштабирует воду вместе с террейном.
