# design: remote-host-tofu

## Context

Мотивация — proposal.md «Why». Существенное для подхода:

- DSK-8 уже держит первую линию: `certificatePins()` хост-слоя + обработчик `app.on('certificate-error')` в `openSession` (`desktop/shell-ts/src/electron/main.ts`), сверка через `certificateFingerprint()` (`src/host/certificate.ts`).
- `certificate-error` даёт URL запроса от Chromium — origin берётся из него, а не из адресной строки сервиса: запрет DSK-7 «контейнер адрес не разбирает» не задевается.
- Диалоги среды у контейнера уже есть (`dialogs.choose` в `openApp`); решение о доверии — тот же шов: логика в `src/host/` (гейт), диалог — инъекция реализации (DSK-6).
- Клиентская библиотека (`controlClient`, SRV-3) сверяет отпечаток рукопожатия — остаётся второй, более слабой линией; TLS-линия появляется под ней.

## Goals / Non-Goals

**Goals:**

- Удалённый агент достижим из контейнера после одного явного «доверяю» человека; дальше — молча по книге.
- Смена отпечатка известного origin — громкое предупреждение, не молчаливое принятие и не глухой отказ.
- Вся проверяемая логика (книга, порядок решения, схлопывание) — чистый Node в гейте; Electron даёт ровно диалог.

**Non-Goals:**

- UI доверия внутри страницы менеджера (страница сертификатов не видит — граница `browserSocket` не трогается).
- Отзыв доверия из UI (правка/удаление файла книги руками — достаточный механизм для админа; отдельная возможность моста не заводится).
- Изменения протокола агента и пейринга.

## Decisions

- **D1. Книга доверия — файл контейнера в его каталоге данных.** `trust.json` в userData (рядом с `services/`): отображение «origin → отпечаток», атомарная запись тем же приёмом, что у прочих файлов хост-слоя. Origin — строка `wss://host:port` из URL события; формат отпечатка — те же 64 hex, та же валидация «не понял = записи нет». Альтернатива — хранить в книге хостов менеджера — отвергнута: книга хостов принадлежит странице, а сертификаты видит только контейнер; смешение сломало бы границу DSK-2.
- **D2. Решение — функция хост-слоя с инъецированным «спросить человека».** `src/host/trust.ts`: `decideCertificate(origin, fingerprint)` с порядком: пины сервисов → книга (совпало — принять; разошлось — вопрос со сменой) → вопрос «незнакомый». Ответ человека приходит колбэком `ask(question) → Promise<boolean>`; Electron-клей передаёт `dialog.showMessageBox` (кнопки «Доверять»/«Отклонить», в вопросе — origin и отпечаток, при смене — оба). Контрактный сьют инъецирует автоответ — случаи DSK-8 проверяются без человека.
- **D3. Схлопывание — по origin, на уровне решения.** Открытый вопрос по origin держится Promise'ом в Map; повторный `certificate-error` того же origin ждёт тот же ответ. Иначе ретраи WebSocket менеджера (переподключение хоста) наплодят стопку одинаковых диалогов.
- **D4. Порядок оснований фиксирован: пины сервисов первыми.** Локальный агент никогда не доходит до диалога — его закрепление написано им самим (DSK-8), и вопрос человеку про него был бы регрессом MGR-5 «без вопросов человеку».
- **D5. Отказ не запоминается.** «Нет» отвергает соединение, но не пишется в книгу: отказ — решение о попытке, а не о хосте навсегда; следующая попытка спросит снова. Запоминание отказов потребовало бы и способа их снимать — UI, которого нет (Non-Goals).
- **D6. Текст `PAGE_LIMIT` в `browserSocket` уточняется.** Сейчас он говорит «поддержанный путь — профиль контейнера с локальным агентом»; после этого change'а контейнер умеет и удалённый хост — текст называет оба пути. Правка прозы, не поведения.

## Risks / Trade-offs

- [Человек бездумно жмёт «Доверять»] → диалог показывает origin и отпечаток и называет последствие; сильнее среда не может — это ровно модель SSH/SRV-3. Сверка отпечатка с напечатанным на VPS (`агент хоста поднят … отпечаток: …`) — в руках админа.
- [Диалог в момент `certificate-error` блокирует навигацию соединения] → колбэк Chromium терпит отложенный ответ; схлопывание (D3) не даёт стопки окон; на закрытие окна во время открытого вопроса ответ — «отклонить».
- [Origin в книге, а не «хост менеджера»] → один и тот же VPS под другим портом спросит заново — осознанно: другой порт — другой эндпоинт, и молчаливо расширять доверие на все порты хоста нельзя.
- [Гонка двух окон/сессий за файл книги] → окно контейнера одно на процесс (DSK-1), запись атомарна; проигравший последнюю запись переспросит — некорректного принятия нет.
