# desktop-shell — дельта

## MODIFIED Requirements

### Requirement: DSK-8 Закрепление сертификата объявленного сервиса

Объявленный профилем сервис (DSK-7), чей канал существует только шифрованным с self-signed сертификатом, SHALL иметь способ назвать контейнеру закрепление своего сертификата: файл закрепления рядом с адресным файлом сервиса, чей формат определяет контейнер — одна строка, отпечаток SHA-256 сертификата в шестнадцатеричном нижнем регистре без разделителей. Файл SHALL писать сам процесс сервиса по подстановке из объявления профиля — тем же путём, каким сервис называет свой адрес; контейнер MUST NOT строить закрепление сам и MUST NOT извлекать его из адресной строки (DSK-7: адрес контейнер не разбирает).

Сертификат, отвергнутый штатной проверкой платформы, реализация контейнера SHALL принимать ровно по двум основаниям: отпечаток равен закреплению объявленного сервиса зафиксированного профиля (DSK-5), либо этот сертификат принял ЧЕЛОВЕК — явным решением в диалоге среды, который контейнер предъявляет с origin соединения и отпечатком SHA-256 (trust-on-first-use, та же семантика, что у клиентского закрепления `server-control` SRV-3). Отказ в диалоге и закрытие диалога SHALL отвергать соединение. Любой сертификат вне этих двух оснований SHALL оставаться отвергнутым; глобальное отключение или ослабление проверки сертификатов — флагом запуска, настройкой сессии или иным способом — MUST NOT применяться.

Принятые человеком решения SHALL переживать сессию: контейнер SHALL вести книгу доверия «origin → отпечаток» в своём каталоге данных; повторное соединение с известным origin и тем же отпечатком SHALL проходить без диалога. Изменившийся отпечаток известного origin MUST NOT приниматься молча: контейнер SHALL предъявить предупреждение о смене с обоими отпечатками, и продолжить можно только новым явным решением человека. Одновременные попытки соединения с одним origin SHALL схлопываться в один диалог: одному origin — не больше одного открытого вопроса.

Сервис без файла закрепления SHALL вести себя как сегодня: его self-signed сертификат контейнером сам по себе не принимается — путь для него тот же диалог доверия, что для любого чужого сертификата. Для отвязываемого сервиса (DSK-7) закрепление SHALL действовать и через границу сессий: новая сессия, нашедшая переживший сервис, читает то же закрепление из каталога состояния.

#### Scenario: Страница открывает шифрованный канал к объявленному сервису

- **WHEN** страница профиля открывает соединение, в котором сервис предъявляет self-signed сертификат, чей отпечаток равен закреплению этого сервиса
- **THEN** соединение открывается без диалога: проверка платформы дополнена сверкой с закреплением, и совпадение — достаточное основание доверия

#### Scenario: Незнакомый сертификат — вопрос человеку

- **WHEN** страница открывает соединение с self-signed сертификатом, чей отпечаток не равен ни закреплению объявленного сервиса, ни записи книги доверия
- **THEN** контейнер предъявляет диалог с origin и отпечатком; согласие открывает соединение и записывает отпечаток в книгу

#### Scenario: Чужой self-signed сертификат

- **WHEN** человек отклоняет (или закрывает) диалог доверия по чужому self-signed сертификату
- **THEN** соединение отвергается так же, как в браузере без контейнера; отказ в книгу не записывается, и следующая попытка спрашивает заново

#### Scenario: Известный origin молчит

- **WHEN** страница снова открывает соединение с origin, чей отпечаток уже записан в книгу доверия, и предъявленный сертификат совпадает с записью
- **THEN** соединение открывается без диалога — решение человека пережило сессию

#### Scenario: Отпечаток известного origin изменился

- **WHEN** известный книге доверия origin предъявляет сертификат с другим отпечатком
- **THEN** молчаливого принятия нет: контейнер предъявляет предупреждение о смене с прежним и новым отпечатками, и соединение открывается только новым явным согласием, которое переписывает запись книги

#### Scenario: Сервис пережил сессию

- **WHEN** новая сессия открывает страницу при отвязываемом сервисе, пережившем прежнюю сессию с записанным закреплением
- **THEN** канал к сервису открывается: закрепление прочитано из каталога состояния сервиса, второй процесс не поднимался
