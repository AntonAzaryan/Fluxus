# Tasks: sec05-npc-rules-in-content-pack

Требование — `specs/netcode/spec.md` (**NET-17**), разбор решений — design.md (D1–D4). Гейт локальный: `npm run check` из корня (CI нет).

Изменение заводится по факту сделанной работы: валидация спек против кода (`docs/reviews/spec-validation-2026-09-01/05-state-serialization.md`) показала, что правила поведения NPC не входят в сверку «одни ли у нас правила» ни по спеке, ни по коду.

## 1. Дельта требования (D1–D4)

- [x] 1.1 `specs/netcode/spec.md`: MODIFIED NET-17 — пункт 11 перечня (блок `npc` целиком и сам факт его наличия: таблица поведений в объявленном порядке, биндинги, бюджет решений, таблица волн) и абзац с основанием. Блок MODIFIED несёт требование ЦЕЛИКОМ со всеми действующими сценариями: MODIFIED заменяет блок, и опущенный сценарий архивация молча выкинула бы.
- [x] 1.2 Там же: в блок «Нормализация» добавлено правило для `npc` — отсутствующий и пустой блок дают разные хеши, внутренние умолчания документов поведения до хеширования не разрешаются, второго разбора формата не заводится.
- [x] 1.3 Там же: два новых сценария — «Дизайнер переписал поведение босса» и «Сцена без блока npc против сцены с пустой таблицей поведений».

## 2. Код (D1–D3)

- [x] 2.1 `engine/core-ts/src/sim/contentPack.ts`: `contentPackForm` получает `npc: def.npc ?? null` с комментарием, называющим основание, границу «отсутствие против пустоты» и цену решения класть блок как записан.

## 3. Тесты

- [x] 3.1 `engine/core-ts/test/contentPack.test.ts`: сцена с платформой поведения NPC и пять проверок — переписанное поведение даёт другой хеш; биндинги, бюджет решений и таблица волн тоже; отсутствие блока против пустой таблицы; переформатирование документа хеш не меняет; замена ассета арены хеш по-прежнему не двигает (граница с зоной `worldInit`).

## 4. Синхронизация и гейт

- [x] 4.1 Перенести дельту в `openspec/specs/netcode/spec.md`. Изменение при этом НЕ архивируется: оно остаётся в очереди как запись о принятом решении.
- [x] 4.2 `openspec/changes/sec06-netcode-spec-alignment/specs/netcode/spec.md`: блок MODIFIED NET-17 неархивированного изменения приведён к синхронизированному тексту требования. MODIFIED заменяет блок целиком, поэтому отставшая дельта откатила бы пункт 11 в момент своей архивации — молча и задним числом. Заодно эта дельта догнала таблицу мягких стелс-каналов, которой ей недоставало (её `--strict` был красным и до этого изменения).
