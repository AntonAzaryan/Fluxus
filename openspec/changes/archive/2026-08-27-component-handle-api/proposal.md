# Proposal: component-handle-api

## Why

Профиль стресс-эталона `npc-behavior` (196 крипов) показал ~3.5 мс/тик, и доминирует в них не логика решений, а путь чтения: каждое `ctx.get(entity, component, field)` заново резолвит строковые имена компонента и поля через словари мира (`world.ts` `getField`). Данные лежат идеально (SoA, TypedArray), но нативные системы платят хеш-поиск строк на каждое чтение каждого агента каждый тик — тысячи поисков на тик при массе NPC, и тот же налог платят физика, локомоция и способности. Резолвить имя один раз при конструировании системы и читать дальше по числовому handle — чистая оптимизация доступа без изменения семантики.

## What Changes

- `SystemContext` (SYS-5) получает handle-путь чтения рядом со строковым: разрешение имени в handle при конструировании системы и чтение поля по handle в горячем цикле. Строковый путь остаётся — им живут JSON-системы (evaluator) и редкие чтения.
- Новое требование SYS-10 нормирует семантику handle: handle — числовая ссылка (id компонента/поля), а не захваченный указатель на массив; чтение по handle SHALL быть побитово эквивалентно строковому чтению, включая тотальность ECS-7 и окно валидности CMD-5; писать через handle MUST NOT быть возможно (Command Buffer остаётся единственным каналом мутаций — иначе это side channel TICK-3); handle переживает рост хранилища и перемотку.
- Нативные системы переводятся на handle-чтение в горячих циклах: платформа NPC (измеренное узкое место), физика, локомоция, способности, видимость, tween. Поведение побитово не меняется — golden-эталоны не пересчитываются.
- **BREAKING нет**: строковые `get`/`has` не депрекейтятся и не меняются.

## Capabilities

### New Capabilities

_нет_

### Modified Capabilities

- `data-driven-systems`: SYS-5 — контракт `SystemContext` дополняется handle-разрешением и handle-чтением (полный обновлённый интерфейс в дельте); ADDED SYS-10 — семантика handle: эквивалентность строковому пути, только чтение, устойчивость к росту хранилища и перемотке, место разрешения (конструирование системы, не тик).

## Impact

- `engine/core-ts/src/ecs/world.ts` — резолвер handle и функция чтения по handle рядом с `getField`, та же проверка владения (ECS-7) без строковых поисков; `types.ts` — расширение `SystemContext`; `sim/tick.ts`/контекст — прокладка новых методов.
- Нативные системы `engine/core-ts/src/systems/` — миграция горячих чтений на handle (NPC в первую очередь; остальные — тем же паттерном). DSL (`dsl/expr.ts`, `dsl/actions.ts`) не меняется: выражения остаются на именах — авторинг контента не затронут.
- Вне ядра ничего не меняется: сеть, рендер, редактор, бот, сериализация и формат снапшота не затронуты; golden-эталоны без изменений (поведение побитово то же); cost-эталоны без изменений (счётчики меряют единицы работы, не способ доступа); wall-time bench-сентинелы могут только улучшиться (PERF-5 гейтит деградацию).
- Тест паритета: чтение по handle против строкового чтения на одном мире — побитово равно; стресс-сценарий `npc-stress` — измеримое снижение wall-time как диагностика (не гейт).
