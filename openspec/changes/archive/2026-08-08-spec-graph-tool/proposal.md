# spec-graph-tool

## Why

Спека выросла до 27 capability, 317 требований, ~7400 строк — и ~1300 перекрёстных ссылок, размазанных по прозе. Навигация по ней стоит дорого: чтобы процитировать одно требование, агент загружает capability целиком (300+ строк вместо ~20), а целостность графа ссылок проверяется только сплошной ручной сверкой — именно так родился change `spec-modality-and-refs`, чинящий висячие атрибуции ссылок, которые `openspec validate --specs --strict` не видит. Графа спек как запрашиваемой структуры не существует, хотя фактически он в текстах уже есть.

## What Changes

- Новый dev-скрипт `scripts/spec-graph.mjs` (zero-deps, plain Node): stateless-парсер дерева `openspec/specs/` с командами навигации и линтом графа.
  - Навигация: `find <текст>`, `where <ID>`, `show <ID>` (одна секция требования + Purpose), `refs <ID>`, `impact <ID>`, `deps <capability>`, `graph --mermaid`.
  - Линт `check`: висячие ссылки, дубли ID, несовпадение имени capability рядом со ссылкой с фактическим местом определения (класс дефекта RNG-8), секция требования без SHALL/MUST в собственном тексте (класс ED-10), ссылка механизма на game-content. Направление ссылок между слоями — не инвариант, а диагностика (см. design.md D6: калибровка по реальному дереву).
  - Метрики-диагностики (не гейт): fan-in требований, instability capability, требования-сироты, рёбра «вверх» по слоям.
  - `--json` на всех командах — структурный вывод для агентов и сабагентов.
- `check` вводится в **режиме отчёта**; в гейт `npm run check` он встаёт отдельным шагом после того, как дерево спек зелёное (см. Impact).
- CLAUDE.md: короткая норма пользования — цитируешь ID через `spec-graph show`, перед правкой требования смотришь `impact`, свою capability читаешь целиком.
- Тонкий скилл `.claude/skills/spec-graph/` по образцу `spec-coverage`: триггеры и шпаргалка команд.

Вне скоупа (осознанно): suspect links (стейт «ссылка сверена с такой-то версией» — вводится позже по доказанной нужде, ритуалом как у golden), парсинг дельта-спек из `changes/`, любая правка самих спек.

## Capabilities

### New Capabilities

Нет. Это dev-tooling поверх дерева спек, не capability движка: поведение симуляции, сети, рендера и редактора не меняется. `skip_specs: true` в `.openspec.yaml` этого change.

### Modified Capabilities

Нет. Тул read-only относительно спек; найденные им дефекты спек правятся отдельными changes через обычный workflow, не этим.

## Impact

- Новые файлы: `scripts/spec-graph.mjs`, конфиг слоёв (рядом со скриптом), тест парсера/линта, `.claude/skills/spec-graph/SKILL.md`.
- CLAUDE.md — абзац о норме пользования.
- `package.json` (корень): скрипт `spec-graph`; `npm run check` на этом change **не** меняется.
- Порядок ввода гейта: (1) тул приземляется с `check` в режиме отчёта → (2) применяется `spec-modality-and-refs` → (3) остаток находок `check` оформляется новым change → (4) на зелёном дереве `check` добавляется в `npm run check`. Шаги 2–4 — вне этого change.
- Зависимость от формата `### Requirement: <ID> <заголовок>`, принадлежащего OpenSpec: прибит `validate --strict`, апгрейд CLI — точка риска; закрывается тестом парсера на текущем дереве.
- `engine/` не трогается; спеки, эталоны `engine/tests/golden/` и `engine/schemas/` не меняются.
