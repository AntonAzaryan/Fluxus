# Design: terrain-visual-curvature

## Context

Мотивация — proposal.md «Why»; требования — дельты REND-9/REND-10, ASSET-7, ASSET-6, ED-11. Текущее состояние: террейн рендерится ступенями из sim-данных (REND-7), подсистемы рендера — упорядоченный список за узким контрактом (REND-8), манифест визуалов и загрузчики — `engine/assets-ts` (ASSET-3, ASSET-6). Редактор — roadmap stage 12, кода нет: ED-11 остаётся спекой.

## Goals / Non-Goals

**Goals**

- Непрерывная функция визуальной высоты/нормали поверхности, единая для геометрии террейна и наклона инстансов.
- Аддитивность: сцены без карты кривизны и манифесты без параметров наклона работают как раньше, побайтово те же golden-файлы.

**Non-Goals**

- Никаких изменений в `engine/core-ts`, netcode, FoW — кривизна не существует для симуляции.
- Не художественная геометрия произвольной формы (REND-7): только bounded-рельеф поверх ступеней.
- Реализация кисти (Kotlin-редактора ещё нет).

## Decisions

1. **Функция визуальной поверхности — отдельный хелпер рендера, не API подсистемы.** `visualSurface(x, z) → { height, normal }` строится при инициализации рендера из sim-данных террейна + карты кривизны и передаётся обеим подсистемам (террейн, модели). Альтернатива — запрос из подсистемы моделей в подсистему террейна — отвергнута: подсистемы за общим контрактом не знают друг о друге (REND-8).

2. **Интерполяция — билинейная по угловым значениям клеток.** Значение угла = среднее смещений смежных клеток **того же уровня**; через cliff-границу смещения не усредняются — выпуклость плато не «перетекает» на нижний уровень, стенка обрыва остаётся резкой. Рампа входит в базовую высоту (наклонный переход REND-7), кривизна добавляется поверх; нормаль — аналитическая производная той же функции, без численного дифференцирования по кадру. Альтернатива (бикубическая) — не для MVP: дороже, а гладкости C1 по нормали хватает после временного сглаживания наклона.

3. **Наклон — в подсистеме моделей, поверх интерполяции позиции.** Per-instance состояние: текущий up-вектор, сглаживаемый к целевому slerp(вертикаль, нормаль, k) с ограничением лимитом угла; на snap (REND-2) состояние перезаписывается целевым. Порядок в кадре: позиция (интерполяция тиков) → наклон по поверхности → процедурные кости (REND-5).

4. **Карта кривизны — новый вид ассета в реестре** (`terrain-curvature`, ASSET-3): свой загрузчик JSON-формата с текстовыми рядами, парсинг и валидация headless (ASSET-5). Величина смещения хранится как `n/16` в единицах шага высоты; в мировые единицы переводится рендером (шаг высоты — его параметр).

5. **Параметры наклона в манифесте** — блок записи `surfaceAlign: { factor, maxAngle? }` плюс верхнеуровневый дефолт манифеста и ссылка `terrain.curvatureMap`; отсутствующие значения → `factor = 1`, без лимита. Расширение схемы манифеста обратно совместимо.

## Risks / Trade-offs

- [Дрожание наклона на границах клеток при беге по рельефу] → аналитическая нормаль непрерывна по построению + временнóе сглаживание; лимит угла страхует крайние случаи.
- [Стоимость `visualSurface` на инстанс на кадр] → билинейная форма аналитична и дешёва; вызовов — по числу видимых инстансов, не по клеткам.
- [Т-стыки/щели геометрии у cliff-стенок при смещённых краях] → стенка тянется до фактической визуальной высоты кромки (skirt), проверяется визуальным смоук-тестом арены с кривизной у обрыва.
- [Расхождение восприятия: вогнутость рядом с дырой в полу] → амплитуда ограничена алфавитом (< полушага), дыры визуально маркируются иначе (REND-7); при жалобах — уменьшить шкалу, не трогая формат.

## Migration Plan

Чисто аддитивно: новые поля манифеста опциональны, новый вид ассета не затрагивает существующие, golden-файлы и реплеи не меняются. Отката не требуется — удаление карты кривизны возвращает прежнюю картинку.

## Open Questions

- Точная кривая временнóго сглаживания наклона (скорость, easing) — подобрать по ощущению от демо; спека фиксирует только факт сглаживания и snap.
