# Tasks: fp2-mul-small-operands

Требование — `specs/fixed-point-math/spec.md` (**FP-2**), опора — `determinism-core` DET-2 (названное исключение о точной целочисленной арифметике в двоичном контейнере) и FP-3. Гейт один и он локальный: `npm run check` из корня репозитория (CI нет).

design.md у изменения нет намеренно: технического решения здесь не принимается. Форма быстрого пути задана DET-2 поимённо (условия 1–5), доказательство границы живёт рядом с расчётом — в комментарии `mul`, как у `div`, `sqrt` и `sumOfSquares`, — а выбор между «двумя ветвями» и «одной» решает замер, а не архитектура (`docs/reviews/2026-09-02-core-tick-headroom.md`, гэп 5).

## 1. Дельта требования

- [x] 1.1 `specs/fixed-point-math/spec.md`: MODIFIED FP-2 — форма TS-эмуляции названа как выбор из двух ветвей по величине произведения; побитовая парность ветвей и обоснование проверки «влезло» (монотонность округления) объявлены обязательными; запрет `BigInt` в hot-path и порядок «магнитуда → знак» сохранены. Блок MODIFIED несёт требование целиком вместе с обоими действующими сценариями.
- [x] 1.2 Там же: новый сценарий «Малые операнды идут быстрым путём».

## 2. Реализация

- [x] 2.1 `engine/core-ts/src/math/fixed.ts`: быстрый путь в `mul` — `p = a * b`, проверка `|p| ≤ Number.MAX_SAFE_INTEGER`, магнитуда `Math.floor(|p| / 0x10000)`, знак после, тот же `wrap` (FP-4). Медленный путь остаётся без изменений.
- [x] 2.2 Там же: доказательство границы рядом с расчётом (DET-2, условие 5) — какие промежутки чем ограничены, почему проверка по уже посчитанному произведению не пропускает больших (округление к ближайшему монотонно, 2^53 представимо) и почему условие 4 о конвенции округления не возникает.

## 3. Тесты

- [x] 3.1 `engine/core-ts/test/fixed.test.ts`: копия hi/lo-пути внутри теста (`hiLoMulShift`) как эталон парности — не экспорт из ядра (CLI-8), плюс BigInt-эталон truncate toward zero (`bigintMulTruncate`).
- [x] 3.2 Парность на 2^16 псевдослучайных пар геймплейного диапазона (±2^23 — это ±128 юнитов), с проверкой, что вся партия действительно ниже порога.
- [x] 3.3 Граница 2^53: пары `2^26 − 1` на `±(2^27 + k)`, `k ∈ [−4, 4]`, во всех знаковых сочетаниях; тест утверждает, что порог пересечён в обе стороны.
- [x] 3.4 Углы `INT32_MIN`/`INT32_MAX` во всех сочетаниях и отрицательные операнды с ненулевым остатком (FP-3): результат — truncate, а не floor.
