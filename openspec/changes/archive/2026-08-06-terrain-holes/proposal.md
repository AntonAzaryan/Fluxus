# terrain-holes: готовность террейна и арены к механикам провала

## Why

Дизайн хочет арены-острова: игровое поле, ограниченное провалом, и сущности, «проваливающиеся» при попадании в зону дыры. Модель дыр уже есть (флаг `_` в TERR-3, мутабельная карта пола TERR-6, событие `FellThroughFloor` в ARENA-5), но три места не готовы к самой механике падения:

1. Критерий «сущность над дырой» нигде не нормирован — реализация проверяет центр сущности, и сущность любого размера «стоит», пока её центр на полу. Для геймплея провала нужен критерий по опорной области, выводимой из коллайдера, и от его точной формулировки зависит побитовая парность реализаций (CLI-6).
2. Восстановление пола не нормировано: TERR-6 говорит только о снятии. Восстанавливающиеся платформы и мосты требуют, чтобы установка бита пола была легальной мутацией с теми же гарантиями.
3. Связь флага `_` (иммутабельный ассет) с начальным состоянием карты пола (мутабельный компонент) реализована (`terrain.ts`), но не записана нормой — для арены-острова это ключевой контракт.

Сам геймплей падения (анимация, смещение вниз, смерть по порогу) в этот change сознательно **не входит**: он будет отдельной системой поверх подготовленного здесь механизма (см. Notes).

## What Changes

- `ArenaState` получает поле `support` — коэффициент опорной области (Q16.16, доля от коллайдера, дефолт `0`).
- Критерий «на полу» в ARENA-5 нормируется: опорная область — круг радиуса `support × inradius коллайдера`; сущность на полу, если область пересекает хотя бы одну клетку с полом; при `support = 0` или отсутствии коллайдера/физики — проверка по центру (текущее поведение). Дефолт `0` сохраняет существующее поведение и golden-эталоны.
- Дискретность проверки по тикам фиксируется как принятое следствие: перенос через дыру за один тик без попадания центра/области в неё провала не даёт.
- TERR-6 расширяется: установка бита пола (восстановление) — легальная мутация, симметричная снятию; начальное состояние карты пола выводится из карты флагов (`_` → нет пола).
- DSL-действие восстановления пола (симметричное снятию из TERR-8) в этот change **не входит** — см. Notes о секвенировании с `carve-floor-action`.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `arena`: ARENA-3 — поле `support` в `ArenaState`; ARENA-5 — нормативный критерий опоры (опорная область vs центр), дискретность проверки по тикам, поведение без коллайдера и без Physics API.
- `terrain`: TERR-6 — восстановление пола как легальная мутация; нормативная связь флага `_` с начальным состоянием карты пола.

## Impact

- `engine/core-ts/src/systems/arena.ts` — проверка опоры вместо точечного `hasFloorAt` при `support > 0`; доступ к коллайдеру через Physics API (DI-3, опциональная зависимость).
- `engine/core-ts/src/systems/terrain.ts` — предикат «область пересекает пол» (rect-disc в fixed-point).
- `engine/schemas/*.json` — регенерация: у `ArenaState` новое поле.
- Golden: дефолт `support = 0` не меняет поведение существующих сценариев; новый golden-сценарий на провал по опорной области.
- Зависимость: `carve-floor-action` (TERR-8) — независим по файлам спеки, но восстановление пола как DSL-действие будет отдельным change'ом после его архивации.

## Notes

Решения, принятые на входе (обсуждение с геймдизайном):

- Будущая система падения — **нативная** TS-система, а не JSON: она потребует состояния падения и согласования с физикой/FoW. Единый интерфейс `System` это допускает; событие `FellThroughFloor` остаётся швом между механизмом и этой системой.
- Геймплей падения: анимация на модели + смещение вниз, смерть при пересечении порога по z. **Конфликт с PHYS-1**: непрерывная вертикальная координата в симуляции запрещена. Порог по z будущей системе придётся выразить длительностью в тиках (наблюдаемо эквивалентно; z рисует представление из прогресса падения) либо пересмотреть PHYS-1 отдельным change'ом. Решается при вводе системы падения, не здесь.
- Событие обратного перехода «пол появился под ногами» (для отмены падения над восстановившейся платформой) не вводится: потребителя ещё нет, нативная система падения сможет опрашивать пол сама. Пересмотреть при её вводе.
