# Design: terrain-holes

## Context

Мотивация и границы — proposal.md; нормативная сторона — дельты `arena` (ARENA-3, ARENA-5) и `terrain` (TERR-6). Текущая реализация: `ArenaSystem` (`engine/core-ts/src/systems/arena.ts`) проверяет `ctx.terrain.hasFloorAt(position)` — точку-центр; `terrain.ts` уже инициализирует биты пола из флага `_` (норма для этого дописана в TERR-6); коллайдеры — круг и AABB, имя компонента коллайдера — параметр физики, а не конвенция ядра (PHYS-2).

## Goals / Non-Goals

**Goals:**

- Опорная проверка пола по уменьшенному коллайдеру, дефолтом ведущая себя как сегодняшняя точечная (golden не двигаются).
- Восстановление пола как легальная мутация на уровне модели.

**Non-Goals:**

- Система падения (нативная, отдельный change): состояние падения, анимация, смерть по порогу. Здесь только готовность механизма.
- DSL-действие восстановления пола: симметрия к действию снятия из TERR-8 (`carve-floor-action`), вводится отдельным change'ом после его архивации, чтобы два change'а не правили одну таблицу ACT-1.
- Навигационная непроходимость клеток без пола — вместе с pathfinding (TERR-7).

## Decisions

**1. Коэффициент — поле `support` в `ArenaState`, а не отдельный компонент и не параметр системы.**
Участие в проверках арены и их параметры — один гейт: отдельный опциональный компонент дал бы вторую маску на горячем пути, а параметр конфигурации системы сделал бы «цепкость» общей для всех сущностей — это балансная величина уровня prefab. Поле снапшотится на общих основаниях, значит модификаторы могут менять его по ходу матча. Альтернатива «абсолютный радиус опоры вместо доли» отвергнута: доля масштабируется с коллайдером сама, не требуя синхронизации двух чисел в prefab.

**2. Опорная область — круг `support × inradius`, одна форма для всех коллайдеров.**
Для AABB берётся меньшая полуось (вписанная окружность). Альтернатива — уменьшенный прямоугольник для AABB — дала бы две ветки narrow-теста и разные «стоишь на краю» у круга и AABB. Круг-точка при `support = 0`, без коллайдера или без Physics API — вырождение в сегодняшний `hasFloorAt`.

**3. Предикат «область пересекает пол» живёт в терейне, форму коллайдера даёт физика.**
`TerrainApi` получает запрос вида `hasFloorWithin(position, radius)`: обход клеток в bounding box круга, ближайшая точка прямоугольника клетки через clamp, сравнение квадратов (`distSqLe`), включительно. Порядок обхода на результат не влияет (проверка существования), ранний выход разрешён. Радиус опоры мал (доля коллайдера), переполнение квадратов (предел ~181 единицы, PHYS-6) не достигается. Inradius коллайдера `ArenaSystem` берёт через Physics API — имя компонента коллайдера знает физика; при отсутствии Physics API в сборке предикат не вызывается (вырождение, решение 2).

**4. Тотальность за краем сетки — по ближайшей клетке.**
Если круг опоры не пересёк ни одной клетки сетки, ответ даёт ближайшая к позиции клетка (правило TERR-4). Частично пересекающий сетку круг считает только реальные клетки. Так сущность, выбитая за край сетки арены-острова с `_`-периметром, штатно теряет опору, а тик не падает.

**5. Восстановление пола не требует нового механизма.**
Установка бита — та же мутация слова карты через Command Buffer, что и снятие; нативный помощник, симметричный `carveFloor`, добавляется при первом потребителе (система платформ), не сейчас. В этом change — только норма TERR-6 и тест, что установка бита проходит через буфер, снапшотится и откатывается.

## Risks / Trade-offs

- [Проверка опоры дороже точечной: до ~(2r/tileSize+1)² клеток на сущность с `support > 0`] → радиус — доля коллайдера, на практике круг накрывает 1–4 клетки; сущности с `support = 0` идут прежним путём без обхода.
- [Поле `support` в `ArenaState` меняет схему компонента → plain-форма снапшота и схемы `engine/schemas` меняются] → регенерация `npm run schemas`; дефолт `0` сохраняет поведение, golden-эталоны не двигаются, но снапшотная plain-форма получает новый ключ — проверить `matchGolden` и при расхождении перезаписать по процедуре golden-update с диффом в коммите.
- [Валидация `support ∈ [0, 1]` при мутации: generic `setField` диапазонов не знает] → валидация на загрузке prefab/сцены; мутация вне диапазона — зона ответственности будущей валидации мутаций, пока фиксируем нормой (ARENA-3) и тестом загрузчика.

## Open Questions

- Порог смерти будущей системы падения: «по z» из геймдизайна против PHYS-1 (непрерывная вертикаль в симуляции запрещена). Кандидат — длительность падения в тиках, z — представлению. Решается при вводе системы падения.
- Событие обратного перехода «пол появился под ногами» (отмена падения над восстановившейся платформой) — вводить при появлении потребителя.
