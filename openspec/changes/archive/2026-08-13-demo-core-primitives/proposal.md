## Why

Демо-арена переходит от «ходьбы с заглушкой фаербола» к проверяемому по сети набору боевых механик (заряжаемый фаербол, щит с рикошетом, захват снаряда). Три механизма, на которые эти механики опираются, в движке отсутствуют, и каждый из них универсален — нанизывать на них будет любая будущая способность, а не только демо: семантика удержания/отпускания кнопок, селективная блокировка действий и честная нормаль столкновения для отскока.

## What Changes

- **Hold/release кнопок.** Слой ввода начинает доносить до симуляции фактическое состояние удержания: бит действия в `buttons` держится, пока орган управления зажат, а не приходит одно-тиковым импульсом. Фронт нажатия по-прежнему латчится (не теряется между тиками); отпускание становится наблюдаемым как falling edge через `prevButtons` (`tick-loop` TICK-4). Формат `InputFrame` не меняется — меняется только семантика заполнения маски. Существующие детекторы rising edge (локомоушен LOC-3, каст в контенте) продолжают работать без правок.
- **Селективный лок действий (`ActionLock`).** Новый компонент-механизм с битовой маской заблокированных классов действий. `LocomotionSystem` начинает уважать биты «манёвры запрещены» (уклон/перекат/прыжок), не трогая обычную ходьбу; JSON-системы проверяют свои биты сами обычными выражениями DSL. Какие состояния какие биты ставят — политика контента (`addComponent`/`modifyComponent`/`removeComponent`); соответствие битов классам действий — параметры систем, а не константы ядра.
- **Честная нормаль столкновения.** Событие столкновения для пары с участием круга несёт нормаль поверхности в точке контакта (для кругов — по линии центров), а не осевую ±1 по оси движения. Без этого отскок снаряда от круглого щита физически неверен. Для пар AABB-AABB осевая нормаль остаётся корректной и сохраняется.

## Capabilities

### New Capabilities

(нет — все три изменения ложатся в существующие capabilities)

### Modified Capabilities

- `input-devices`: INP-2 — латчинг фронтов дополняется семантикой удержания: маска действий сэмпла отражает состояние удержания на момент выборки, объединённое с залатченными фронтами; отпускание наблюдаемо симуляцией.
- `locomotion`: новое требование LOC-7 — система локомоушена уважает селективный лок манёвров из компонента-маски; имя компонента и биты — параметры системы (в духе LOC-1).
- `physics`: PHYS-9 — уточнение: нормаль столкновения для пар с кругом SHALL быть нормалью поверхности в точке контакта, а не осью движения.

## Impact

- `engine/client-ts/src/input/sampler.ts` (+ источники `keyboardMouse`, `gamepad`, `touch`, при необходимости `bindings`) — held-состояние в маске действий; тесты семплера.
- `engine/core-ts/src/systems/locomotion.ts` — проверка лок-маски перед стартом манёвра; новый компонент в контенте демо-сцены (контент — вне этого чейнджа).
- `engine/core-ts/src/systems/physics.ts` — вычисление нормали для пар circle-circle и circle-AABB в событии столкновения.
- Golden-эталоны: поведение существующих сценариев не меняется (лок-компонент ни на ком не стоит, нормаль в текущих сценариях не потребляется, held-биты в записанных вводах отсутствуют); если эталон всё же дрогнет — регенерация по процедуре `npm run golden` с диффом в коммите.
- Спеки: дельты `input-devices`, `locomotion`, `physics`; `spec-graph check` на перекрёстные ссылки.
