# Design: content-boundary-loader-not-directory

## Context

Мотивация — `proposal.md`, «Why». Change чисто спековый: код и контент уже соответствуют целевому тексту (PRES-1 реализован, парный документ лежит в `content/scenes/` и грузится модулем ассетов), меняется только формулировка CONT-2.

## Goals / Non-Goals

- Goal: CONT-2 говорит прямо — граница sim/presentation задана каналом загрузки; парный документ сцены назван в перечислении presentation-контента; его соседство с конфигом сцены — законный случай, купленный парностью именем.
- Non-Goal: менять PRES-1..5, ASSET-*, поведение загрузчиков или раскладку `content/` — ничего из этого change не трогает.

## Decisions

1. **Дельта несёт полный финальный текст CONT-2.** Правки три: пополнено перечисление presentation-контента; абзац «Соседство поддеревьев MUST NOT ослаблять запрет ASSET-1» развёрнут в норму «границу задаёт канал загрузки», сохранив прежний запрет; добавлен сценарий «Presentation-документ в sim-поддереве». Прежние два сценария сохранены дословно.
2. **Разрешение адресное, а не общее.** Формулировка «другим presentation-файлам в sim-поддереве делать нечего» оставляет исключением ровно парный документ: без неё правка читалась бы как разрешение складывать модели куда угодно, и «два поддерева» потеряли бы смысл.
3. **Конкурирующих дельт нет.** На момент написания ни один change очереди не несёт дельты `game-content` (проверено по `openspec/changes/*/specs/`); перед синхронизацией проверку повторить.

## Risks / Trade-offs

Риск один — расхождение с «Неснимаемыми принципами» `openspec/config.yaml`: там границы слоёв не перечислены по директориям, правка их не задевает; сверено.
