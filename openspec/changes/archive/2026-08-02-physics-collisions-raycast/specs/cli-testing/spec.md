## MODIFIED Requirements

### Requirement: CLI-2 Вход CLI

Входом CLI SHALL быть один JSON-документ: сценарий (сцена по SER-7) + начальное состояние + seed + `inputs[]`.

Начальное состояние SHALL задаваться расстановкой prefab'ов — списком `{prefab, overrides}`: порядок элементов задаёт выданные ID (ID-2, DET-6), а сам список пишется и читается человеком, в отличие от plain-формы мира. Инпуты SHALL раскладываться по тикам по собственному полю `tick` (TICK-2).

Документ со списком `inputs[]` SHALL содержать упорядоченный список игроков — тот, что задаёт слоты (TICK-5). Без него адресация фреймов к сущностям не определена, а прогон невоспроизводим; порядок игроков SHALL быть частью документа, а не аргументом командной строки, чтобы его изменение попадало в дифф вместе с эталоном.

Документ SHALL допускать необязательное поле включения физики (`physics` PHYS-4) с параметрами её системы. Оно живёт в сценарии, а не в конфиге сцены: физика — зависимость сборки (DI-3), и SER-7 прямо запрещает её присутствие среди данных сцены. Прогон без этого поля SHALL идти без физики — прежние сценарии и их эталоны от изменения не зависят.

#### Scenario: Воспроизведение матча по записи

- **WHEN** на вход подаются seed и записанные инпуты
- **THEN** CLI воспроизводит матч без дополнительных данных

#### Scenario: Тот же сценарий из теста и из командной строки

- **WHEN** сценарий прогоняется golden-тестом и командой CLI
- **THEN** обе стороны зовут один и тот же прогон и дают побитово одинаковый вывод

#### Scenario: Инпуты без списка игроков

- **WHEN** сценарий содержит `inputs[]`, но не содержит списка игроков
- **THEN** прогон падает до первого тика: слоты не определены

#### Scenario: Сценарий с физикой

- **WHEN** документ содержит поле включения физики, а сцена — террейн и коллайдеры
- **THEN** статика обрывов строится при загрузке (PHYS-7), система разрешения движения регистрируется, и эталон фиксирует блокировки вместе с событиями столкновений
