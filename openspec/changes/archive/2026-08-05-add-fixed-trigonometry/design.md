## Context

Мотивация — в `proposal.md`. Технически важное на входе:

- Скаляры Q16.16 живут в `engine/core-ts/src/math/fixed.ts`, интерфейс `MathApi` — в `types.ts`, реализация — `math/mathApi.ts`; таблица операторов DSL — `dsl/expr.ts` (`num1`-хелпер для унарных операторов уже есть).
- Набор операторов **перечислен** в JSON-схемах: `system.schema.json` строится из экспорта `operators` (`dsl/schema.ts`). Допущение proposal «регенерация схем не требуется» проверено и неверно — `npm run schemas` обязателен.
- Float в тестах разрешён (`fromFloat` «только для констант и тестов», DET-2) — эталонная сверка таблицы с `Math.sin` может жить в vitest.

## Goals / Non-Goals

**Goals:**

- `sin`/`cos` в Q16.16, воспроизводимые бит в бит любой реализацией ядра (задел Rust-порта, этап 20).
- Операторы `sin`/`cos` в закрытой таблице выражений (EXPR-6).

**Non-Goals:**

- `atan2`, `tan`, повороты векторов, полярные конверсии — по требованию, отдельными изменениями.
- Перевод `CastFireball` демо в JSON — этап 30 (`cast-fireball-in-json`); этот change даёт ему механизм, но не трогает контент.
- Изменение формата `aimDir` (TICK-2).

## Decisions

**1. Единица угла — binary angle measure: оборот = 2^16.** Ключевое свойство: сырое значение угла совпадает с Q16.16-записью доли оборота (`16384` = `0.25` оборота = 90°), то есть угол — обычное Q16.16-число для всей остальной арифметики, а заворачивание — маска `& 0xFFFF`, бесплатная и точная, включая отрицательные углы через two's complement. Альтернатива — радианы в Q16.16 — отклонена: на обороте остаётся ~2.6 значащей десятичной цифры, приведение по модулю требует деления на иррациональное 2π (округление FP-3 накапливается), а узлы таблицы не попадают в целые значения аргумента.

**2. Таблица первой четверти, 257 узлов, шаг 64 единицы.** Ошибка линейной интерполяции синуса ограничена `h²/8·max|sin″|`: при `h = 2π/1024 ≈ 0.0061 рад` это `4.7·10⁻⁶` — треть кванта Q16.16 (`1/65536 ≈ 1.5·10⁻⁵`). Больше узлов точность результата в Q16.16 уже не улучшает (доминирует округление), вдвое меньше (129) — даёт межузловую ошибку больше кванта. 257-й узел — сентинел `sin(90°) = 65536`: интерполяция не требует заворота индекса внутри четверти.

**3. Таблица — литерал в исходнике, не порождение в рантайме.** libm-синусы расходятся в младшем бите между языками и платформами; таблица, порождённая на месте, десинкает кросс-языковую парность недетектируемо до первого матча. Литерал (257 × i32, ~2 КиБ исходника) порождён офлайн по нормативной формуле FP-8; тест сверяет каждый узел с `Math.round(Math.sin(2π·i/1024)·65536)` — двойная точность даёт запас на порядки от границы округления, а float в тестах разрешён. CORE-1 не задет: зависимостей нет.

**4. Сведение к четверти — знак после магнитуды.** Тот же порядок, что в FP-2 (`mul`): внутри четверти вся арифметика неотрицательна, `>> 6` — усечение неотрицательного, то есть truncate toward zero без ветвлений; знак навешивается при развороте четвертей. Симметрии дают точность на осях без специальных случаев.

**5. Раскладка по коду.** Механизм (core): `math/fixed.ts` — `SIN_TABLE`, `sin`, `cos`; `types.ts` — `MathApi.sin/cos`; `math/mathApi.ts` — проводка; `dsl/expr.ts` — операторы через готовый `num1`. Политика: использование углов — целиком в JSON-контенте (этап 30), в этом change контент не меняется. `export * as fixed` уже реэкспортирует новые функции; поверхность API меняется добавлением, `api-surface.golden.json` отслеживает имена верхнего уровня — диффа не ждём, тест скажет.

**6. Эталоны.** Существующие golden-сценарии тригонометрию не используют — `engine/tests/golden/` не меняется; изменение схем — только `npm run schemas` (генерация из ядра, руками не правится).

## Risks / Trade-offs

- [Литеральную таблицу можно «поправить» руками незаметно для генератора] → тест-сверка каждого узла с формулой FP-8 краснеет на любой правке; формула нормативна, расхождение — дефект данных.
- [BAM непривычнее радиан для авторов контента] → редактор (этап 12) конвертирует при сохранении, как уже решено для Q16.16-литералов (EXPR-2); в сыром JSON `16384 = 90°` читается не хуже, чем `102944 ≈ π/2`.
- [Интерполяция не даёт последний бит точности между узлами] → допуск ±2 кванта к float-эталону зафиксирован тестом; для геймплейных углов это заведомо достаточно, а битовая воспроизводимость реализаций — свойство таблицы и правила, не близости к идеальному синусу.

## Migration Plan

Развёртывания нет: чистое добавление. Порядок: `fixed.ts` + типы + `mathApi` → тесты математики → операторы DSL + тест → `npm run schemas` → полный `npm test` + `npm run typecheck`.
