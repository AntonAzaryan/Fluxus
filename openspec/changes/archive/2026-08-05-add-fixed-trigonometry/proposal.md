## Why

Этап 29 roadmap. Тригонометрии в fixed-математике ядра нет вовсе, и это упирается не в удобство, а в выразительность контента: направление каста нельзя получить из угла внутри симуляции. Отсюда хак демо — направление пакуется двумя Q2.14 в один `i32` поля `aimDir` и распаковывается сдвигами в нативной TS-системе, потому что сдвигов в DSL нет и не будет (EXPR-2 прямо отвергает полный набор битовых операций).

Пока `sin`/`cos` не существует, любая способность с произвольным углом — конус, разлёт, наведение, вращение — обязана быть нативной. Это ровно та стена, о которую упирается «геймдизайнер собирает системы без правки кода».

## What Changes

- Math API получает `sin` и `cos` в Q16.16 (FP-7+), реализованные таблицей.
- Единица угла фиксируется нормативно. Кандидат по умолчанию — binary angle measure: полный оборот = 2^16 единиц, заворачивание бесплатно (маска), деления на π в горячем пути нет. Альтернатива — радианы в Q16.16, у которых на полном обороте остаётся мало значащих бит.
- Сами табличные данные (или формула их порождения вместе с правилом округления и размером таблицы) становятся **нормативными** — как раскладка карты пола в TERR-6.
- Уточняется EXPR-2: `sin`/`cos` доступны из JSON-выражений. Формулировка «векторная математика через Math API» уже допускает это по духу, но операторы в таблице кода их пока не содержат.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `fixed-point-math`: новые требования на `sin`/`cos`, единицу угла, источник таблицы и правило округления между её узлами (FP-3 — truncate toward zero — на интерполяцию распространяется явно, а не по умолчанию).
- `data-driven-systems`: EXPR-2 — операторы `sin`/`cos` в наборе выражений.

## Impact

- `engine/core-ts/src/math/` — таблица и функции; ядро остаётся без runtime-зависимостей (CORE-1), таблица порождается сборкой или лежит литералом.
- `engine/core-ts/src/dsl/expr.ts` — операторы.
- Регенерация JSON-схем **требуется**: набор операторов перечислен в `system.schema.json` (`propertyNames.enum` строится из экспорта `operators`) — `npm run schemas` после добавления.
- Golden-эталоны не двигаются: существующие сценарии тригонометрию не используют.
- **Rust-порт (этап 20):** таблица обязана совпадать бит в бит, иначе кросс-языковая парность рушится на первой же способности с углом. Это и есть причина, по которой требование нормирует данные, а не только сигнатуру.

## Notes

Решение по единице угла и таблице принято в `design.md`: binary angle measure (оборот = 2^16), таблица первой четверти из 257 узлов с линейной интерполяцией — межузловая ошибка меньше кванта Q16.16.
