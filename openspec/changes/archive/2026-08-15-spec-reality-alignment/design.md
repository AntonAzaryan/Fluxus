## Context

Мотивация — `proposal.md` «Why». Каждое решение здесь взято не из рассуждения, а из §0 отчёта `docs/reviews/2026-08-15-repo-audit.md`, где владелец репозитория закрыл открытые вопросы разбора; ссылки на пункты отчёта (C-1, C-2, A-1, A-2, A-4, D-1/D-2, SHELL-3/4/5) стоят в каждом разделе ниже.

Ограничения, формирующие подход:

- ID и назначение требований сохраняются (`openspec/config.yaml`); правки минимальны и локальны — это чейндж выравнивания, а не переписывания капабилити.
- Спека — источник правды (CORE-3), но три пункта (SHELL-3/4/5) владелец решил закрыть в обратную сторону: код признан правильным, спека приводится к нему. Такое решение всегда явное и здесь названо по имени.
- Норма живёт в одном месте: `openspec/config.yaml` прямо запрещает дублировать требование в двух capability. Это и есть механика D-1/D-2 и часть механики C-1.
- Единственная задача реализации — A-1. Остальные девять пунктов кода не касаются.

## Goals / Non-Goals

**Goals:**

- Снять все жёсткие противоречия и дрейф спеки, названные §2 и §3 отчёта и закрытые решением владельца в §0.
- Сделать сцену с `fog` без `terrain` невозможной — отказом валидации с русским сообщением, называющим зависимость, а не фолбэком.
- Оставить `npm run check`, `openspec validate --specs --strict` и `spec-graph check` зелёными.

**Non-Goals:**

- Пункты §0, отданные другим чейнджам: C-3, A-3, CH-3 (`rewind-ult`), CH-1 (`terrain-texturing`), CH-2 (`blender-level-design-integration`). Этот чейндж их файлов не касается.
- Аналог A-1 для арены (ARENA-5 ↔ TERR-6, «пол без террейна»). §0 отчёта оставляет его открытым сознательно, и решение по туману на него не распространяется.
- Ретюн-гарды, рефакторы, coverage, `engines`/`.nvmrc`, перенос `demo-serve` — отдельные пункты §0 с собственной судьбой.

## Decisions

**Решение 1. OBS-4 сужается, владение уходит по ссылке в NET-13 (C-1).** Отчёт: NET-13 — более поздний и проработанный текст, его сценарий прямо отвергает конструкцию, которую предписывает OBS-4. Альтернатива — чинить NET-13 — отвергнута там же: она вернула бы в сетевой слой второе определение слова «видно», против которого NET-13 и написан. Поэтому из OBS-4 уходит фраза «Per-client фильтрация событий по видимости — тоже в потребителе (netcode-слой)», а на её место встаёт разделение «выбор точки зрения и момент — в потребителе, вычисление видимого — механизм ядра (NET-13)». Собственного правила о границе OBS-4 больше не несёт — ровно так же, как FOW-6 не несёт собственного правила порядка, отдав его DET-9.

**Решение 2. Локомоция вписывается в перечни, а «единственное основание» SER-7 заменяется на «ровно два основания» (C-2).** Код (`engine/core-ts/src/sim/build.ts`) регистрирует `LocomotionSystem` в сборке рядом с `InputSystem`, по наличию поля `locomotion` в документе прогона. Ни одно требование этого не разрешало: SER-7 объявлял зависимость сборки «единственным основанием» для регистрации сборкой, а у локомоции зависимости нет. Альтернатива — переписать код так, чтобы локомоция включалась составом сцены, — отвергнута: имена компонентов и биты кнопок система берёт параметрами (LOC-1), а список игроков и выбор механизма передвижения принадлежат документу прогона, а не арене; сцена, жёстко назвавшая механизм передвижения, перестала бы подниматься другой оболочкой. Поэтому спека описывает фактическую сборку: второе основание — «система сама является выбором сборки, объявляемым документом прогона», и под него подпадает `InputSystem`, который сборка регистрировала и раньше, будучи при этом не покрытым «единственным основанием» ничуть не лучше локомоции. Третьего основания текст закрывает явно, чтобы новое исключение требовало правки спеки.

**Решение 3. A-1 закрывается запретом, и владелец нормы — SER-7.** §0: «Запретить: сцена с `fog` без `terrain` — ошибка валидации при загрузке (спека + код), а не молчаливый фолбэк». Владельцем выбран SER-7: он и перечисляет поля конфига сцены, и уже несёт норму «загрузчик поднимает мир, валидируя содержимое». FOW-5 получает одну фразу — «запрос уровня у сцены с туманом есть всегда, потому что SER-7 отвергает обратное» — и тем самым перестаёт описывать несуществующий случай, не заводя второй нормы. Альтернативы, отвергнутые вслед за §0: фолбэк «все уровни нулевые» (выглядел бы исправной FoW и отличался бы от неё только на сценах с перепадом высот) и обязательный `terrain` у любой сцены (сломал бы легальные плоские сцены без тумана).

**Решение 4. Проверка живёт в `loadScene`, до создания мира.** Место выбрано по симметрии с уже существующими проверками того же слоя (`checkArenaSupport`, `createTerrainGrid`): бросок на первом нарушении, префикс ID требования в сообщении, русский текст. Это же автоматически даёт находку редактору: `editor/core-ts` не имеет собственной валидации конфига сцены и получает сообщение `loadScene` дословно (ED-29, `engineRules.ts`). Проверка в `buildSimulation` была бы поздней — конфиг сцены без прогона (редактор, `contentPackHash`) её бы не увидел.

**Решение 5. A-2 — имена полей пишутся в требования-владельцы событий, а тезис о форме данных уходит в OBS-1.** Имена берутся из кода: `Collision { entity, other, nx, ny }` (`physics.ts`), `Overlap { entity, other }`, `LeftArena { entity }`, `FellThroughFloor { entity }`. Нормаль лежит двумя скалярами `nx`/`ny`, а не вектором, потому что вектор значением поля данных события быть MUST NOT (EXPR-7) — спека фиксирует именно это, а не выдуманное поле `normal`. Висячую атрибуцию NET-13 («данные события — плоская карта чисел, `tick-loop` OBS-1») чиним добавлением тезиса в OBS-1, а не удалением ссылки: OBS-1 уже описывает `events` в отчёте тика, и форма записи события — естественно его. Альтернатива — переписать атрибуцию на `data-driven-systems` — отвергнута: там форма события описана только с одной стороны (EXPR-7 запрещает вектор), и владельцем целого утверждения этот текст не является.

**Решение 6. A-4 — PHYS-1 переписывается со ссылкой на PHYS-11.** Вторая фраза PHYS-1 («не как перепад высот, а как статические коллайдеры») читалась как лицензия игнорировать направленный гейт. Новый текст сохраняет главное — непрерывной вертикали в расчёте нет, обрыв входит в 2D-геометрию коллайдером — и добавляет, что проходимость решает PHYS-11 по разности уровней сторон ребра. Норму гейта PHYS-1 не повторяет.

**Решение 7. D-1/D-2 — пересказ заменяется ссылкой, а не удаляется молча.** SNAP-5 сохраняет свой предмет (порядок оптимизаций, запрет structural sharing, dirty-набор вне снапшота) и там, где пересказывал FOW-2 и FOW-6, теперь называет их владельцами и объясняет, зачем они здесь упомянуты. PHYS-4 отдаёт отключаемость в DI-3 и оставляет за собой сторону физики — «реализация доступна только через Physics API». Пустым требование не остаётся: пустое требование пришлось бы удалять, а его ID цитируется CLI-2 и схемой сценария.

**Решение 8. SHELL-3/4/5 — спека к коду, и граница вытеснения формулируется как норма.** §0: «Спеку к коду: узаконить словарь в конвертах, границу вытеснения событий, „мелкий конверт“». Ключевой выбор — как писать про `maxEventAgeTicks`: не «событие может потеряться, если не повезёт», а «глубина аккумулятора ограничена, вытеснение наблюдаемо счётчиком в доставке». Иначе спека узаконила бы потерю, а не границу, и следующий читатель не отличил бы дефект от нормы. Для SHELL-3 запрет переформулирован по объёму («ничего, что растёт со сценой»), а не по числу объектов: «ноль объектов на тик» поверх `postMessage` невыполнимо, и буква, которую реализация обязана нарушить, — та же болезнь, что чинится здесь.

## Risks / Trade-offs

- **Golden-эталон `visibility` меняется поведенчески.** `engine/tests/golden/visibility.scenario.json` — сцена с `fog` и без `terrain`. Добавление террейна создаёт сущность-носителя карты пола ДО расстановки, сдвигает выданные ID и меняет хеш `worldInit`, то есть эталон перегенерируется целиком, а не редактируется. → Перегенерация строго через `npm run golden` из корня, диффом эталона в том же коммите; смысл сценария (видимость через стену) сохраняется — террейн ровный, без обрывов, чтобы фильтр по уровню не менял ответ.
- **Сцены-фикстуры вне ядра.** Фикстуры с туманом без террейна живут ещё в `engine/net-ts`, `editor/core-ts` и `editor/ui-ts`; каждая падёт на новой валидации. → Правка точечная: ровная сетка минимального размера, если предмет теста не в террейне; там, где предмет теста — сам отказ, фикстура остаётся и проверяет сообщение.
- **Сдвиг ID в сетевых фикстурах.** Добавление террейна в `fogScene()` сетевых тестов создаёт носителя и сдвигает ID героев. → Тесты, завязанные на конкретные ID, правятся вместе с фикстурой; тесты, сравнивающие снапшоты сторон между собой, к сдвигу нечувствительны.
- **Спека к коду — исключение, а не прецедент.** Три требования оболочки приведены к реализации, и это может быть прочитано как разрешение чинить спеку вместо кода. → Решение принято владельцем поимённо (§0) и обосновано в решении 8 существом каждого случая; CORE-3 остаётся правилом по умолчанию.
- **Чужие открытые чейнджи.** `rewind-ult`, `blender-level-design-integration`, `terrain-texturing`, `ramp-chain-surface` держит другой автор, и их дельты трогают соседние капабилити. → Пересечений по требованиям у этого чейнджа с ними нет; синк идёт только по перечисленным здесь ID.

## Migration Plan

1. Дельты спек → `openspec validate --strict`.
2. Код A-1: проверка в `loadScene`, тест отказа, правка фикстур снизу вверх (ядро → net → editor → golden).
3. `npm run golden` из корня — только после того, как все прочие тесты зелёные, чтобы перегенерация не зафиксировала попутный дефект.
4. `npm run check` из корня.
5. Синк дельт в главные спеки → `openspec validate --specs --strict`, `npm run spec-graph -- check`.
6. Архив чейнджа.

Откат: чейндж целиком лежит в рабочем дереве одним набором правок; откат — возврат дерева, отдельной процедуры не требуется.
