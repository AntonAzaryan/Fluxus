## 1. Действия random и randomBelow (ACT-1, RNG-6)

- [x] 1.1 `random { as, subStream?, do }` — `nextFixed()`, значение в Q16.16
- [x] 1.2 `randomBelow { as, bound, subStream?, do }` — `nextBelow(toInt(bound))`, результат сырое целое
- [x] 1.3 `bound` меньше единицы — ошибка, называющая значение
- [x] 1.4 `subStream` — строковый литерал, стрим по RNG-7; по умолчанию основной стрим системы
- [x] 1.5 `as` вводит имя только в тело `do` — та же семантика, что у `let` и `forEach`

## 2. Валидация (SYS-3)

- [x] 2.1 `subStream` — литерал, `bound` — выражение, `do` — список действий
- [x] 2.2 Опечатка в имени действия падает на регистрации — покрыто закрытым набором `actionNames`
- [x] 2.3 Переменная из `as` видна в теле и не видна снаружи

## 3. Схемы (SER-5)

- [x] 3.1 `system.schema.json` и `scene.schema.json` перегенерированы из `actionNames`
- [x] 3.2 Тест сверки закоммиченных схем зелёный

## 4. Тесты и эталоны

- [x] 4.1 Одинаковый seed → одинаковая последовательность; разный seed → разная
- [x] 4.2 Суб-стрим независим: добавление вызова в одну ветку не сдвигает другую (RNG-2)
- [x] 4.3 `randomBelow` совпадает с прямым `nextBelow` — распределение не смещено остатком
- [x] 4.4 Golden-сценарий со случайным разбросом; поле `rng` в снапшотах непустое
- [x] 4.5 Восстановление снапшота продолжает ту же последовательность (RNG-5) — покрыто `rng.test.ts`: snapshot()/restore() реестра
