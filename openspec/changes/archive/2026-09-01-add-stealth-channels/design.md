## Context

Мотивация — в proposal.md. Текущее состояние: `Stealth { active: i32 }` — бинарный флаг, который `VisibilitySystem` (`engine/core-ts/src/systems/visibility.ts`) применяет глобальным фильтром `isHidden(candidate)`, не зависящим от наблюдателя; детекции не существует; фильтр снапшота (`sim/filter.ts`) режет по битмаске `Visibility` и о стелсе не знает. Слотовые списки источников уже нормированы (TIME-7) и реализованы одной фабрикой `modifierList()` (`systems/modifiers.ts`) с единственным редьюсером `product` (значение `fixed`, нейтраль `65536`). Контент компонент `Stealth` не использует; используют тестовые фикстуры (`net-ts`, `integration-ts`, `core-ts`) и схемы редактора (`editor/ui-ts/src/areas/objectsSchemas.ts`).

Ограничения: ноль зависимостей и Q16.16 в ядре; ECS-типы полей закрыты (`i32`/`fixed`, ECS-3); закрытые наборы операторов и действий DSL расширяются только правкой спеки (EXPR-6, ACT-1); формат снапшота — функция конфига сцены (SER-7); аллокационная дисциплина тика.

## Goals / Non-Goals

**Goals:**

- Один механизм ядра, покрывающий все виды невидимости данными: каналы, источники, детекция, жёсткость из таблицы сцены.
- DSL-ручки без нового класса механизмов: существующие `addModifier`/`removeModifier` + один новый предикат выражений.
- Формат снапшота меняется один раз и только для сцен с `fog`.

**Non-Goals:**

- Шиммер-шейдер преломления в рендере: спека FOW-13 фиксирует контракт подачи, реализация в этом изменении — плейсхолдер (полупрозрачность/силуэт из presentation-данных).
- Per-entity гранулярность видимости (остаётся per-team, FOW-2) и «размытая» доставка позиции.
- Демо-контент со стелс-способностями (арена не меняется; проверка — фикстуры и тесты).
- Изменения `sim/filter.ts` и netcode-слоя: NET-15 уточняется текстуально, код фильтра по построению не трогается.

## Decisions

**D1. Каналы — битмаска `i32`, а не целочисленные «уровни» и не per-source записи.** Уровни не выражают «эту невидимость видят только избранные» (неупорядоченный кейс); упорядоченная лестница выражается конвенцией битов детекции. Прецедент и аргументация ширины — FOW-2: одно поле, dirty — сравнение двух чисел, детерминизм без сортировок, второй раскладки не заводим. Предел 32 вида невидимости на игру принят осознанно.

**D2. Масочные списки источников — та же фабрика `modifierList()`, параметризованная видом значения.** Фабрика получает опцию (тип значения слота `i32`, нейтраль `0`, свёртка OR — метод `union(ctx, entity)` рядом с `product`), `StealthSources`/`DetectionSources` создаются ею же с той же раскладкой слотов и правилами занятости. Альтернатива — вторая фабрика — отвергнута: дублирует логику занятости слотов/peekField (jscpd, и две реализации одной раскладки — ровно то, что запрещает TIME-7). `addModifier`/`removeModifier` работают без изменений: значение слота и так приходит числом.

**D3. Свёртки публикуются производными компонентами `StealthState`/`DetectionState`, пишет их `VisibilitySystem`.** Пересчёт видимости и так читает источники каждый тик; он же эмитит состояние командой только при изменении (правило FOW-6). Альтернатива «каждый потребитель сворачивает слоты сам» отвергнута: DSL не умеет OR по слотам (и не должен — битовая арифметика в выражениях закрыта), а свёртка в N местах — N определений эффективной маски. Следствие о свежести: потребители, стоящие в тике раньше якоря 900 (способности, NPC), читают состояние прошлого пересчёта — так же, как сегодня читается сама `Visibility`; это детерминированно и документируется, а не чинится.

**D4. Жёсткость каналов — маска, вычисленная загрузчиком из `softStealthChannels`, доставляется системе как зависимость сборки.** Загрузчик кладёт `hardChannelsMask = ~softMask` в объект `Scene` рядом с `modifiers`; сборка передаёт её в конструктор `VisibilitySystem` (система и так регистрируется сборкой из-за raycast, DI-3). В мир и снапшот маска не входит (FOW-12). Альтернатива — компонент-носитель в мире — отвергнута: это состояние, которое пришлось бы снапшотить и защищать от мутаций.

**D5. Скрытость в пересчёте — `(stealthEff & hardMask & ~detectionEff) != 0` на пару наблюдатель-кандидат.** Свёртки считаются один раз на сущность за проход (в ту же временную структуру, где живёт накопитель масок `next`), сравнение пары — две битовые операции; ранний выход «бит команды уже взведён» сохраняется. Аллокационный профиль системы не меняется (та же ponytail-оговорка, что сейчас).

**D6. Предикат выражений — `maskCovered`, возвращающий bool, а не битовые операторы.** Двух предикатов (`bitTest`, `maskCovered`) достаточно всем известным потребителям; оператор, возвращающий маску, открыл бы битовую арифметику в геймплейных выражениях — EXPR-2 это явно запрещает. Регенерация схем (`npm run schemas`) — часть задачи.

**D7. NPC — проверка на платформе через те же компоненты.** Выбор цели/скоринг платформы читает `StealthState` кандидата и `DetectionState` агента опциональными handle (отсутствие компонента = маска 0) и отсекает непокрытых — обе жёсткости, как велит NPC-10. Threat-накопление не трогаем: политика документа.

**D8. Подача — минимальная и из данных.** Парный presentation-документ получает необязательную секцию стелса (непрозрачность своих, непрозрачность чужого невскрытого мягкого; документированные умолчания), демо-рендер применяет её к юнитам с ненулевым доставленным `StealthState`. Шиммер как отдельный шейдер — за пределами изменения; плейсхолдер удовлетворяет FOW-13 («силуэт»). Знание «вскрыт ли канал моей командой» клиент собирает OR-ом `DetectionState` доставленных союзников.

**D9. Порядок компонентов группы `fog` нормируется в FOW-3** (`Vision, Visibility, Team, StealthState, DetectionState, StealthSources, DetectionSources, VisionModifier`): SER-7 отсылает к требованию-владельцу группы, а владелец до сих пор порядок не называл — закрываем пробел заодно, потому что состав группы всё равно меняется (BREAKING для снапшотов fog-сцен).

## Risks / Trade-offs

- [Свежесть `StealthState` для ранних систем тика — прошлый пересчёт] → детерминированно и симметрично сегодняшней `Visibility`; зафиксировано в FOW-3/FOW-5, тест на порядок обязателен.
- [Мягкий стелс чит-прозрачен] → принято и нормировано (FOW-13): преимущество держится на правилах симуляции; каналы с требованием тайны позиции объявляются жёсткими.
- [BREAKING формата снапшота fog-сцен] → контент `Stealth` не использует; фикстуры, схемы редактора, golden и cost-базлайны регенерируются в том же коммите (`npm run schemas`, `npm run golden`, `npm run golden:cost`).
- [Рост стоимости пересчёта: свёртка масок на сущность + сравнение на пару, плюс ~18 новых i32-колонок группы `fog` в клонировании персонального снапшота] → O(слоты) на сущность и две битовые операции на пару при «до 10 наблюдателей» (FOW-4). Гейтом цена НЕ измерена: cost-записи (`match-*`) не объявляют `fog`, и пересчёт на них не исполняется — cost-дифф пуст по построению. Добавление fog-сценария в cost-базлайны (PERF-3/PERF-4) — принятый follow-up, не часть этого изменения.
- [32 канала может не хватить экзотическому дизайну] → принято в D1; расширение — второе поле и правка FOW-2-аргументации, отдельным изменением, если дизайн реально упрётся.

## Migration Plan

1. Ядро: фабрика с `union`, новые компоненты, пересчёт, таблица каналов, `maskCovered`, схема сцены/сценария (`npm run schemas`).
2. Потребители: NPC-платформа, фикстуры тестов (`Stealth { active }` → источник в `StealthSources`), схемы редактора.
3. Регенерация: golden, cost — с диффом в коммите.
4. Презентация: секция стелса presentation-документа + применение в демо-рендере.

Отката как отдельной процедуры нет: изменение атомарно в одном коммите на ветке; откат — revert коммита (формат снапшота вернётся вместе с кодом).

## Open Questions

- Вид маскирующего эффекта чужого мягкого стелса (шейдер преломления против силуэта) — решается работой по рендеру; контракт FOW-13 и секция данных не изменятся.
