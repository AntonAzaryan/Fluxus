## Context

Мотивация — в proposal.md. Состояние на входе:

- Сим-сторона FoW готова и не меняется: `VisibilitySystem`, per-client фильтрация (`engine/core-ts/src/sim/filter.ts`), маска `Visibility` в снапшоте. Демо её не включает: `duel.scene.json` без `fog`, у Hero нет `Vision`, `duel.match.json` без `visibility`.
- Рендер (`engine/render-ts`) — three.js, подсистемы за контрактом REND-8 (`terrain`, `models`, `overlays`, `effects`, `particles`); подсистема владеет своими сценовыми объектами и чужих материалов не трогает. Пост-обработки в конвейере сейчас нет; слой эффектов камеры (CAM-6) — офсеты позы, не пиксели.
- Главный поток получает: `TickView` (сущности доставленного, уже отфильтрованного состояния + статы по именам, HUD-8) и террейн handshake'ом (SHELL-5), включая производные cliff-отрезки (`TerrainGrid.cliffs`, TERR-5).
- Декорации в демо сегодня не рисуются вовсе: `DecorationSet` потребляет только вьюпорт редактора. Парный presentation-документ (`duel.presentation.json`) демо не загружает.
- Рендер живёт во float (REND-1) — вся геометрия маски здесь легально приближённая.

## Goals / Non-Goals

**Goals:**

- Fog-mask в демо: затемнение вне видимости, плавный край, LoS-обрезка по cliff-отрезкам (FOW-7, FOW-9).
- Конфигурация картинки тумана — секция `fog` парного presentation-документа, применяемая в рантайме (FOW-10, PRES-2).
- Fade «ушла в туман ≠ умерла» (FOW-8 — реализация существующего требования).
- Туман на миникарте из той же маски (HUD-6).
- Демо включает FoW: `fog: true`, `Vision` героя в полкарты (24 тайла), `visibility` в конфиге матча; декорации демо рисует (иначе «декорации видны под туманом» показать не на чем).

**Non-Goals:**

- Состояние «неразведано» и его отслеживание (задел в модели конфига, не в коде).
- Динамические укрытия-сущности в LoS-обрезке (FOW-9 MAY).
- Изменения ядра, сим-спеки FOW-1..6, сетевого слоя.
- Дельта/оптимизация доставки — маска строится из уже доставляемого.

## Decisions

**D1. Маска видимости строится на CPU в мировых координатах.** Один grayscale-канвас (разрешение — из конфига FOW-10, покрывает прямоугольник террейна), перестраиваемый на каденсе доставки: для каждого наблюдателя своей команды рисуется reveal-полигон — круг эффективного радиуса, обрезанный 2D shadow-casting'ом по cliff-отрезкам в радиусе, — с радиальным градиентом края. Альтернатива — GPU-маска (шейдер по укрытиям) — отвергнута: наблюдателей ≤ 10, отрезков сотни, канвас 2D тривиально отлаживается, и тот же битмап без изменений потребляет миникарта (D6). Сглаживание между тиками не требуется: ширина градиента и консервативный радиус прячут дискретность каденса. Кромка тени растеризуется с покрытием 2×2 субсэмплов на тексель — бинарный тест по центру давал ступени на диагонали кромки даже под билинейным сэмплом текстуры (FOW-7 «без ступеней»); частичное покрытие затемняет, а не осветляет, так что консервативность FOW-9 сохранена.

**D2. Наложение — полноэкранный пост-проход с реконструкцией мировой позиции.** Сцена рендерится в render target; фог-проход по глубине и inverse view-projection восстанавливает мировые XY фрагмента, сэмплирует маску и затемняет (сила/цвет — из конфига). Альтернативы отвергнуты: ground-плоскость с маской (ломается на перепадах уровней — стены обрывов и возвышенности плоскость не накроет); подмена/патч материалов террейна и моделей (подсистема чужих материалов не касается — тот же принцип изоляции, что у overlays, ED-22); three.js scene fog (дистанционный, не та модель). Пост-проход затемняет всё в туманной зоне — террейн, декорации, стены — а юнитов там нет по построению (NET-12).

**D3. Владелец — новая подсистема `fog` за REND-8.** Ей принадлежат маска, пост-проход и конфиг; вход данных — `syncTick` (наблюдатели из `TickView`) плюс террейн из инициализации, как у подсистемы террейна. Регистрирует её сборка игрового клиента; вьюпорт редактора — нет (превью тумана в редакторе — отдельная будущая работа).

**D4. Наблюдатели и радиусы приезжают статами (HUD-8), новых каналов нет.** В конфиг экстрактора демо добавляются записи `Vision.radius` и команда наблюдателя; подсистема берёт наблюдателей своей команды из `TickView` по именам статов. В демо `VisionModifier` не используется, эффективный радиус = `Vision.radius`; когда модификаторы понадобятся, их слоты — обычные поля компонента, доставляемые тем же механизмом, а свёртка на presentation-стороне повторяет произведение FOW-3 во float — консервативный коэффициент (FOW-9) покрывает дрейф. Team-фильтр обязателен: в отфильтрованном снапшоте есть и видимые враги со своими `Vision` — их круги в маску попадать не должны.

**D5. Конфиг: секция `fog` presentation-документа, читается демо, применяется в рантайме.** Демо начинает загружать парный документ (Vite уже раздаёт дерево контента): `decorations` уходят в `DecorationSet` (закрывает Non-Goal-дыру «декораций в демо нет»), секция `fog` — в подсистему при инициализации и обновлением без пересборки (FOW-10). Валидация состава секции — в валидаторе presentation-документа `engine/assets-ts` (`validatePresentationScene`): это и есть единственная реализация, которую зовут редактор, рантайм и импортёр (ED-30, BLND-5); дефолты документированы у подсистемы. Поля MVP: сила затемнения, цвет, ширина градиента края, коэффициент консервативности, разрешение маски, длительность fade (D7).

**D6. Миникарта затемняет туман тем же битмапом.** Продюсер маски отдаёт стабильный объект «канвас + прямоугольник мира»; сборка демо передаёт его виджету миникарты, тот рисует маску поверх подложки с силой затемнения из того же конфига. Собственного пересчёта у миникарты нет (HUD-6); упрощения (без LoS-точности) допустимы — маска уже общая, так что упрощать нечего.

**D7. Fade — в подсистеме моделей по диффу доставленных сущностей.** Исчезновение сущности из `TickView` без `EntityDied` → fade-out длительностью из конфига, инстанс живёт до конца анимации; появление → короткий fade-in; `EntityDied` → существующий путь смерти. Это реализация FOW-8 без изменения требования.

**D8. Контент демо.** `duel.scene.json`: `fog: true`, компонент `Vision` у Hero, `radius: 1572864` (24 тайла = полкарты 48×48, Q16.16); `duel.match.json`: `visibility: {}` (действующий предикат по умолчанию, NET-13); `duel.presentation.json`: секция `fog` с осмысленными для демо значениями. Числа — контент, спека их не фиксирует.

## Risks / Trade-offs

- [Пост-проход — первый RT-проход в конвейере: стоимость и взаимодействие с picking/зеркалом пола] → picking и floorMirror живут своими проходами и маски не видят; фог-проход включается только при активном тумане, сцена без `fog` рендерится по-старому, ноль изменений.
- [Реконструкция по глубине на краях геометрии даёт артефакты (ореол на стенах обрывов)] → ширина градиента и билинейный сэмпл маски сглаживают; при заметности — консервативный сдвиг сэмпла. MVP-порог: артефакт не должен читаться в игровом масштабе камеры.
- [CPU-перестройка маски каждый доставленный тик] → ≤ 10 наблюдателей, отрезки в радиусе — сотни, разрешение конфигурируемо; при профилировании на реальной сцене — перестройка только при изменении входов (позиции наблюдателей квантованы тиком, сравнение дёшево).
- [Мигание врага на границе радиуса: доставка дискретна, картинка плавная] → консервативный коэффициент (FOW-9) + fade-in/out (D7) превращают мигание в мягкое появление.
- [Бот демо с включённым FoW теряет цель вне обзора (BOT-3 — мозг видит фильтрованное)] → ожидаемое честное поведение, не дефект; если демо-бой станет скучным, радиус или профиль бота — контентная правка.
- [Включение `fog` меняет состав компонентов сцены демо → `contentPackHash`, worldInit-хеш] → golden-наборы движка построены на фикстурах `integration-ts`, не на `content/` (CONT-4), — проверить `npm run check` это подтвердит; клиент и сервер демо читают один контент, рассинхрона версий нет.

## Open Questions

- Тюнинг дефолтов (сила затемнения, ширина градиента, длительность fade) — подбирается на глаз при реализации, спека чисел не фиксирует.
- Нужна ли интерполяция позиций наблюдателей между тиками доставки при быстрой камере — решится визуальной проверкой; механизм D1 её допускает без смены модели.
