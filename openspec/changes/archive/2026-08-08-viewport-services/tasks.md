## 2. Picking (REND-15)

- [x] 2.1 Экранная точка → мировой луч из `CameraPose` и прямоугольника вьюпорта; общая с `applyCameraPose` математика позы, без второго способа её посчитать (CAM-1). Тест — headless, без WebGL-контекста
- [x] 2.2 Пересечение луча с `VisualSurface`: марш по клеткам с уточнением внутри клетки; результат — мировая точка, индекс клетки, признак отсутствия пола. Поверхность берётся текущая (`VisualSurfaceSource.current`), а не захваченная при создании сервиса
- [x] 2.3 Разрешение попадания в вертикальную стенку в клетку верхнего уровня; сверено с геометрией стенок `subsystems/terrain.ts`: стенка тянется до углов ВЕРХНЕЙ клетки, и попадание приходится в неё же. Для этого `VisualSurface` получила `heightInCell` — выборку по ЗАДАННОЙ клетке той же билинейной формой, без второй копии формулы
- [x] 2.4 Объём-прокси инстанса: границы нормализованной модели (ASSET-5) × масштаб записи манифеста и набора; преобразование — то же, каким `ModelsSubsystem` ставит holder (позиция на поверхности либо на высоте уровня, вертикальное смещение, наклон REND-10, курс с поправкой переда REND-13). Взято МАТРИЦЕЙ holder'а, а не повторным расчётом позы
- [x] 2.5 Инстанс без загруженной модели участвует в picking'е объёмом заглушки; сущность, которую рендер не рисует, — не участвует
- [x] 2.6 Порядок разрешения и правило ближайшего; ответ — сущность presentation-состояния, перевод в ключ документа остаётся за `DocumentSource.keyOf` (REND-11) и в picking не переезжает
- [x] 2.7 Никаких аллокаций на кадр в hover-пути: луч, попадание, скретч-матрица и записи прокси переиспользуются, визитор источника создан один раз (дисциплина рендера по образцу `subsystems/models.ts`)
- [x] 2.8 Экспорт из `engine/render-ts/src/index.ts` рядом с остальными сервисами рендера; в ядро, `net-ts` и игровой клиент ничего не добавляется
