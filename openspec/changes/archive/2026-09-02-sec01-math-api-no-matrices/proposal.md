# Math API без матриц: требование перестаёт обещать то, чего в ядре нет и не планируется

## Why

DI-2 говорит: «Math API (fixed-point операции, векторы, **матрицы**) SHALL быть обязательной зависимостью ядра». Матриц в `MathApi` нет ни одной — интерфейс состоит из скаляров (`add`/`sub`/`mul`/`div`/`abs`/`min`/`max`/`clamp`/`sqrt`/`sin`/`cos`) и двумерных векторов, — и появиться им неоткуда: симуляционная геометрия двумерна и состоит из примитивов (DET-8), а матричные преобразования живут в представлении, которое ядру не принадлежит.

Валидация спек против кода (2026-09-01, `docs/reviews/spec-validation-2026-09-01/01-core-math.md`) назвала это расхождением с адресатом: вторая реализация ядра (CORE-2), читающая DI-2 буквально, начнёт с матричного модуля, которого не встретит потом ни в одном эталоне. Слово в требовании — обещание, а не заметка на будущее.

## What Changes

- **DI-2:** состав Math API назван прямо — скаляры формата FP-1 и двумерные векторы; матриц в нём MUST NOT быть, и заделом на них требование считать MUST NOT. Тут же — основание (DET-8) и адресат: второй реализации матричный модуль писать не нужно.
- Новый сценарий «Реализации понадобилась матрица»: нужда в матрице читается как признак, что в симуляцию поехала геометрия представления.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `determinism-core`: DI-2 — состав обязательного Math API и отсутствие матриц в нём.

## Impact

- Кода правка не касается вовсе: `MathApi` в `engine/core-ts/src/types.ts` уже ровно таков, каким его теперь описывает требование.
- Golden- и cost-эталоны не двигаются.
- Требований не прибавляется: правится одно существующее, новых номеров DI не заводится.
