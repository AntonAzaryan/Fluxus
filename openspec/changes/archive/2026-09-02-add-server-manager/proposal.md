# Fluxus Server Manager: агент хоста и приложение управления серверами

## Why

Сегодня выделенный сервер матча — это процесс `demo-serve.mjs`, которым управляют только stdout и Ctrl+C: нельзя со своей машины поднять несколько серверов, увидеть их состояния и игроков, позвать людей на тест без собственного dev-окружения. Одновременно production-путь хостинга (исследование `docs/reviews/2026-08-24-game-server-infra.md`) требует ровно тот же недостающий слой — «тонкий allocator»: control plane, который спавнит process-per-match, наблюдает его и отдаёт адрес. Один механизм закрывает обе задачи и становится швом под будущий матчмейкинг: матчмейкер — ещё один клиент того же управляющего протокола.

## What Changes

- **Агент хоста** (`game/server-agent-ts`, headless-демон): запускает/останавливает процессы серверов матча, держит их реестр со статусами, ловит краши (с сохранением артефактов для постмортема), копит логи и выставляет один управляющий эндпоинт. Работает и на локальной машине разработчика, и на удалённом VPS — один и тот же бинарь и протокол.
- **Управляющий протокол** поверх wss: закрытый набор сообщений с версией в рукопожатии; команды реестра (список, запуск с параметрами, остановка, подписка на детали сервера), админ-операции над матчем и игроками (принудительная отвязка соединения — реконнект NTR-17 разрешён; запирание слота — «removed» с возможностью снятия; пауза и возобновление матча — NTR-20 change'а `add-match-pause`), потоки метрик и логов. Только шифрованный канал: self-signed сертификат агента + TOFU-пиннинг отпечатка у менеджера; аутентификация — пейринг кодом → долгоживущий отзываемый токен.
- **Наблюдаемость сервера для админа**: RTT соединения (наблюдаемая транспорта — ping/pong несущего канала, не сообщение игрового протокола), отклик NTR-11, длительность тика p99, broadcast lag, snapshot bytes/client, event-loop delay и RSS процесса.
- **Запертый слот** (новое требование `netcode-transport`): админ-операция запирает слот ростера — `Hello` владельца получает отказ до снятия запрета; заместитель (NTR-18/BOT-14) продолжает играть по политике стенда. Запирание обратимо.
- **Приложение Fluxus Server Manager** (`game/server-manager-ts`, веб-приложение + третий профиль десктоп-контейнера): список хостов (локальный + добавленные адресом), список серверов со статусами, запуск/остановка, окно деталей сервера (игроки со статусами `connecting/active/disconnected/removed/left/rejected`, пинг/отклик, метрики, хвост лога, действия дисконекта/запирания/возврата), тумблер «остановить серверы при выходе» (умолчание — включён).
- **Отвязываемые сервисы контейнера** (**BREAKING** для `desktop-shell` DSK-7): сервис, объявленный профилем как отвязываемый, переживает закрытие сессии; для прочих действующее правило «сервис умирает с сессией» сохраняется.
- **Host bundle**: упакованный дистрибутив хоста — агент + сборка стенда сервера + собранный клиентский бандл + контент-пак, собранные одной командой (версии `buildId`/`contentPackHash` сходятся по построению, NET-16/NTR-5). Агент раздаёт клиентский бандл и дерево контента по HTTP — тестеру достаточно браузера и ссылки.

## Capabilities

### New Capabilities

- `server-control`: агент хоста — супервизия процессов серверов матча (реестр, статусы, краш-постмортем, логи), управляющий протокол (рукопожатие с версией, команды, потоки событий и метрик), безопасность канала (TLS, пейринг, токены), host bundle и раздача клиентского бандла.
- `server-manager`: приложение управления — хосты, список серверов, окно деталей сервера с игроками и админ-операциями, политика завершения (kill-on-exit), запуск как профиль десктоп-контейнера.

### Modified Capabilities

- `desktop-shell`: DSK-7 — отвязываемый сервис (переживает сессию, объявляется профилем); DSK-5 — профиль Server Manager в перечне профилей приложений.
- `netcode-transport`: NTR-11 — RTT как наблюдаемая несущего канала и админ-метрики сервера (tick p99, broadcast lag, snapshot bytes/client); новое NTR-19 — запертый слот: обратимый админ-запрет реконнекта владельца поверх NTR-17.

## Impact

- Новые пакеты: `game/server-agent-ts` (агент, узел workspace, в гейте `npm run check`), `game/server-manager-ts` (веб-приложение менеджера, в гейте).
- `desktop/shell-ts`: профиль `apps/server-manager.app.json`, отвязываемый сервис в мосте и контрактном сьюте (Electron-клей — вне гейта, DSK-6).
- `engine/net-ts`: RTT в WebSocket-транспорте (ping/pong), API запертого слота в `MatchServer` (не сообщение протокола), новые счётчики метрик хоста.
- `game/demo-ts`: стенду добавляется control-адаптер (stdio JSON-линии до агента) — статусы, метрики, операции; сам матчевый цикл не меняется.
- Сборка: скрипт упаковки host bundle в `game/server-agent-ts`; раздача клиентского бандла — статикой из bundle.
- Тесты: супервизия и протокол агента, пейринг/токены, запертый слот и RTT в net-ts, control-адаптер стенда, контрактный сьют DSK-7.
- Golden-эталоны и симуляция не затрагиваются: ни одно изменение не касается тика.
- Зависимости: реконнект (NTR-17/NTR-18, BOT-14) уже в main — change строится на нём; операции паузы (SRV-5, MGR-3) требуют NTR-20 из параллельного change'а `add-match-pause` — реализуются после него.
