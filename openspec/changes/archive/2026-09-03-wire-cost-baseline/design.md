# Design: wire-cost-baseline

## Context

- **Стенд есть.** `integration-ts/test/fixtures.ts`: `harness()` (LoopbackHub + MatchServer + MatchHost), `connectClient`, `playMatch(ticks, inputs, config)` — детерминированный loopback-матч с генераторами ввода `walkRight`, `fuzzInput`; `matchGolden.test.ts` записывает `match-*` именно им. `MatchHost.report()` отдаёт `HostReport.connections[]` с `snapshotBytes`, `snapshots`, `bytes`, `snapshotsSkipped` по соединению (NTR-11, NTR-22).
- **Кодек детерминирован.** `@msgpack/msgpack` кодирует значение по построению: фиксированные числа — целые, порядок ключей — порядок конструирования `toWireSnapshot`. Ни времени, ни случайности.
- **Состав доставленного** виден на клиенте: `client.latest` — применённый персональный снапшот (число сущностей и событий в нём).
- **Форма документов.** `match-*.cost.json` — секции по стадиям (`tick`, `extract`, пресеты); документ оси — `{ axis, small, large, cost: { small, large } }`.

## Goals / Non-Goals

**Goals:** секция `wire` по слоту на записях; ось `clients` с документом `wire-clients.cost.json`; величины — из `HostReport` и снапшотов, без второго кодека; регенерация `golden:cost`.

**Non-Goals:** не транспорт (WebSocket, backlog — время и ОС, PERF-5 при надобности); не память ПРОЦЕССА сервера (CLI-11); не правка проекции NET-18 и фильтра — если числа покажут лишнее, это отдельный change.

Эталон памяти при этом заводится — `wire-clients.footprint.json` рядом с документом стоимости той же оси. Провод состояния не держит, и своих `*.footprint.json` у него нет; но PERF-8 требует снимать величины «на тех же нагрузках и по тем же осям, что счётчики стоимости», а мир сервера под N соединениями — состояние, и растёт оно вместе с осью: каждый слот приходит со своим героем. Ось стоимости без эталона памяти рядом была бы дырой ровно того размера, который PERF-8 и закрывает.

## Decisions

### D1. Источник величин

`snapshotBytes`, `snapshots` — из `HostReport.connections[i]` после прогона; `entitiesDelivered` — сумма по применённым снапшотам клиента слота (счёт на каждой итерации `playMatch`, где `client.latest` обновился); `eventsDelivered` — факты, доставленные слоту потоком `Events` (NTR-15), считаемые на той же итерации: шина внутри снапшота презентационной поверхностью клиента не отдаётся вовсе (`PresentedState`), а очередь фактов сливает каждый шаг клиентского хоста, и по концу прогона в ней остаётся хвост последнего шага; `eventBytes` — байты сообщений `Events` соединения = `bytes − snapshotBytes` минус хендшейк (если хендшейк не выделяется отчётом — считать `bytesOther` как есть и назвать честно). Утверждение `snapshotsSkipped === 0` — в тесте.

### D2. Записи

`playMatch` вызывается с теми же генераторами и числом тиков, что в `matchGolden.test.ts` (вынести общие определения в `benchLoad.ts`, чтобы стенд записи и стенд провода не разошлись). Секция `wire` в `match-*.cost.json`: `{ "p1": { snapshotBytes, snapshots, entitiesDelivered, eventsDelivered, bytesOther }, "p2": … }`. `extract`/`tick` этих документов не трогаются.

### D3. Ось `clients`

Сцена дуэли С ТУМАНОМ (`fogScene` фикстур) на N героев (`Player.slot` 0..N−1, команды через одну) и N клиентов, одинаковый ввод (`walkRight`), 24 тика; `small` = 2, `large` = 8 (в пределах продуктовых «до 10»). Герои стоят двумя линиями команд, расстояние между линиями больше радиуса обзора: свою команду сущность видит всегда (FOW-3), чужую — не видит ни на одном размере, и фильтр (NET-12) РЕЖЕТ слоту ровно половину героев. Документ `wire-clients.cost.json`: по размеру — сумма по всем слотам и то же по слоту `p1`; L/S суммы читается против L/S = 4.

Туман здесь предмет замера, а не декорация. Записанные матчи набора его не несут вовсе — `duelScene`/`propScene` объявляют сцену без `fog`, — и фильтр на них не вырезает ничего: секции слотов в `match-*.cost.json` совпадают, а сценарий PERF-12 «Фильтр перестал вырезать невидимое» на записях пуст. Перезапись матчей — это правка записанного контента и в этот change не входит; фильтр поэтому стережёт ось, и утверждение «слоту едет не весь мир» — её тест.

## Risks / Trade-offs

- **Вложенность стенда** — `playMatch` асинхронен через `settle()`; `cost.test.ts` синхронен. Тест провода — отдельный `it` с `async`, документ пишется тем же помощником эталона.
- **Хендшейк в байтах** — не снапшот и константен; входит в `bytesOther` с комментарием.
