# Освещение сцены и динамические тени

## Why

Свет сцены сегодня — захардкоженная копипаста приложений: демо (`game/demo-ts/app/main.ts`), вьюпорт редактора (`editor/ui-ts/src/areas/sceneStage.ts`) и портрет HUD держат по своему `AmbientLight` + `DirectionalLight` с одинаковыми числами, а тождество кадров вьюпорта и клиента (`editor` ED-22) выполняется дисциплиной копирования, а не построением. Теней нет вовсе, хотя все материалы движка уже освещаемые (`MeshStandardMaterial`). Дизайнеру нечем настраивать свет и вид теней per-сцену — ни для визуального стиля, ни для оптимизации.

## What Changes

- Новая подсистема рендера — освещение сцены: реестровая подсистема (`REND-8`) в `engine/render-ts`, владеющая источниками света и тенями. Захардкоженный свет демо и вьюпорта редактора уходит; ED-22 начинает выполняться по построению.
- Авторская конфигурация света — данные presentation-слоя: необязательная секция `lighting` парного presentation-документа сцены, по образцу секции `fog` (`presentation-scene` PRES-2 / `fog-of-war` FOW-10). Отсутствие секции — документированные значения по умолчанию, воспроизводящие сегодняшний кадр (тени выключены).
- Режимы теней — авторский выбор сцены с ярусами кастеров:
  - `none` — теней нет (сегодняшний кадр);
  - `hybrid` — статические кастеры (декорации без анимации, стены террейна) рисуются в кэшированную карту теней один раз («запекание» при загрузке сцены и на правку декораций), динамические (юниты, анимированные декорации) — в покадровую карту;
  - `full` — все кастеры в покадровой карте.
  Ярус кастера — производная данных: сущности presentation-состояния всегда динамические, декорация классифицируется по наличию анимации у записи манифеста визуалов. Режим `hybrid` требует статичного глобального света: анимация источников в нём не поддерживается по построению.
- Ручки качества по QUAL-3: как минимум потолок режима теней (`none` < `hybrid` < `full`, действующий = min(авторский, потолок) — семантика ceiling, как `fog.maskResolution`) и потолок разрешения карты теней. Пресеты игры получают значения (`performance` — тени off, `ultra` — сценные значения).
- Стоимость под контролем `performance-budget`: детерминированные счётчики теневых кастеров в стоке стоимости кадра; изменение cost-бейзлайнов принимается явно через `npm run golden:cost`.

## Capabilities

### New Capabilities

Нет: освещение — presentation-механизм рендера, его дом — существующая capability `rendering` (там же живут подсистемы тумана, частиц, наложений), а формат авторских данных — `presentation-scene`.

### Modified Capabilities

- `rendering`: ADDED — требование подсистемы освещения (источники света сцены из данных секции `lighting`, единый свет всех потребителей рендера) и требование режимов теней с ярусами кастеров и ручками качества (QUAL-3).
- `presentation-scene`: MODIFIED PRES-2 — состав документа расширяется необязательной секцией `lighting`; семантику секции нормирует `rendering` (как секцию `fog` нормирует FOW-10). Импорт Blender-сопряжённой сцены секцию не трогает уже по действующему BLND-2 («всякое поле вне пространственного слоя — байт-в-байт») — дельта `blender-pipeline` не нужна.

`render-quality` не меняется: новые ручки — экземпляры уже существующего механизма QUAL-1/QUAL-3, требований он не добавляет.

## Impact

- `engine/render-ts` — новая подсистема освещения (реестр `PresentationStage`, декларация ручек `QualityController`), разбор секции `lighting` с умолчаниями (по образцу `fog/config.ts`), флаги `castShadow`/`receiveShadow` в подсистемах моделей/террейна, корректная глубина теней для батчевого VAT-яруса (custom depth material — иначе тень батча застынет в позе покоя), счётчики кастеров в `cost.ts`.
- `editor/core-ts` — валидация состава секции `lighting` (закрытый состав, адресный отказ на неизвестный ключ) и канонический порядок при сохранении (ED-21/ED-29).
- `game/demo-ts` — снятие захардкоженного света из `main.ts`, `renderer.shadowMap` при сборке рендерера, значения новых ручек в трёх пресетах, прогон `npm run golden:cost` при изменении бейзлайнов.
- `editor/ui-ts` — снятие захардкоженного света из `sceneStage.ts` (вьюпорт получает свет подсистемой; ED-22 — по построению). Авторинг секции в UI редактора — вне объёма, секция правится руками в JSON.
- Портрет HUD (`engine/hud-ts/src/portrait/threeStage.ts`) — вне объёма: отдельная мини-сцена, не арена.
- Экспорт источников света из Blender (`tools/blender-ts`) — вне объёма, отдельное будущее изменение BLND.
