# Design: ужесточение тестового харнесса

## Context

Четыре пакета связаны `file:`-зависимостями, каждый со своим lockfile; общей команды прогона нет. Попарные швы уже покрыты: `net-ts/test/match.test.ts` держит реплей-парность NTR-8 ассертом, `render-ts/test/host.test.ts` гоняет рендер-хост на мини-симуляции ядра, `net-ts/test/boundary.test.ts` проверяет односторонность зависимости. `MatchServer.toScenario()` уже отдаёт документ CLI-2 — запись матча в сценарий существует. `typescript` есть в devDependencies всех пакетов; `Fixed` в ядре — небрендированный `number`, поэтому tsc не отличает Q16.16 от float. Мотивация — см. proposal.md, требования — delta `cli-testing` (CLI-8..CLI-10).

## Goals / Non-Goals

**Goals:**

- Одна команда из `engine/` прогоняет всё: тесты и typecheck всех пакетов, включая новый интеграционный модуль.
- Инварианты CLI-8 проверяются на обычном прогоне тестов без новых зависимостей.
- Вертикаль CLI-9 и golden матчей CLI-10 встраиваются в существующую golden-инфраструктуру, а не рядом с ней.

**Non-Goals:**

- CI — отдельный будущий шаг; он позовёт ту же команду и ничего своего не добавит.
- ESLint / подсветка в редакторе — не добавляет охвата сверх guard-тестов.
- Брендирование `Fixed` — единственное средство от тихого смешения fixed/float в арифметике, но инвазия в ядро несоразмерна этому изменению; кандидат в отдельное предложение.
- Браузерный e2e с WebGL/скриншотами — рендер-хост тестируется в Node на графе сцены three.
- Изменения в поведении симуляции: если guard найдёт нарушение в существующем коде, оно чинится отдельно по CORE-3.

## Decisions

**Workspace-корень — `engine/`, не корень репозитория.** `draft/` — самостоятельный workspace и песочница; смешивать их графы зависимостей незачем. Пакеты остаются как есть, `file:../core-ts` заменяется на workspace-ссылку, lockfile становится один. Альтернатива — скрипт-обёртка поверх четырёх независимых пакетов — отвергнута: `integration-ts` всё равно требует кросс-ссылок, а единый lockfile убирает расползание версий three/ws между пакетами.

**Guard-сканер — AST через TypeScript Compiler API, запускается vitest-тестом.** `typescript` уже в devDependencies, значит ноль новых зависимостей; AST в отличие от regex не срабатывает на комментарии и строки и позволяет точечно различать `Math.min` (разрешён) и `Math.sqrt` (запрещён). Альтернативы: grep-денилист (ложные срабатывания, не отличает контекст), ESLint + typescript-eslint (новый тулинг ради того же охвата), type-aware правило (бессильно без бренда `Fixed`).

**Сканер общий, конфигурация — по пакетам.** Код сканера живёт в `engine/tests/guard/` — той же зоне общей тестовой инфраструктуры, где уже лежат golden-фикстуры (дух CLI-4: инфраструктура вне кода конкретной реализации). Каждый пакет держит в своём `test/` адаптер-тест, объявляющий, какие директории под каким режимом: `core-ts/src` — строгий (DET-2/4/5 целиком), в `net-ts` — чистые циклы (`src/server`, `src/match`, `src/client` без хоста, `src/protocol`); хосты, транспорт, рендер не сканируются. Списки запрещённого/разрешённого — данные в конфиге сканера, их правка видна в диффе (CLI-8). Если кросс-пакетный импорт TS-модуля из `engine/tests/` упрётся в тулинг — fallback: сканер оформляется маленьким dev-only workspace-пакетом.

**Границы и поверхность ядра — три отдельных guard-теста в `core-ts/test/`:** (1) все импорты в `src/` относительные — закрывает физическую досягаемость чужих пакетов через общий `node_modules` после workspace-конверсии; (2) `package.json` ядра не содержит `dependencies`; (3) отсортированный список экспортов `src/index.ts` сверяется с эталонным файлом, обновление — `UPDATE_API=1` по образцу `UPDATE_GOLDEN`.

**`integration-ts` — новый workspace-пакет, тесты только через публичные API.** Зависимости на все четыре пакета. Свои фикстуры матча (loopback-харнесс) собираются заново из публичных поверхностей `net-ts` и `render-ts`, а не импортом из чужих `test/` — это одновременно требование CLI-9 и проверка того, что публичной поверхности достаточно для сборки вертикали. Вертикальный смоук тонкий: содержательные проверки остаются в попарных швах.

**Golden матчей — через существующий адаптер, без нового формата.** Рекордер (скрипт в `integration-ts`) разыгрывает детерминированный матч и seeded-фазз, снимает `toScenario()` и кладёт пары `match-*.scenario.json` / `match-*.golden.json` в `engine/tests/golden/`. Адаптер `core-ts/test/golden.test.ts` подхватывает их автоматически — он перечисляет все `*.scenario.json`; перегенерация — тем же `npm run golden`. Фазз-вводы порождаются от фиксированного seed xorshift-генератором через публичный API ядра, поэтому рекордер воспроизводим и сам.

## Risks / Trade-offs

- [Workspace-конверсия ломает привычные потоки: session-start hook ставит `engine/core-ts`, CLAUDE.md командует из `core-ts/`] → hook и раздел «Commands» обновляются в этом же изменении; критерий приёмки — `npm install && npm test --workspaces` из чистого клона.
- [Hoisting меняет резолв версий (три lockfile сливаются в один)] → полный прогон всех пакетов после конверсии; расхождения версий фиксируются в корневом lockfile осознанно.
- [Ложные срабатывания сканера на легальном коде] → аллоулист точных целочисленных операций требование CLI-8 закрепляет нормативно; сообщение об ошибке указывает файл, строку и путь к конфигу.
- [Кросс-пакетный импорт сканера из `engine/tests/` может не завестись в vitest/tsc без плясок с tsconfig] → fallback описан в Decisions: dev-only workspace-пакет; интерфейс адаптеров от этого не меняется.
- [Golden матчей делает пейсинг сетевого слоя частью побитовых эталонов: рефакторинги пейсинга начнут красить эталоны] → это цель, а не побочный эффект (CLI-10); принятие изменения — существующий явный путь `npm run golden` с диффом эталона на ревью.
- [Фазз в обычном прогоне тестов не должен растягивать цикл агента] → фиксированный бюджет тиков в фикстуре; расширение пространства — отдельными фикстурами, а не удлинением одной.

## Migration Plan

1. Workspace-конверсия + правка hook/CLAUDE.md; все существующие тесты зелёные из `npm test --workspaces`.
2. Guard-тесты (сканер, границы, поверхность): если находят существующие нарушения — фиксируются как известные дефекты (CORE-3) отдельно от этого изменения, guard временно сужается точечным исключением с пометкой в конфиге.
3. `integration-ts`: вертикальный смоук, затем рекордер и первые фикстуры `match-*`, затем фазз.

Откат любого шага — revert коммита; данных и совместимости шаги не затрагивают.

## Open Questions

- Сколько фикстур `match-*` и какой бюджет тиков у фазза — подберётся по фактическому времени прогона; спеки и задачи от этого не зависят.
- Сканировать ли JSON-системы (`dsl`) на float-литералы в выражениях — у evaluator'а свои проверки; решится при написании конфигурации сканера.
