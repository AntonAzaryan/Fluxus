# dsl-cost-axis

## Why

Data-driven слой — один из неснимаемых принципов ядра: системы и геймплей описываются JSON, ядро — универсальный evaluator. Его стоимость считается — счётчик `expressions` сводки тика (`performance-budget` PERF-3) — но меряется ОДНИМ размером: на записанных матчах он равен нескольким сотням за прогон, а на обеих осях стороны симуляции (`npcAgents`, `navAgents`) он ноль — их нагрузки собраны нативными системами. Оси PERF-6 объявлены для физики, навигации и NPC, а у evaluator'а, через который идёт весь контентный геймплей, оси нет: вырастет ли работа JSON-системы линейно числом сущностей, которых она обрабатывает, или квадратично (обход запроса внутри действия на каждую сущность, повторное вычисление выражения на каждый шаг), эталон не показывает — сравнить `expressions` не с чем. PERF-6 это оговаривает буквально: «одним размером её счётчики меряются по решению, а не по умолчанию», и для evaluator'а такого решения никто не принимал.

## What Changes

- **Ось «число сущностей под JSON-системами» (PERF-6, MODIFIED).** Перечень осей стороны тика получает ось `dslEntities`: сцена с фиксированным набором JSON-систем (`data-driven-systems`) — выражения в условиях, действия с командами, запрос с фильтром, эмиссия события — и число сущностей, которые они обрабатывают, как единственная величина оси. Два размера, эталон `dsl-scale.cost.json` и `dsl-scale.footprint.json` той же формы, что `npc-stress`, регенерация тем же `npm run golden:cost`. Ожидаемое — линейный рост `expressions` и `commandsApplied`; отклонение читается отношением L/S.
- **Нагрузка — фикстура движка, не контент (CONT-4).** Сцена строится инлайн в `engine/integration-ts` рядом с `churnScene` и загрузками осей, без чтения `content/`.

Не меняется: ядро, evaluator, счётчики и форма записи `TICK_COST`, существующие эталоны.

### New Capabilities

### Modified Capabilities

- `performance-budget`: MODIFIED PERF-6 — перечень осей стороны тика дополнен осью числа сущностей, обрабатываемых JSON-системами.

Без дельты: `data-driven-systems` (нагрузка использует существующий DSL, требований к нему не добавляется), `game-content` (фикстура остаётся в движке по CONT-4).
