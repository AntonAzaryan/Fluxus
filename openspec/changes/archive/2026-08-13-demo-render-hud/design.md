## Context

Мотивация — proposal.md; нормативные контракты — дельты `rendering` (REND-12, REND-23) и `match-hud` (HUD-6, HUD-8). Текущее состояние:

- `render-ts`: единственная процедурная геометрия — magenta-заглушка ASSET-4; прозрачность только из материалов ассетов; `EntityView.scale` заполняется только документным источником, кодек его не возит; анимации масштаба нет. Дуга прыжка — `model/verticalOffset.ts` + `subsystems/models.ts` (~783-787): добавка дуги не гейтится `isAirborne`, поэтому Dodge/Roll получают полные 0.9 прыжка.
- Плоская форма/кодек (`client-ts/src/codec.ts`, `extractor.ts` в `render-ts`, демо-экстрактор): позиции, kind, motion state/phase, событий hp/кулдаунов/смертей нет. `HudDeliveredState` (`hud-ts/src/delivery.ts`) соответственно тоже.
- Миникарта (`hud-ts/src/minimap/widget.ts`): мировая `+Y` маппится в canvas `y` (растущий вниз) при камере, показывающей `+Y` вверх, — вертикальная инверсия и в отрисовке, и в клике.
- HUD-композиция демо: match-status (пауза/тик), ability-bar (пустой `update`), minimap (bottom-right), portrait (bottom-left, живой 3D). Помощь по управлению — статический `#help` в `index.html`. fps-счётчика нет нигде.

Ограничения: REND-1 (float только внутри рендера, вход — доставленное состояние), REND-2 (разрывы), REND-8 (подсистемы за общим контрактом), SHELL-2..5 (плоская форма, transferable ping-pong без аллокаций, события reliable), HUD-1/HUD-4/HUD-5, ноль знания ядра о визуале.

## Goals / Non-Goals

**Goals**

- Эффект-подсистема (REND-23): сферы с альфой/масштабом, записи манифеста по kind и по событию, «оболочки» от состояния и «вспышки» от событий.
- Дуги по видам движения (REND-12): гейт прыжковой дуги по `Airborne`, отдельная низкая высота для Dodge/Roll, полётная дуга по фазе из плоской формы.
- Статы в доставке (HUD-8): декларативная конфигурация воркера «компонент/поле → имя стата», провоз через кодек, `HudDeliveredState.stats`.
- Виджеты: hp-бар, кд-оверлей (затемнение + секунды), счётчики смертей, рантайм-панель (fps/тик/сущности), флип миникарты, портрет −15%, раскладка (миникарта слева у рантайм-панели, способности снизу по центру в два ряда).
- Демо-манифест и композиция обновлены, чтобы всё было видно уже с текущим контентом (fireball-шарик вместо magenta-заглушки).

**Non-Goals**

- Геймплейные системы (hp, кулдауны, щит, захват) — следующая фаза: здесь механизмы и записи данных, работающие с тем, что доставлено (виджет без стата показывает пустое состояние по HUD-8).
- Никаких изменений симуляции/ядра; golden-эталоны нетронуты.
- Частицы, шейдерные эффекты, пост-процессинг — только процедурные примитивы.
- Иконки способностей как арт — placeholder-глифы допустимы; арт-пайплайн вне охвата.

## Decisions

**D1. Эффекты — отдельная подсистема, два источника: kind-состояние и событие.**
`EffectsSubsystem` (REND-8, `register`): разделяемая `SphereGeometry`, пул `Mesh`-инстансов с per-instance материалом (альфа/цвет/масштаб). Записи манифеста: `effects.byKind[<kind>]` (оболочка: живёт, пока живёт сущность такого kind/состояния; позиция — за сущностью) и `effects.byEvent[<event>]` (вспышка: играет `durationMs` по часам кадра от точки события; HUD-5-семантика «ровно один раз» уже обеспечена reliable-доставкой). Фаза жизни вспышки — по интерполяционным часам главного потока (REND-2/SHELL-7), не по тикам: события не тикают. Разрыв непрерывности сбрасывает вспышки.
Альтернатива «расширить ModelsSubsystem» отвергнута: у эффектов нет модели, ассетов и анимационного графа — отдельный, маленький и заменяемый кусок.

**D2. Дуги: `maneuverArc` рядом с `jumpArc` в манифесте, полётная фаза — новое поле плоской формы.**
`verticalOffset`-параметры записи: `jumpArc` (есть), `maneuverArc` (новое, для Dodge/Roll), опционально `flightArc` (для полётной дуги). В `models.ts` добавка дуги выбирается по виду состояния: `Airborne → jumpArc`, `Dodge/Roll → maneuverArc`, отсутствие параметра — ноль (чинит баг по REND-12). Полётная дуга: `EntityView.flightPhase?` (0..1), заполняется экстрактором воркера (для демо — из `Lifetime` снаряда: пройдено/полное), кодек возит опционально; рендер применяет `4·p·(1−p)·flightArc`. Демо-манифест: `Hero.maneuverArc ≈ 0.25` (существенно ниже 0.9), `Fireball.flightArc` низкий (~0.35).

**D3. Статы: секция экстрактора воркера, плоский словарь на сущность, `stats` в доставке.**
Конфигурация сборки воркера (демо: рядом с `kindByTags`): `stats: [{name, component, field, filter?}]`. Экстрактор читает компоненты через существующий read-only доступ наблюдателя и кладёт в плоскую форму разреженно: `entity → {name → f64}`. Кодек: пары (нормализованный индекс имени из handshake SHELL-5 + значение) — имена едут один раз в рукопожатии, тикоу кадр несёт индексы; аллокационная дисциплина SHELL-3 сохраняется (буфер переиспользуется). `HudDeliveredState.entities[i].stats` + `statNames`. Смерти — тоже стат (счётчик из компонента контента), никакого спец-канала.
Альтернатива «жёсткие поля hp/cd в кодеке» отвергнута прямо HUD-8: имена компонентов — контент, кодек их смысла не знает.

**D4. Флип миникарты — в преобразовании widget'а, обе стороны.**
`py = offsetY + (worldH − y·scale)` (и обратное в `onClick`); floor-клетки тем же преобразованием. Тест: маркер сущности, движущейся к северу экрана, движется вверх по canvas; клик-инверсия совпадает.

**D5. Виджеты — существующий реестр HUD-4, раскладка — данные композиции.**
Новые виджеты `hud-ts`: `hp-bar` (под портретом, бинд на `hp`/`hpMax`), `cooldowns` (два ряда снизу по центру; оверлей — conic-gradient затемнение + число секунд из `оставшиеся тики × tickMs` SHELL-5; без статов — пустое состояние), `deaths` (top-center, по слоту игрока), `runtime` (top-left: fps по rAF-окну главного потока, тик, число доставленных сущностей). Портрет: размер — параметр композиции, −15% в данных демо. `#help` из `index.html` удаляется (управление уезжает в README демо). Композиция демо: minimap → left (за runtime), abilities → bottom-center-2-rows.

## Risks / Trade-offs

- [Разрастание кодека статами ломает буферную дисциплину SHELL-3] → имена в handshake, значения разреженно, замер размера в тесте кодека; статов в демо — единицы.
- [Эффект-оболочка «пока состояние доставляется» требует знать состояние] → для демо оболочка привязана к kind сущности (щит = отдельная сущность контента в след. фазе) либо к бит-полю статов; выбор зафиксирован в записи манифеста, подсистема остаётся данными.
- [fps-счётчик — не presentation-состояние] → он и не едет через границу: главный поток меряет свой rAF; HUD-1 не нарушен (не данные мира).
- [conic-gradient в тестовой среде (jsdom)] → тест проверяет модель оверлея (доля, текст секунд), не пиксели.
- [Флип миникарты может разъехаться с камерой при будущем повороте камеры] → HUD-6 формулирует инвариант через ориентацию основного вида; поворот камеры — вне охвата, инвариант остаётся критерием.

## Migration Plan

Кодек получает новые опциональные секции — сериализация обратно совместима в рамках одной сборки (SHELL-протокол не версионируется между сборками, обе стороны из одного билда). Манифест — новые опциональные поля записей. Golden-эталоны не затрагиваются. Откат — не подключать подсистему эффектов и статы в сборке.
