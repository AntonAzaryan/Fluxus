# Proposal: local-light-sources

## Why

Свет арены — только рассеянный плюс один направленный источник (REND-29): факел на дуэльной арене стоит мёртвой декорацией, кристалл не светится, фаербол не освещает землю под собой. Локальные источники (point/spot) — главный недостающий инструмент художественной выразительности дизайнера сцены, и оба уже стоящих на арене `Torch` ждут его.

## What Changes

- Запись манифеста визуалов — и сущностная (ASSET-6), и decoration-вид (ASSET-9) — получает необязательный блок `light`: тип point/spot, цвет, интенсивность, дистанция, затухание, смещение от опоры инстанса, для spot — угол и полутень. Новое требование ASSET-16.
- Подсистема освещения (REND-29) создаёт и снимает локальные источники вместе с инстансами записи: свет следует трансформу инстанса, одинаково для обоих продюсеров presentation-состояния (REND-11) и для декораций (REND-18). Новое требование REND-33.
- Теней локальные источники в MVP MUST NOT отбрасывать: карты теней остаются направленному источнику (REND-30 не меняется), и полей теней в блоке `light` нет.
- Ручка качества — потолок числа активных локальных источников с детерминированным правилом отбора (QUAL-1, QUAL-3); число активных источников за кадр — детерминированным счётчиком в сток стоимости (PERF-2, PERF-3). Новых требований в `render-quality`/`performance-budget` это не заводит — действуют общие.
- Вьюпорт редактора и демо получают свет по построению из одной подсистемы (ED-22) — без правок своего кода.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `assets`: новый ASSET-16 — блок `light` в записи манифеста визуалов (сущностной и decoration-вида).
- `rendering`: новый REND-33 — локальные источники света инстансов в подсистеме освещения.

## Impact

Пакеты: `engine/assets-ts` (тип и валидация блока `light`), `engine/render-ts` (подсистема освещения — жизненный цикл источников, ручка качества, счётчики; сцепка с подсистемами моделей и декораций). Контент: `content/visuals/manifest.json` — блок `light` у вида `Torch`. Симуляция не затрагивается ни байтом (ASSET-1, PRES-4); golden и cost-бейзлайны — только если счётчик света войдёт в сток стоимости демо-матчей (принимается отдельно, `npm run golden:cost`).

## Notes

**Резервация номеров (сверена 2026-08-22).** ASSET-16: main занят по ASSET-14, ASSET-15 держит стаб `terrain-texturing`. REND-33: main занят по REND-32 (`lighting-time-of-day` синкнут), резерв REND-26 стаба `terrain-texturing` протух (номер занят в main) и будет пересверен его автором. Парный чейндж `bloom-tone-mapping` берёт REND-34: без bloom локальный свет и emissive читаются вполсилы, но ценность самостоятельная — свет от факела виден и без него.
