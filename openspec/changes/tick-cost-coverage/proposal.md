# tick-cost-coverage

## Why

Сводка стоимости тика (`TICK_COST`, `performance-budget` PERF-3) держит шесть счётчиков — применённые команды, вычисленные выражения, кандидаты broad-phase, узлы поиска пути, соседи платформы NPC, лучи, — и все они про физику, навигацию, NPC и DSL. Три платформы ядра, чья работа за тик растёт контентом, в сводке не представлены вовсе: платформа способностей (`abilities` — скан кандидатов таргетинга по запросу к миру, шаги снарядов, проход по инстансам баффов и поиск стакающегося инстанса перебором всех живых), видимость (`fog-of-war` — пары «наблюдатель × цель» и проверки линии видимости) и слой времени (`tween`, `modifiers`). Шина событий, которую платформы дёргают на каждую цель, тоже не считается. Регрессия любой из них — квадратичный поиск хозяина баффа, скан всех сущностей на каждый каст, проверка линии видимости на каждую пару вместо только близких — гейт стоимости (PERF-4) не видит: счётчики не двигаются, а wall-time сторож (PERF-5) краснеет только на порядок. Правило «у платформы свой счётчик, а общий на двоих прячет регрессию одной за шумом другой» сегодня живёт комментарием в `debug.ts`, а не требованием.

## What Changes

- **Счётчики платформ ядра в сводке тика (PERF-3, MODIFIED).** `TICK_COST` получает по счётчику на каждую платформу, чья работа растёт контентом: `abilityCandidates` (кандидаты, осмотренные сканом таргетинга способности), `projectileSteps` (снаряды, продвинутые за тик), `buffSteps` (инстансы баффов, обработанные проходами apply/advance), `buffCandidates` (инстансы, осмотренные поиском стакающегося хозяина), `visibilityPairs` (пары «наблюдатель × цель», проверенные системой видимости), `tweenSteps` (твины, продвинутые за тик), `eventsEmitted` (события, эмитированные в шину). Единицы — те же «осмотренный кандидат» и «исполненный шаг», что у существующих счётчиков; учёт — теми же инертными калитками (без стока — ничего). Требование получает норму, которая сегодня комментарий: у каждой платформы ядра свой счётчик, общий на двоих MUST NOT быть; новая платформа объявляет счётчик или явно объявляет константную стоимость — по образцу `render-quality` QUAL-3.
- **Эталоны стоимости расширяются новыми полями (PERF-4).** Все `*.cost.json` получают новые строки секции `tick`; существующие значения не меняются — счётчики добавляются, а не переопределяются. Регенерация — `npm run golden:cost`, дифф в коммите.

Не меняется: поведение симуляции, поведенческие эталоны, записи матчей, публичная поверхность ядра (CLI-8), закрытый перечень кодов диагностики (`TICK_COST` уже в нём), оси PERF-6 (новые счётчики двигаются существующими осями: `npcAgents` — баффами и видимостью через способности NPC, записанные матчи — таргетингом и снарядами).

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `performance-budget`: MODIFIED PERF-3 — перечень платформ ядра, у каждой из которых свой счётчик в сводке тика; запрет общего счётчика на две платформы; обязанность новой платформы объявить счётчик или константную стоимость.

Без дельты: `diagnostics` (форма записи DIAG-2 и уровень DIAG-3 не меняются, поле в `data` записи — не новый код), `abilities`, `fog-of-war`, `tween` (учёт — измерение, а не обязанность платформы).

## Impact

- `engine/core-ts/src/debug.ts` — семь полей контекста диагностики, семь калиток `countCost*`, семь строк в `recordTickCost`; `src/systems/abilities/runtime.ts` (скан кандидатов), `abilities/projectile.ts`, `abilities/buffs.ts` (проходы и поиск хозяина), `src/systems/visibility.ts`, `src/systems/tween.ts`, `src/ecs/events.ts` — по одному вызову калитки в горячем месте. Тик, детерминизм и публичная поверхность не меняются; чек-лист `determinism-review` обязателен.
- `engine/core-ts/test/tickCost.test.ts` — по тесту на калитку: счётчик двигается ровно на исполненную работу, без стока не исполняется.
- `engine/tests/golden/*.cost.json` — новые поля `tick` во всех документах (записи, `npc-stress`, `nav-path`); `engine/integration-ts/test/cost.test.ts` без правок кода, если секция `tick` собирается из полей записи без перечня.
- Документация: CLAUDE.md (абзац о `*.cost.json`) — одна фраза о составе счётчиков тика.
