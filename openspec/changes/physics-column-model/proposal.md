# Колоночная модель пересечений (physics-column-model)

## Why

Сегодня видимость высоту знает, а пересечения — нет: луч обзора перекрывается обрывом относительно уровня испускателя (PHYS-13), гейт движения сравнивает уровни сторон ребра (PHYS-11), но коллизии, сенсоры и попадания снарядов считаются в чистой 2D-проекции «независимо от уровня участников» (PHYS-1). Снаряд у подножия обрыва попадает в цель на плато, зона у нижнего уровня задевает стоящих на верхнем. Для арен с перепадами высот (модель Dota: плато, рампы, полёт) нужен гейт пересечений по дискретным уровням — колоночная модель, без непрерывной вертикальной координаты и без изменения принципа DET-8.

## What Changes

- Пересечение пары (блокировка PHYS-8, событие `Collision` PHYS-9, `Overlap` PHYS-12) дополнительно гейтуется пересечением высотных полос участников: полоса — отрезок дискретных уровней террейна `[эффективный уровень, эффективный уровень + высота − 1]`, где эффективный уровень — производный по TERR-4 (`levelAt` либо override ARENA-6), а высота — опциональное поле коллайдера в уровнях.
- Поле высоты отсутствует → полоса не ограничена, коллайдер участвует в пересечениях на всех уровнях — поведение сегодняшнего дня. Гейт строго аддитивен: существующие сцены и golden-эталоны не меняются.
- Луч (PHYS-6) с уровнем испускателя (опция из PHYS-13) засчитывает попадание в коллайдер сущности, только если полоса коллайдера содержит уровень луча; луч без уровня пересекает всё — то же консервативное умолчание, что у обрывов в PHYS-13.
- Статика обрывов не меняется: у неё собственные высотные правила (PHYS-11 для движения, PHYS-13 для луча).
- Высоты — политика контента: числа живут в полях коллайдеров сцены, ядро знает только правило пересечения полос (mechanism vs policy).
- Вне скоупа: непрерывная вертикальная координата (запрет PHYS-1 сохраняется), баллистика снарядов, динамические/анимируемые хитбоксы, изменения FoW (PHYS-13 уже покрывает).

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `physics`: PHYS-1 — норма «пересечения считаются независимо от уровня участников» заменяется отсылкой к колоночному гейту; запрет непрерывной вертикали сохраняется. Новое требование PHYS-14 — колоночный гейт пересечений: определение полосы, участие эффективного уровня и поля высоты, применение к блокировке/событиям/сенсорам/лучу, умолчание «без поля — без гейта».

## Impact

- `engine/core-ts`: `systems/collisionGeometry.ts` (гейт полос в narrow-phase), `systems/physics.ts` (эффективный уровень участников, опция луча), схема компонента коллайдера (+ `npm run schemas`). Broad-phase остаётся 2D-сеткой.
- Тесты: `engine/core-ts/test/physics.test.ts` + сценарии PHYS-14; golden-эталоны не перезаписываются (гейт аддитивен), прогон `npm run check` это подтверждает.
- `terrain`, `locomotion`, `arena`, `ability-system` — без правок требований: TERR-4/ARENA-6/LOC-5 уже дают эффективный уровень, ABIL-9 уже запекает уровень в снаряд.
- Контент: существующие сцены работают без изменений; включение гейта — добавление поля высоты в коллайдеры сцены (отдельная работа контента, вне этого изменения).
