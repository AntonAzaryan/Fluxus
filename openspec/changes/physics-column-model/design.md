# Design — physics-column-model

## Context

Мотивация — proposal.md «Why»; нормативное поведение — delta `specs/physics/spec.md` (PHYS-1 MODIFIED, PHYS-14 ADDED). Здесь — только решения реализации в `engine/core-ts`.

Текущее состояние: narrow-phase (`systems/collisionGeometry.ts`) — чистая геометрия без знания об ECS и террейне; разрешение движения, события и сенсоры — `systems/physics.ts`; эффективный уровень сущности уже вычисляется по TERR-4 (`levelAt` + `LevelOverride`) в гейте обрыва и в visibility. Raycast уже несёт опцию уровня испускателя (PHYS-13).

## Goals / Non-Goals

**Goals**

- Гейт полос — в `physics.ts`, рядом с проверкой масок `layer`/`blockMask`/`hitMask`; `collisionGeometry.ts` остаётся свободным от ECS и террейна.
- Ноль изменений поведения при отсутствии поля высоты / значении 0 — существующие golden-эталоны остаются зелёными без перезаписи.
- Аллокационная дисциплина: ни одной новой аллокации на тик.

**Non-Goals**

- Непрерывная вертикаль, баллистика, анимируемые формы хитов — вне скоупа (proposal).
- Изменения visibility/FoW: PHYS-13 покрывает лучи обзора, гейт полос там не участвует.
- Автоматическое проставление высот в существующий контент.

## Decisions

1. **Дискретная полоса уровней, не Q16.16-интервал.** Непрерывный z-band нарушал бы PHYS-1/DET-8 и давил на диапазон fixed-point (квадратичные тесты уже упираются в ~181 единицу). Полоса `[L, L+h−1]` — два целочисленных сравнения на пару. Альтернатива «допуск |ΔL| ≤ k» отвергнута: k — скрытое умолчание ядра, а асимметричные высоты (высокий юнит против низкого снаряда) им невыразимы.

2. **Высота — поле компонента коллайдера, семантика нуля — «без гейта».** SoA-хранилище не умеет «отсутствия поля на сущности»: поле либо есть в схеме на всех, либо нет. Умолчание TypedArray — 0, поэтому 0 обязан значить «неограниченная полоса», иначе объявление поля в схеме молча выключило бы все пересечения сцены. Спека это фиксирует нормативно.

3. **Гейт живёт в `physics.ts`, не в геометрии.** `collisionGeometry.ts` не знает ни ECS, ни террейна — это его граница. Гейт — предикат уровня пары, вычисляемый вызывающей стороной до/рядом с масками; геометрии передаётся уже отфильтрованная пара. Альтернатива (полоса в `Collider`-структуре геометрии) отвергнута: затащила бы TERR-4/ARENA-6 в модуль чистых форм.

4. **Эффективный уровень — один раз за тик, по разрешённому состоянию, в переиспользуемом скретче.** Уровни участников кэшируются в перевыделяемом только при росте сцены массиве (дисциплина аллокаций). Одна оценка на тик — прямо из PHYS-14; она же убирает зависимость от порядка разрешения осей.

5. **Raycast: гейт по коллайдерам сущностей — та же опция уровня, что PHYS-13.** Сигнатура `raycast` не меняется — опция уровня уже существует; добавляется проверка «полоса цели содержит уровень луча» в переборе динамических коллайдеров. Статика обрывов — без изменений (PHYS-11/PHYS-13). Эффективный уровень цели внутри raycast берётся тем же путём TERR-4, что в гейте пар.

6. **Схема компонента — через `npm run schemas`.** Поле высоты попадает в `engine/schemas/*.json` генерацией, не руками.

## Risks / Trade-offs

- [Содержательный риск: рампы] Полосы высоты 1 на смежных уровнях не пересекаются — юниты на границе рампы прошли бы друг сквозь друга. → Это политика контента: боевым юнитам задаётся высота ≥ 2 (сценарий «Контакт на рампе»); правило документируется в контент-гайде сцены, ядро умолчаний не несёт.
- [Перф] +2 сравнения на кандидатную пару после broad-phase и кэш уровней на тик. → Констатный множитель, счётчики `TICK_COST` не зависят от арифметики пары; ожидание — `*.cost.json` без диффа, проверяется прогоном `npm run check` до коммита.
- [Дрейф двух гейтов] Гейт полос (пары) и гейт обрыва (PHYS-11) — разные правила с общим источником уровней. → Общий помощник «эффективный уровень сущности» — единственная точка чтения TERR-4/ARENA-6 в физике; тест на согласованность обоих путей.
- [Rust-порт] Новый нормативный гейт входит в контракт кросс-языковой парности (CORE-2). → Правило укладывается в целочисленные сравнения — переносимо тривиально; сценарии PHYS-14 дают готовые парные тесты.

## Migration Plan

Изменение аддитивно: деплой — обычный merge, существующие сцены и golden-эталоны не трогаются. Откат — удаление чтения поля (гейт исчезает, поведение возвращается к 2D-проекции). Контент включает гейт добавлением поля высоты в схему коллайдера сцены — отдельными правками сцен, вне этого изменения.

## Open Questions

- Имя поля высоты в схеме коллайдера (`height` / `heightLevels`) — решается при реализации по конвенциям существующих полей компонента; на спеку и задачи не влияет.
