# Design — physics-column-model

## Context

Мотивация — proposal.md «Why»; нормативное поведение — delta `specs/physics/spec.md` (PHYS-1 MODIFIED, PHYS-14 ADDED). Здесь — только решения реализации в `engine/core-ts`.

Текущее состояние: narrow-phase (`systems/collisionGeometry.ts`) — чистая геометрия без знания об ECS и террейне; разрешение движения, события и сенсоры — `systems/physics.ts`; эффективный уровень сущности уже вычисляется по TERR-4 (`levelAt` + `LevelOverride`) в гейте обрыва и в visibility. Raycast уже несёт опцию уровня испускателя (PHYS-13).

## Goals / Non-Goals

**Goals**

- Гейт полос — в `physics.ts`, рядом с проверкой масок `layer`/`blockMask`/`hitMask`; `collisionGeometry.ts` остаётся свободным от ECS и террейна.
- Ноль изменений поведения при отсутствии поля высоты / значении 0 — существующие golden-эталоны остаются зелёными без перезаписи.
- Аллокационная дисциплина: ни одной новой аллокации на тик.

**Non-Goals**

- Непрерывная вертикаль, баллистика, анимируемые формы хитов — вне скоупа (proposal).
- Собственных правил для visibility/FoW не вводится: перекрытие обзора обрывами остаётся за PHYS-13, а фильтр высоты кандидата — за FOW-5. Гейт полос при этом луча обзора ДОСТАЁТ, и это не побочный эффект: опция уровня у `raycast` одна, и `VisibilitySystem` передаёт в неё уровень наблюдателя (FOW-5) — тем же полем, что PHYS-13 читает у обрывов. Следствие нормативно (PHYS-14 про луч сказано прямо) и наблюдаемо: укрытие с ограниченной полосой перестаёт перекрывать обзор наблюдателю, чей уровень в полосу не попал. Симметричная мелочь на стороне цели — луч, прошедший сквозь коллайдер цели, может засчитать попадание в то, что за ним, и цель прочтётся перекрытой — из правила выводится, но наблюдаема лишь при коллайдере ровно на позиции цели; отдельного правила ей не нужно.
- Автоматическое проставление высот в существующий контент.

## Decisions

1. **Дискретная полоса уровней, не Q16.16-интервал.** Непрерывный z-band нарушал бы PHYS-1/DET-8 и давил на диапазон fixed-point (квадратичные тесты уже упираются в ~181 единицу). Полоса `[L, L+h−1]` — два целочисленных сравнения на пару. Альтернатива «допуск |ΔL| ≤ k» отвергнута: k — скрытое умолчание ядра, а асимметричные высоты (высокий юнит против низкого снаряда) им невыразимы.

2. **Высота — поле компонента коллайдера, семантика нуля — «без гейта».** SoA-хранилище не умеет «отсутствия поля на сущности»: поле либо есть в схеме на всех, либо нет. Умолчание TypedArray — 0, поэтому 0 обязан значить «неограниченная полоса», иначе объявление поля в схеме молча выключило бы все пересечения сцены. Спека это фиксирует нормативно.

3. **Гейт живёт в `physics.ts`, не в геометрии.** `collisionGeometry.ts` не знает ни ECS, ни террейна — это его граница. Гейт — предикат уровня пары, вычисляемый вызывающей стороной до/рядом с масками; геометрии передаётся уже отфильтрованная пара. Альтернатива (полоса в `Collider`-структуре геометрии) отвергнута: затащила бы TERR-4/ARENA-6 в модуль чистых форм.

4. **Эффективный уровень — в переиспользуемом скретче, и точка оценки у двух сторон пары разная.** Уровни ПРЕПЯТСТВИЙ — одна оценка за тик по состоянию ДО разрешения, в перевыделяемом только при росте сцены массиве (дисциплина аллокаций): оценивать соседа по его уже разрешённой позиции значило бы поставить полосу в зависимость от того, успел ли он пройти разрешение раньше, то есть от порядка обхода. Полоса ДВИЖУЩЕГОСЯ оценивается по состоянию до хода для блокировки (PHYS-8, PHYS-9) — обе оси видят один уровень, промежуточных уровней вдоль пути не возникает — и отдельно по разрешённому состоянию для заметаемого объёма (PHYS-12). Две оценки, а не одна: нормативное «один раз за тик … по разрешённому состоянию» PHYS-14 сказано ровно про проверку заметаемого объёма, а блокировка происходит раньше, чем разрешённое состояние существует. Сквозной снаряд (`blockMask = 0`) платит только вторую.

5. **Raycast: гейт по коллайдерам сущностей — та же опция уровня, что PHYS-13.** Сигнатура `raycast` не меняется — опция уровня уже существует; добавляется проверка «полоса цели содержит уровень луча» в переборе динамических коллайдеров. Статика обрывов — без изменений (PHYS-11/PHYS-13). Эффективный уровень цели внутри raycast берётся тем же путём TERR-4, что в гейте пар.

6. **`PhysicsWorld` выносится в `systems/broadPhase.ts`.** Гейт довёл `physics.ts` до предела `max-lines` (400 строк кода), и делить его надо там, где границу проводит сама спека: broad-phase (PHYS-5) — равномерная сетка по статике, не знающая ни ECS, ни террейна, ни разрешения движения. Перенос дословный, публичная поверхность сохранена реэкспортом из `physics.ts`: адрес физики остаётся один. Правило полос уезжает по той же логике в `systems/columnModel.ts` — оно не знает ни форм, ни свипов.

7. **Поле высоты — содержимое сцены, а не генерируемой схемы.** Компонент коллайдера объявляет СЦЕНА (PHYS-2), а `engine/schemas/component.schema.json` описывает форму объявления — имя и карту «поле → тип» из закрытого набора, — а не список полей коллайдера: имён `hitMask` и `cliffRise` там нет и никогда не было. Поэтому высота живёт в документе сцены, `engine/schemas/*.json` от её появления не меняются, и прогон `npm run schemas` здесь — проверка отсутствия диффа, а не шаг производства артефакта.

8. **Имя поля — `height`.** Зафиксировано константой `COLLIDER_HEIGHT_FIELD` рядом с правилом полос, по конвенции существующих полей компонента (`cliffRise` — тоже целое число уровней). `heightLevels` отвергнут как повтор единицы измерения, уже заданной спекой. Имя вошло в публичную поверхность ядра (`api-surface.golden.json`), поэтому переименование — отдельное изменение, а не правка реализации.

## Risks / Trade-offs

- [Содержательный риск: рампы] Полосы высоты 1 на смежных уровнях не пересекаются — юниты на границе рампы прошли бы друг сквозь друга. → Это политика контента: боевым юнитам задаётся высота ≥ 2 (сценарий «Контакт на рампе»); правило документируется в контент-гайде сцены, ядро умолчаний не несёт.
- [Перф] +2 сравнения на кандидатную пару после broad-phase и кэш уровней на тик. → Констатный множитель, счётчики `TICK_COST` не зависят от арифметики пары; ожидание — `*.cost.json` без диффа, проверяется прогоном `npm run check` до коммита.
- [Дрейф двух гейтов] Гейт полос (пары) и гейт обрыва (PHYS-11) — разные правила с общим источником уровней. → Общий помощник «эффективный уровень сущности» — единственная точка чтения TERR-4/ARENA-6 в физике; тест на согласованность обоих путей.
- [Дрейф ВХОДА помощника] Помощник общий, но запрос террейна к нему приходит по двум дорогам: системе — из контекста тика, лучу — из `PhysicsDeps`. Сборщик, заполнивший зависимости наполовину, развёл бы гейты, не тронув ни строчки правила, — и молча, только на сценах с высотами. → Обязанность зафиксирована на самом поле `PhysicsDeps.terrain` («тот же `TerrainApi`, что уходит на `Simulation.terrain`»), все три сборщика (ядро, демо, превью редактора) заполняют его целиком. Полное устранение — забрать террейн у `createPhysicsApi` так же, как его берёт система, — требует контекста тика, которого у API нет.
- [Rust-порт] Новый нормативный гейт входит в контракт кросс-языковой парности (CORE-2). → Правило укладывается в целочисленные сравнения — переносимо тривиально; сценарии PHYS-14 дают готовые парные тесты.

## Migration Plan

Изменение аддитивно: деплой — обычный merge, существующие сцены и golden-эталоны не трогаются. Откат — удаление чтения поля (гейт исчезает, поведение возвращается к 2D-проекции). Контент включает гейт добавлением поля высоты в схему коллайдера сцены — отдельными правками сцен, вне этого изменения.
