- [x] 2.1 `MatchHostOptions.maxQueuedSnapshots` (умолчание 2, `Infinity` — не пропускать); в `MatchHost.sendOutgoing` персональный `Snapshot` пропускается ДО кодирования, если задолженность соединения ≥ порог × размер последнего ушедшего ему снапшота; первый снапшот и все прочие сообщения уходят всегда; транспорт без наблюдаемой — без пропусков (NTR-22, design D2, D3). Проверка — юнит-тест хоста на подставном транспорте с управляемым `backlog`: пороговая арифметика, первый снапшот, `Events`/`Pause`/`End`, `unsupported`.
- [x] 2.2 `ConnectionMetrics.snapshotsSkipped` и `ConnectionMetrics.backlog` в `HostReport`/`connectionMetrics()`; broadcast lag пропуск не двигает (NTR-11, design D4). Проверка — тест отчёта хоста: пропуски считаются по соединению, у закрытого соединения задолженность — названное отсутствие.
- [x] 2.3 Матч на эмуляторе с узким каналом у одного из двух клиентов (design D6): без политики (`maxQueuedSnapshots: Infinity`) отставание применённого снапшота от серверного тика растёт, с политикой — ограничено, `snapshotsSkipped > 0`, ввод слота применяется; сосед на широком канале — нуль пропусков; канонический лог обоих прогонов совпадает при одинаковом вводе (OBS-2). Проверка — новый тест-файл `backpressure.test.ts` в `engine/net-ts/test`.
