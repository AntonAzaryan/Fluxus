# wire-cost-baseline

## Why

Стоимость считается по стадиям конвейера клиента (`performance-budget` PERF-2): тик, экстракция и канал, приём доставки, кадр. Провод сервера — персональный снапшот каждому соединению, отфильтрованный по видимости (`netcode` NET-12, `netcode-transport` NTR-3), закодированный кодеком (NTR-13) — стадией не объявлен и эталона не имеет. Хост матча уже публикует по соединению байты и число ушедших снапшотов (NTR-11, NTR-22) — как рантайм-метрику для администратора (`server-control` SRV-4), которую в гейте никто не читает. При этом величины детерминированы по построению: фильтр — чистая функция состояния и точки обзора, кодек — чистая функция сообщения, и на записанном матче байты каждого снапшота каждому слоту воспроизводимы побитово на любой машине — ровно контракт PERF-3. Дефекты, которые гейт сегодня не видит: поле, попавшее в проекцию снапшота (NET-18) и удвоившее провод; фильтр, переставший вырезать невидимое (размер снапшота слота растёт до полного мира — это и утечка информации, и байты); работа фильтра, растущая квадратично числом клиентов × сущностей. Первые два ловятся только тестами на конкретные поля, третий — ничем.

## What Changes

- **Стоимость провода (новое PERF-12).** На записанных матчах (CLI-10), прогнанных через тот же loopback-стенд, которым они записаны, эталон стоимости получает секцию `wire` по слоту: байты персональных снапшотов, их число, число сущностей и событий, доставленных слоту (размер выхода фильтра NET-12), байты потока событий. Значения — из отчёта хоста (NTR-11) и из самих снапшотов; машинно-независимы; регенерация — тем же `npm run golden:cost`. Пропущенных снапшотов (NTR-22) на loopback MUST NOT быть — это утверждение теста, не поле эталона.
- **Ось «число клиентов» (PERF-6, MODIFIED).** Ось провода — число соединений одного матча при неизменном мире: та же арена, N героев и N клиентов; два размера, документ `wire-clients.cost.json`. Суммарные байты и суммарная работа фильтра растут числом клиентов; квадратичность «клиенты × сущности» читается отношением L/S суммы, деленной на N.

Не меняется: сервер, фильтр, кодек, протокол (набор сообщений закрыт, NTR-4), рантайм-метрики хоста; поведенческие эталоны и записи матчей; ни одного порога байтов в спеке.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `performance-budget`: ADDED PERF-12 (стоимость провода — детерминированные байты и состав персональных снапшотов по слоту с эталоном на записях), MODIFIED PERF-6 (ось числа клиентов как ось провода).

Без дельты: `netcode-transport` (NTR-11 уже публикует байты и число снапшотов по соединению; PERF-12 читает их, а не добавляет), `netcode` (NET-12, NET-18 нормируют содержимое снапшота; PERF-12 меряет его размер).
