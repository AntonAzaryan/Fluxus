# Tasks: sec02-ecs-dsl-spec-alignment

Требования — `specs/ecs-foundation/spec.md` (**ECS-5**, **QUERY-1**) и `specs/data-driven-systems/spec.md` (**SYS-9**, **EXPR-4**), разбор решений — design.md (D1–D5). Гейт один и он локальный: `npm run check` из корня репозитория (CI нет).

Изменение заводилось по факту сделанной работы: валидация спек против кода (`docs/reviews/spec-validation-2026-09-01/02-ecs-dsl.md`) назвала все четыре расхождения; три чинятся текстом требования, четвёртое (EXPR-4) — текстом требования плюс удалением мёртвого объявления.

## 1. Дельты требований (D1–D5)

- [x] 1.1 `specs/ecs-foundation/spec.md`: MODIFIED ECS-5 — точка контроля названа загрузчиком, схемы названы контрактом и не воротами, полное разделение оставлено за `serialization` SER-5. Новый сценарий «Реализация подключает валидатор схем как ворота загрузки». Блок MODIFIED несёт требование ЦЕЛИКОМ со всеми действующими сценариями: MODIFIED заменяет блок, и опущенный сценарий архивация молча выкинула бы.
- [x] 1.2 Там же: MODIFIED QUERY-1 — обоснование пустого результата у `any` заменено на верное (D3); терпимость запроса и строгость регистрации разведены как два рубежа со ссылкой на SYS-3; дописано следствие для контента. Новые сценарии: «Неизвестный компонент в any», «Система, описанная данными, называет в запросе не объявленный сценой компонент».
- [x] 1.3 `specs/data-driven-systems/spec.md`: MODIFIED SYS-9 — перечень класса 3 пополнен пятью пунктами (физика в общем пункте зависимостей сборки, отрицательный `limit`, непредставимое значение поля, слоты и нулевой id источника, ёмкость мира), добавлено правило пополнения перечня. Новые сценарии: «Луч в сцене, собранной без физики», «Требование вводит ошибку вычисления, не внеся её в перечень».
- [x] 1.4 Там же: MODIFIED EXPR-4 — требование переписано на единственный вход вычисления; заголовок переименован в «Единственный вход вычисления выражения».
- [x] 1.5 Перенести дельты в `openspec/specs/ecs-foundation/spec.md` и `openspec/specs/data-driven-systems/spec.md`. Изменение при этом НЕ архивируется: оно остаётся в очереди как запись о принятом решении. Проверка — `npx openspec validate --specs --strict` и `npm run spec-graph -- check`.
