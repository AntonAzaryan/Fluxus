# entity-fall-system: падение сущности в дыру

## Why

Механизм провала готов и заархивирован (`terrain-holes`): флаг `_` и мутабельная карта пола (TERR-3, TERR-6), критерий опорной области и событие `FellThroughFloor` (ARENA-5), действие `carveFloor` (ACT-1). Самой механики падения — того, ради чего это делалось, — нет: сущность над дырой получает событие, и ничего не происходит. Нужен геймплей: наступил на дыру → падение с анимацией и визуальным снижением → смерть по порогу.

## What Changes

- **Геймплей падения — политика в JSON, а не нативная система.** Заметка архива `terrain-holes` предлагала нативную TS-систему; с тех пор DSL получил всё необходимое (`forEachEvent`, `eventField`, `addComponent`, `destroyEntity`), а `cast-fireball-in-json` и `carve-floor-action` зафиксировали направление: геймплей — в JSON, нативным остаётся только механизм. Пересмотр записан в design.md.
- **Порог падения — в тиках, а не по z-координате.** Непрерывная вертикаль в симуляции запрещена (PHYS-1); длительность в тиках наблюдаемо эквивалентна и уже предложена той же заметкой архива. Число тиков — балансное, живёт в контенте.
- **Смерть — не блокер.** Конвенция смерти уже есть: событие `EntityDied` (NET-14, REND-4, FOW-6) и `destroyEntity`/компонент `Dead` как политика контента (образец — `KillSwitch` сцены дуэли). Падение завершается `emitEvent EntityDied` + `destroyEntity` — отдельной «системы смерти» не требуется.
- Сцена дуэли получает арену (`arena` в конфиге — без неё `ArenaSystem` не регистрируется и `FellThroughFloor` не эмитится), `ArenaState` на prefab'е героя, компонент `Falling { progress, duration }` и две JSON-системы: старт падения по событию и продвижение с гибелью по порогу; движение/каст исключают падающих.
- Рендер: визуальное снижение падающей сущности — extractor читает прогресс падения из компонента, названного конфигом (политика в данных), нормированный прогресс пересекает границу оболочки новой колонкой и опускает инстанс по z в представлении. Анимация падения — существующий маппинг «событие → one-shot клип» манифеста (REND-4), кода не требует.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `rendering`: REND-12 — визуальное снижение падающей сущности из прогресса падения в данных симуляции; сам прогресс в симуляции остаётся счётчиком тиков (PHYS-1), z существует только в представлении.

Симуляционная сторона — чистый контент поверх уже нормированного механизма (ARENA-5, ACT-1, EVT-1..4): дельт `arena`/`terrain`/`data-driven-systems` нет.

## Impact

- `content/scenes/duel.scene.json` — арена, `ArenaState` героя, компонент `Falling`, системы `FallStart`/`FallProgress`, `not: ["Falling"]` в запросах движения/каста. Добавление арены создаёт сущность-носителя до расстановки — ID расставленного сдвигаются, `worldInit` меняется законно (SER-7).
- `content/visuals/manifest.json` — маппинг события `FellThroughFloor` на клип падения.
- `engine/render-ts` — `extractor.ts` (конфиг компонента падения, колонка `fall`), `viewBuffer.ts` (prev/curr прогресс), `types.ts` (`EntityView`), `subsystems/models.ts` (снижение по z, наклон не применяется).
- `engine/client-ts` — `codec.ts` (колонка `fall` в плоской форме через канал оболочки), `demo/worker.ts`/`main.ts` (проводка конфига).
- Тесты: render-ts (extractor/viewBuffer/models), client-ts (codec round-trip), integration-ts (падение над дырой → `EntityDied` на ожидаемом тике, сущность уничтожена — на инлайн-фикстуре, CONT-4).
- Golden: эталоны движка собраны из фикстур, а не из дерева контента (CONT-4) — побитово не меняются; любой дифф — сигнал, что работа задела движок.
