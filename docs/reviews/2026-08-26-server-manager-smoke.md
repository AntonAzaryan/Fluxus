# Ручная проверка Server Manager (задача 7.3 add-server-manager): дистрибутив хоста, пейринг, админ-операции

Дата: 2026-08-26. Машина: Windows 11 Pro, Node v24.19.0, репозиторий на `D:\Fluxus`, профиль пользователя с кириллицей (важно: `%TEMP%` резолвится через короткое 8.3-имя — это вскрыло класс багов). Проверялись коммиты `e49478d` (add-match-pause) и `5dc23ad` (add-server-manager); найденные дефекты исправлены коммитом `8e56b57`, после которого проверка пройдена заново.

## TL;DR

Однокомпьютерная часть 7.3 пройдена полностью и чисто: host bundle собирается одной командой, агент из бандла раздаёт играбельного клиента, join link ведёт на LAN-имя хоста, пейринг и named-отказы работают, все пять админ-операций SRV-5 проверены на живом матче с наблюдением из клиента (включая видимый отсчёт возобновления NTR-20 и named-отказ запертого слота NTR-19). Остаточные пункты — прогон со второй машины и тумблер kill-on-exit через десктоп-профиль — вынесены в конец.

## Найдено и исправлено (8e56b57)

Первый прогон `npm run check` был красным, и все причины оказались портируемостью на Windows, а не дефектами фич:

1. **`npm run host:bundle` падал сразу** — `execFileSync('npm', …)` не находит `npm.cmd` (`spawnSync npm ENOENT`). Сборка клиента переведена на `execSync` с константной строкой; заодно добавлен `--client-dist` (изоляция теста бандла от состояния дерева, SRV-7).
2. **Мост контейнера отвергал каждую операцию ложным DSK-5** на коротких 8.3-путях: корень канонизировался JS-реализацией `realpathSync` (короткие имена не разворачивает), цель — системной (разворачивает), `contains()` не совпадал никогда. Обе стороны переведены на `.native`; попутно граница стала fail-closed с named-причиной на нерешаемых realpath-ошибках. Тот же класс: `fs.watch` на 8.3-пути валил процесс ассертом libuv — канонизация каталога в наблюдателе контейнера и в watch-режиме импортёра (BLND-12).
3. **CRLF-чекаут** (`* text=auto` без `eol=lf`) красил все побайтовые тесты (golden, схемы, cost, записи матчей). Закреплено `eol=lf`.
4. eslint не игнорировал gitignored-артефакт `desktop/shell-ts/build/` (~542 parsing error при его наличии).
5. POSIX-допущения в тестах: `URL.pathname` вместо `fileURLToPath`, `/`-литералы путей, `signal: 'SIGKILL'` (на Windows — `null` + код выхода), впритык выставленные таймауты pause/fuzz под нагрузкой гейта, symlink-фикстуры без привилегии (переведены на junction для каталогов и capability-probe с named-скипами).
6. **UX менеджера**: неудача подключения к хосту из веб-страницы была вечной тишиной — у открытия канала не было дедлайна, а хост не отрисовывался до исхода попытки. Теперь: строка хоста появляется мгновенно со статусом «подключается…», через 10 с — named-отказ; подсказка про самоподписанный сертификат — только на мгновенных отказах (MGR-1, SRV-2).

Итог дважды прошёл ревью независимым агентом (2 раунда, 11 находок, все закрыты — включая мутационную проверку теста уведомлений менеджера).

## Шероховатости среды (не дефекты продукта)

- Встроенный браузер-панель агентской сессии блокирует `ws://` с не-localhost origin — join link с LAN-именем внутри панели не доигрывается, хотя Node-проба к тому же адресу открывается. В обычном Chrome ограничения нет; двухмашинный прогон это закроет.
- SIGINT из Git Bash (MSYS) не доходит до Node-процессов — Ctrl+C стенда стоит перепроверять из обычной консоли.
- В `%TEMP%` могли остаться неудаляемые junction-каталоги от QA-проб (`jt-*`, `loop*`, `probe-*`) — чистятся только elevated-шеллом; том `D:` на этой машине не «локальный» для junction-целей, отсюда и скипы symlink-тестов.

## Остаточные пункты 7.3

1. **Вторая машина**: открыть `joinUrl` из браузера тестера в той же сети; ожидание — страница с `http://<хост>:8088`, матч по `ws://<хост>:<порт>`. Заготовка из tasks.md остаётся в силе: у контейнерного профиля управляющий канал на loopback, раздача на 0.0.0.0, реклама — `os.hostname()`; если имя не резолвится у тестера — добавить агенту `--advertise <LAN-IP>`.
2. **Тумблер kill-on-exit через десктоп-профиль** (MGR-4/MGR-5): в браузере непроверяем по построению (самоподписанный wss), закрыт e2e-тестами пакета; глазами — при первом прогоне контейнера.
