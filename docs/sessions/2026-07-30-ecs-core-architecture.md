# Разгон: Архитектура чистого ECS-ядра и синхронизация с рендером

## Дата
2026-07-30

## Тема / повод
Проектирование переносимого, управляемого данными (data-driven) ECS-ядра для сетевой игры типа Warlocks (Warcraft 3 mod) с возможностью легкой смены рендер-движков и разделением потоков в веб-среде.

## Что обсуждали
*   **Связь ECS-ядра с рендером** — как передавать данные без жесткой привязки к графическому движку. Пришли к одностороннему экспорту через плоские компоненты трансформаций и ссылки на визуальные объекты.
*   **Многопоточность в Web** — выносить ли ядро в Web Worker. Определили, что для сетевого экшена это необходимость, чтобы избежать фризов основного потока и обеспечить быструю перемотку кадров (Rollback).
*   **Общая память через SharedArrayBuffer** — как организовать Pull-модель для рендера и Push-модель для игрового ввода без лишней аллокации памяти.
*   **State-Driven Rendering vs Событийная модель** — как рендер узнает о сиюминутных эффектах (взрывы, анимации) и таймингах.
*   **Слоистая архитектура ядра** — как не переусложнить ECS при сборке геймплейных механик из базовых кубиков. Разделили ядро на атомарный физический слой (Engine) и декларативный слой с тегами (Gameplay).
*   **Тупики и отброшенные идеи:**
    *   *ECS поверх ECS:* Идея делать надстроечное ядро для сборки механик отброшена как избыточная и медленная. Заменена тегами и JSON-конфигами.
    *   *Синхронизация через тяжелые блокировки (Mutex):* Отброшена в пользу двойной буферизации (Double Buffering) внутри SharedArrayBuffer с атомарным переключением указателей.
    *   *Полноценный State-Driven для VFX:* Идея хранить визуальные эффекты в памяти ядра до конца их анимации отброшена. Это раздувает буфер и заставляет ядро знать тайминги графики. Заменена на Fire-and-Forget с флагами смерти.

## К чему пришли
*   **Вывод 1** → Архитектура моста «Ядро-Рендер» строится на модели Fire-and-Forget. Ядро выставляет флаг уничтожения/состояния на один кадр и мгновенно очищает память, а рендер-адаптер сам управляет локальными хвостами анимаций. → *Оформлено как ADR-0001*
*   **Вывод 2** → Ядро изолируется в Web Worker, оперирует только примитивами и разделяет память с Main Thread через SharedArrayBuffer с использованием двойной буферизации и `Atomics`. Ввод передается через `postMessage` (Push), рендер забирает данные сам (Pull). → *Оформлено как ADR-0002*
*   **Вывод 3** → Геймплей проектируется data-driven: базовые системы (движение, коллизии кругов) пишется на основе стандартных ECS-бойлерплейтов (например, модули Flecs) и ничего не знают о геймплее. Конкретные сущности (Варлоки, снаряды) собираются навешиванием базовых кубиков данных и пустых геймплейных компонентов-тегов (`TAG_UNIT`, `TAG_PROJECTILE`). → *Правка в архитектурную спеку ядра*
