# Глоссарий

Словарь терминов спецификации игрового ядра. Единая точка истины для перевода RU↔EN и снятия неоднозначностей. При расхождении с `conventions.md` или `topology.md` — правится глоссарий и/или другой документ, чтобы устранить противоречие.

---

## 1. ECS-модель

| RU | EN | Определение |
|---|---|---|
| Сущность | Entity | Именованный контейнер компонентов, идентифицируемый уникальным `entity_id: u64`. Не содержит данных сама по себе. |
| Идентификатор сущности | Entity ID | Монотонно возрастающий `u64`, выдаётся из `EntityAllocatorState`. Не переиспользуется. `0` = «нет ссылки». |
| Компонент | Component | Структура данных без логики, прикрепляемая к сущности. |
| Система | System | Единица поведения. Чистая функция от компонентов, ресурсов и событий. |
| Архетип | Archetype | Именованный шаблон композиции компонентов + дефолтные значения. Используется при спавне. |
| Ресурс | Resource | Глобальное состояние симуляции в единственном экземпляре, не привязано к сущностям. |
| Выборка | Query | Множество сущностей, отобранных по составу компонентов, для итерации в системе. |
| Компоновка (доступ) | Access (read/write) | Уровень доступа системы к компоненту/ресурсу, декларируется в `requires`/`reads`/`writes`. |
| Позиция | Position | Компонент с координатами (x, y, z) в fixed-point. Мир 2.5D: XY — плоскость, Z — высота. |

## 2. События и ввод

| RU | EN | Определение |
|---|---|---|
| Событие | Event | Сообщение с полями, живёт один тик, передаётся между системами. |
| Команда игрока | PlayerCommand | Событие-вход в симуляцию извне. Обязательные поля: `tick`, `player_id`. |
| Внутреннее событие | Internal event | Событие, порождаемое и потребляемое системами внутри ядра. |
| Исходящая нотификация | Outbound notification | Событие с флагом `outbound: true`, читается слоем презентации, на симуляцию не влияет. |
| Триггер | Trigger | Декларация системы, что она обрабатывает события указанного типа. |
| Буфер ввода | Input buffer | Ресурс, куда складываются `PlayerCommand`-события текущего тика. |

## 3. Время и симуляция

| RU | EN | Определение |
|---|---|---|
| Тик | Tick | Шаг симуляции фиксированной длительности, задаётся `meta.tick_rate`. Всегда целое число тиков за такт. |
| Кадр | Frame | Визуальный кадр рендеринга, вне ядра. Может быть чаще или реже тиков, использует интерполяцию. |
| Расписание | Schedule | Порядок стадий и систем внутри одного тика (`schedule.yaml`). |
| Стадия | Stage | Группа систем в расписании, выполняемых до перехода к следующей стадии. |
| Шаг времени | dt | Длительность одного тика в fixed-point с учётом `time_scale`: `dt = (1 / tick_rate) * time_scale`. |
| Масштаб времени | Time scale | Множитель скорости симуляции. `1.0` — норма, `0` — пауза, `0.5` — slow-mo. |
| Локальный масштаб времени | Local time scale | Компонент `LocalTimeScale`, дающий индивидуальное замедление сущности поверх глобального. |

## 4. Детерминизм и снапшоты

| RU | EN | Определение |
|---|---|---|
| Детерминизм | Determinism | Свойство: один и тот же вход + один и тот же старт → бит-в-бит одинаковый результат на любой платформе. |
| Чистая функция | Pure function | Функция без сайд-эффектов и скрытых зависимостей. Ядро — чистая функция `tick(state, inputs) -> state`. |
| Снапшот | Snapshot | Полный сериализованный дамп состояния ядра (все ECS-данные + ресурсы). |
| Round-trip | Round-trip | Инвариант: `deserialize(serialize(state)) == state` бит-в-бит. |
| Wrapping-арифметика | Wrapping arithmetic | Целочисленная операция, переполнение которой оборачивается по модулю. Разрешена **только** в PCG32. |
| Переполнение | Overflow | Выход результата за диапазон типа. Для fixed-point всегда паника. |

---

## 5. Арифметика

| RU | EN | Определение |
|---|---|---|
| Fixed-point | Fixed-point | Представление вещественных чисел как целых с фиксированным масштабом. В ядре: signed 64-bit, 16 бит дробной части (Q32.16). |
| Q32.16 | Q32.16 | Формат fixed-point: 32 бита целой части, 16 бит дробной, знаковый. |
| SCALE | SCALE | Константа масштаба fixed-point, `65536` (2¹⁶). |
| Truncate toward zero | Truncate toward zero | Округление к нулю (отбрасывание дробной части). Используется в `mul`/`div`. |
| Half-to-even | Half-to-even | Банковское округление: 0.5 → 0, 1.5 → 2, 2.5 → 2. Используется в `round`. |
| LUT | Lookup table | Таблица предвычисленных значений для `sin`/`cos`/`atan2`. Артефакт спеки, коммитится в репозиторий. |

## 6. Случайные числа

| RU | EN | Определение |
|---|---|---|
| ГПСЧ | RNG (PRNG) | Генератор псевдослучайных чисел. В ядре — PCG32. |
| PCG32 | PCG32 | Конкретный алгоритм: pcg-xsh-rr, 64→32, автор M. O'Neill 2014. |
| Seed | Seed | Начальное значение состояния ГПСЧ. |
| Stream | Stream | Второй параметр PCG32, определяющий независимую последовательность (`inc`). |
| Rejection sampling | Rejection sampling | Метод генерации равномерного распределения с отбрасыванием части значений. В ядре ограничен фиксированным числом попыток или запрещён. |

## 7. Сетевые режимы

| RU | EN | Определение |
|---|---|---|
| Lockstep | Lockstep | Режим сети: все клиенты гоняют одинаковую симуляцию по одинаковому вводу всех игроков за тик. |
| Авторитарный сервер | Authoritative server | Режим сети: сервер — истина, клиент предиктивно симулирует и корректируется. |
| Клиентский предикт | Client prediction | Локальное предсказание результата на клиенте до получения ответа сервера. |
| Реконсиляция | Reconciliation | Согласование клиентского состояния с авторитетным: rollback + переигровка. |
| Rollback | Rollback | Откат ядра к более раннему снапшоту с последующей переигровкой тиков. |
| Задержка ввода | Input delay | Число тиков, на которое отложен ввод (в lockstep — для ожидания вводов всех игроков). |

## 8. Слои и границы

| RU | EN | Определение |
|---|---|---|
| Ядро | Core | Детерминированная часть игры: ECS-мир, системы, ресурсы. Чистая функция `tick`. |
| Слой презентации | Presentation layer | Всё вне ядра: рендер, звук, ввод с устройств, интерполяция, UI. |
| Слой транспорта | Transport / netcode layer | Обвязка ядра для сетевого режима: сбор ввода, снапшоты, rollback-контроллер. |
| Интерполяция | Interpolation | Плавный переход визуальных величин между дискретными тиками для рендера. |
| Runtime ECS | ECS runtime | Конкретная реализация ECS-движка на целевом языке (Rust, TS и т.д.). |

## 9. Тесты

| RU | EN | Определение |
|---|---|---|
| Сценарий | Scenario | Data-driven тест: `initial_state` → `actions` → `expected_state`. |
| Тест-вектор | Test vector | Пара «вход → ожидаемый выход» для сверки реализации с контрактом (fixed-point, RNG, математика). |
| Золотой снапшот | Golden snapshot | Эталонное состояние, с которым сверяется результат прогона сценария. |
| Rollback-тест | Rollback test | Сценарий, проверяющий бит-в-бит воспроизводимость после сохранения/восстановления снапшота. |

## 10. Соответствие другим документам

Все термины, используемые в `topology.md`, `conventions.md`, `spec.yaml` и в блоках `logic:` систем, обязаны присутствовать в этом глоссарии. Введение нового термина = правка глоссария в том же коммите.

## 11. Физика и коллизии

| RU | EN | Определение |
|---|---|---|
| 2.5D | 2.5D | Модель мира: XY-геометрия + Z как скаляр высоты. Прыжки и параболы через Z, коллизии считаются в XY с проверкой Z-интервалов. |
| Тело | Body | Сущность с компонентами Position + Collider, участвующая в физике. |
| Статичное тело | StaticBody | Тело, которое не двигается (стены, декор). |
| Динамическое тело | DynamicBody | Тело с массой, реагирующее на скорости и коллизии. |
| Broad-phase | Broad-phase | Быстрое отсечение пар тел, не пересекающихся по грубой оценке. В ядре — uniform grid по XY. |
| Narrow-phase | Narrow-phase | Точная проверка пересечения пары тел. |
| Uniform grid | Uniform grid | Детерминированная пространственная структура: XY-плоскость разбита на клетки фиксированного размера. |
| AABB | AABB | Axis-aligned bounding box, прямоугольник по осям. |
| Слой коллизий | Collision layer | Битовая маска в CollisionLayer, определяет с чем сталкивается тело. |
| Контакт | Contact | Точка пересечения двух тел с нормалью и глубиной проникновения. |

## 12. Внешние провайдеры

| RU | EN | Определение |
|---|---|---|
| Провайдер | Provider | Внешняя реализация стадии тика, соответствующая контракту. |
| Контракт | Contract | Документ в spec/contracts/, описывающий вход/выход и обязательства провайдера. |
| Capabilities | Capabilities | Декларация возможностей провайдера: детерминизм, cross-platform, rollback. |
