# Словарь журнала боя — политика игры

`duel.dictionary.json` — отображение «тип события демо-арены → семантика журнала
боя» (`diagnostics` DIAG-10). Документ ИГРЫ, а не движка и не дерева контента:

- инструмент журнала (`engine/core-ts`, `npm run journal`) не знает ни одного
  игрового события — знание живёт здесь;
- дерево контента (`content/`) едят сцена, матч, манифест и профиль бота;
  словарь журнала не ест никто, кроме отладочного инструмента, и третьим
  чтением дерева из-под `engine/` он становиться не должен (`game-content`
  CONT-4);
- поэтому место у него то же, что у пресетов качества (`app/presets/*.json`) и
  раскладки управления (`app/bindings.json`) — политика игры рядом с игрой.

Формат: `{"events": {"<тип события>": {"kind": "<семантический код>",
"actor": "<поле события>", "target": "<поле события>"}}}`. Роль — ИМЯ ПОЛЯ
события, а не значение: журнал ничего не додумывает, и событие, не назвавшее
источник урона, даёт запись без актора. Поля, не занятые ролями, попадают в
параметры целиком.

Набор семантических кодов принадлежит этому документу и в спеке не нормируется:
это политика игры. Новое событие (бафф, срыв каста, щит) — новая строка ЗДЕСЬ, а
не правка кода; тип, которого в словаре нет, попадает в журнал с неизвестной
семантикой и называется отчётом прогона. Покрытие словаря событиями сцены
стережёт `test/demoJournal.test.ts`.
