# Разгон: Архитектура декларативной спецификации ECS-ядра

## Дата
2026-07-31

## Тема / повод
Проектирование кроссплатформенного детерминированного игрового ядра. Необходимость создания высокоуровневого формата спецификации (DSL), который будет выступать единым источником правды и автоматически транслироваться силами LLM в код для разных платформ (Rust на сервере, TypeScript на клиенте), а также обеспечивать универсальное тестирование.

## Что обсуждали
- **Выбор формата спецификации:** Сравнение JSON и YAML. YAML выбран как основной интерфейс для ручного написания благодаря поддержке многострочного текста без экранирования (удобно для блоков логики) и комментариев. JSON утвержден как промежуточный компилируемый формат для скриптов и API LLM.
- **Разделение плоскостей спецификации:** Четкое разделение на статичную схему данных (компоненты, события на английском языке) и процедурную логику систем (на русском языке для LLM-компилятора).
- **Импорты и связи в ECS:** Как связать системы с данными без привязки к конкретному языку. Пришли к декларации зависимостей через явные блоки `requires` и `emits` с указанием прав доступа (`read`/`write`). Связи между сущностями реализуются строго через детерминированные `EntityID` (u32), а не указатели.
- **Кроссплатформенный детерминизм:** Обсуждали риски рассинхронизации логики (Float-math в V8 vs Native). Закрепили необходимость изоляции систем от I/O, времени и платформенного РНГ, а также потенциальный переход на Fixed-Point Math (`i32`/`fixed32`).
- **Универсальные headless тесты:** Как тестировать код на разных языках одинаково. Пришли к концепции Data-Driven тестирования через независимые JSON-снапшоты состояния (дампы).

## К чему пришли
- **Вывод 1** → Утвержден YAML-формат спецификации с разделением на англоязычную схему данных и русскоязычный псевдокод систем. Разработан базовый шаблон `engine_spec.yaml`.
- **Вывод 2** → Схема данных из спецификации признана пригодной для прямой генерации схем сериализации (Protobuf/FlatBuffers) и JSON-Schema для тестов.
- **Вывод 3** → Архитектура тест-раннера утверждена в виде цепочки: `Загрузка дампа (JSON)` -> `Экшен/Тик` -> `Сравнение нового дампа с эталоном`. Специфичные реализации ECS-движков скрыты за интерфейсом раннера.

## Затронутые якоря
ECS-1, DET-4, DET-5, TST-8

## Открытые вопросы
- [ ] Окончательно зафиксировать полный список базовых типов данных (включая фиксированную точку) для валидатора схемы.
- [ ] Написать системный промпт для LLM-компилятора, гарантирующий точную трансляцию русского псевдокода в идиоматичный `Bevy ECS` (Rust) и `bitecs` (TS).
- [ ] Проверить производительность сериализации/десериализации полного дампа ECS-мира на больших объемах сущностей.
