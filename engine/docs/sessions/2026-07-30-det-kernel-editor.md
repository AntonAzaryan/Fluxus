# Разгон: Архитектура детерминированного ядра и визуального редактора

## Дата
2026-07-30

## Тема / повод
Проектирование архитектуры полностью изолированного детерминированного ECS-ядра для сетевой игры на 10 человек (веб, TypeScript на клиенте, Rust на бэкенде) и создание собственного визуального редактора компонентов и логики на Jetpack Compose Multiplatform.

## Что обсуждали
*   **Связь ядра с сетью и рендером** — ядро изолировано; ввод из сети поступает в Input Queue, сайд-эффекты для рендера и аналитики выгружаются через Output Buffer / Event Queue в конце тика.
*   **Удаление сущностей при смерти** — отброшена идея задерживать удаление юнита на 10 тиков ради анимаций (это засоряет логику систем проверками). Юнит удаляется в ядре мгновенно, рендера сообщает событие `UNIT_DIED` с контекстом, и графика сама доигрывает анимацию.
*   **Data-Driven архитектура** — геймплейная логика и архетипы собираются без хардкода через JSON-конфиги триггеров в стиле Warcraft 3 (Событие -> Условие -> Действие).
*   **Производительность динамических триггеров** — интерпретатор триггеров медленнее чистого кода, но для 10 игроков (200-300 активных сущностей) запаса V8/JIT хватит с головой. Заложена возможность прогрессивной оптимизации (замена триггера из JSON на хардкодную TS-систему без изменения данных).
*   **Визуальный редактор логики** — интерфейс для не-программиста на Compose Multiplatform будет строиться на древовидных выпадающих списках (Конструктор Выражений / Expression Tree) для генерации математических формул и связей, экспортируемых в JSON.
*   **Кросс-платформенный детерминизм (TS vs Rust)** — стандартный Float гарантированно рассинхронизирует симуляцию. Опция поиска готовых синхронизированных библиотек отброшена как слишком сложная и ненадежная.

## К чему пришли
*   Синхронизация математики через фиксированную точку (Fixed-Point `Q16.16`) → оформлено решение написать свой ультра-легковесный идентичный микро-класс на TS и Rust на базе целочисленных битовых сдвигов. Полиномы (Безье, параболы траекторий) и LUT-таблицы тригонометрии собираются на его основе.
*   Для сквозного тестирования детерминизма создается CLI-контракт → ядра на TS и Rust запускаются в CLI через тест-раннер, который скармливает им JSON-тест-векторы и сравнивает хэш бинарного стейта / JSON-дампы.
*   Ядро на TypeScript собирается из готовых библиотек → `bitECS` как производительный менеджер сущностей на ArrayBuffers и `json-logic-js` (или `expr-eval`) для вычисления динамических условий и формул из JSON.
