# Демо-арена

Демо воркер-сборки клиента (`client-shell` SHELL-1..8): симуляция идёт в
воркере, главный поток рисует доставленное состояние и шлёт ввод.

```sh
npm run dev -w @game-mvp/client       # dev-сервер vite
npm run demo:build -w @game-mvp/client
```

Режим страницы выбирается один раз, при старте (SHELL-8):

| адрес | что поднимается |
| --- | --- |
| `/` | матч против бота на сетевом стеке: сервер вкладки плюс тонкий клиент |
| `/?server=ws://…` | тот же тонкий клиент против выделенного стенда |
| `/?solo` | одиночная симуляция в воркере — с паузой и отладочной перемоткой |

## Арена

Контент арены — `content/scenes/duel.scene.json`: сетка 48×48 по клетке,
играбельный пол — диск радиуса 22 вокруг центра `(24, 24)`, клетки вне его
без пола (`_`), и шаг за кромку — провал в пустоту. По квадрантам стоят четыре
плато уровней 2 (СЗ), 3 (СВ), 4 (ЮЗ) и 5 (ЮВ); к каждому ведёт рампа шириной
четыре клетки со стороны центра — подъёмы оспариваются из середины. В коридор
рампы входят только с земляной клетки в его же колонке: сбоку к земле примыкает
лишь нижняя полоса, все остальные отделены от неё обрывами в два уровня и выше,
и подойти к плато «наискосок» не выйдет. Герои матча спавнятся симметрично:
`p1` в `(8,5; 24,5)`, `p2` в `(39,5; 24,5)`.

## Управление

| клавиши | действие |
| --- | --- |
| `WASD` / стрелки | движение героя |
| `Shift` | уклон; дважды подряд — перекат (`locomotion` LOC-3, LOC-4) |
| `Space` | прыжок |
| `ЛКМ` | фаербол в точку клика; взрыв выбивает пол, шаг в дыру — смерть |
| `F` | купол замедления: чужие снаряды внутри летят вчетверо медленнее |
| `R` | захват снаряда: удержание показывает зону, отпускание ловит |
| `K` | смерть героя (отладка) |
| `T` | сменить скин steel/ember (`rendering` REND-6) |
| `C` | центрировать камеру на герое; удержание — держать в центре |
| `Y` | режим слежения (follow) |
| `V` | режим облёта: `WASD` двигают камеру, `QE` — вверх/вниз, `ПКМ` — осмотр |
| стрелки, край экрана, `СКМ`, колесо | панорама и зум камеры (`camera` CAM-1..3) |

Тач и геймпад работают по тем же биндингам — раскладка устройств лежит в
`bindings.json` (`input-devices` INP-4), а смысл битов кнопок — в `sim.ts`
(`ACTION_BITS`), то есть в контенте демо, а не в движке.

## Способности

Обе живут в JSON-системах сцены; все числа — поля компонента `AbilityConfig`
prefab'а `Hero`, то есть балансная политика, а не код (mechanism vs policy).

**Купол замедления** (`F`, перезарядка 10 с, живёт 2 с). Ставится на месте
героя радиусом 3,5 радиуса его коллайдера. Каждый тик системы `DomeSlow`
снимают свой источник со всех снарядов и ставят его заново тем, кто внутри и
принадлежит НЕ владельцу купола (`time` TIME-8): множитель 0,25 сводится
`TimeScaleSystem`, а шаг снаряду умножает физика (TIME-3) — сама скорость в
компоненте не трогается, поэтому выход из купола восстанавливает полёт точно.
Свои снаряды купол не замедляет — на этом и держится связка с захватом.

**Захват снаряда** (`R`, перезарядка 2 с). Пока клавиша зажата, главный поток
рисует сектор зоны под курсором — это чистое presentation (кадр идёт чаще
тика), и симуляция о превью не знает. На ОТПУСКАНИИ (falling edge, INP-2)
система `CaptureRelease` берёт первый чужой снаряд, попавший и в радиус зоны, и
в её раствор вокруг `aimDir` того тика. Пойманный снаряд замирает у держателя,
обычный каст на это время заблокирован, а манёвры — селективным локом
`ActionLock` (`locomotion` LOC-7); ходьба остаётся. Бросок — ЛКМ тем же
прицелом: снаряд уходит по `aimDir`, и ЕГО ВЛАДЕЛЕЦ СТАНОВИТСЯ БРОСИВШИМ,
поэтому свой купол его больше не замедляет, а купол прежнего хозяина — да.
Не выброшенный за 400 мс снаряд взрывается в руках и снимает держателю 250 hp
общим путём урона сцены (`Damage` → `DamageApply` → `HealthDeath`).

## Что видно на экране

HUD собран из виджетов пакета `@game-mvp/hud` по значению композиции
(`hud.ts`, `match-hud` HUD-4): рантайм-панель и статус матча слева сверху,
счётчики смертей сверху по центру, миникарта слева, портрет героя с полосой
здоровья слева снизу, способности с оверлеем перезарядки снизу по центру.

Полоса здоровья, счётчики смертей и оверлеи перезарядки читают ДОСТАВЛЕННЫЕ
статы (HUD-8). Здоровье и перезарядки купола и захвата в сцене есть и едут
значениями; счётчика смертей в ней по-прежнему нет, и его виджет показывает
пустое состояние — прочерк вместо выдуманного нуля; это ожидаемое поведение, а
не поломка. Кнопки `cast`, `dodge` и `jump` держат нулевой предел перезарядки —
они всегда готовы, и оверлей на них не появляется.
