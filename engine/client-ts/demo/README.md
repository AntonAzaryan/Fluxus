# Демо-арена

Демо воркер-сборки клиента (`client-shell` SHELL-1..8): симуляция идёт в
воркере, главный поток рисует доставленное состояние и шлёт ввод.

```sh
npm run dev -w @game-mvp/client       # dev-сервер vite
npm run demo:build -w @game-mvp/client
```

Режим страницы выбирается один раз, при старте (SHELL-8):

| адрес | что поднимается |
| --- | --- |
| `/` | матч против бота на сетевом стеке: сервер вкладки плюс тонкий клиент |
| `/?server=ws://…` | тот же тонкий клиент против выделенного стенда |
| `/?solo` | одиночная симуляция в воркере — с паузой и отладочной перемоткой |

## Управление

| клавиши | действие |
| --- | --- |
| `WASD` / стрелки | движение героя |
| `Shift` | уклон; дважды подряд — перекат (`locomotion` LOC-3, LOC-4) |
| `Space` | прыжок |
| `ЛКМ` | фаербол в точку клика; взрыв выбивает пол, шаг в дыру — смерть |
| `K` | смерть героя (отладка) |
| `T` | сменить скин steel/ember (`rendering` REND-6) |
| `C` | центрировать камеру на герое; удержание — держать в центре |
| `Y` | режим слежения (follow) |
| `F` | режим облёта: `WASD` двигают камеру, `QE` — вверх/вниз, `ПКМ` — осмотр |
| стрелки, край экрана, `СКМ`, колесо | панорама и зум камеры (`camera` CAM-1..3) |

Тач и геймпад работают по тем же биндингам — раскладка устройств лежит в
`bindings.json` (`input-devices` INP-4), а смысл битов кнопок — в `sim.ts`
(`ACTION_BITS`), то есть в контенте демо, а не в движке.

## Что видно на экране

HUD собран из виджетов пакета `@game-mvp/hud` по значению композиции
(`hud.ts`, `match-hud` HUD-4): рантайм-панель и статус матча слева сверху,
счётчики смертей сверху по центру, миникарта слева, портрет героя с полосой
здоровья слева снизу, способности с оверлеем перезарядки снизу по центру.

Полоса здоровья, счётчики смертей и оверлеи перезарядки читают ДОСТАВЛЕННЫЕ
статы (HUD-8). Пока геймплейные системы их не эмитят, виджеты показывают
пустое состояние — прочерк вместо выдуманного нуля; это ожидаемое поведение,
а не поломка.
