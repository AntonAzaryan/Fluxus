## Why

В спеке нет капабилити террейна. Арена как физическая сущность не описана нигде: ни формы, ни высот, ни пола. При этом `PHYS-1` уже вынес решение по высоте — «высота — вопрос рендера, а не симуляции» — и это решение закрывает многоуровневость (high ground, обрывы, разрушаемый пол) до того, как она обсуждалась.

Многоуровневость по образцу Warcraft III / Dota нужна как механизм движка: обрывы дают укрытия и разрывы LoS, разница высот даёт информационное преимущество, дыры в полу дают способ отсечь или столкнуть противника. Механизм проектируется сейчас, потому что от выбора представления зависят Physics, FoW, будущая навигация для NPC и формат данных редактора — переделывать после реализации дороже, чем описать до.

## What Changes

- Новая капабилити `terrain`: модель арены как height field — карта дискретных уровней + карта пола, размер клетки как параметр ассета, запрос `levelAt`, генерация cliff-геометрии.
- Фиксируется **необратимое** решение: уровень есть функция от 2D-позиции (height field), а не множество (multi-layer). Мосты выражаются как локальный патч того же height field по образцу WC3; тоннели и этажи — вне области определения модели навсегда.
- Разделение по мутабельности: карта уровней иммутабельна и живёт вне снапшота, карта пола мутабельна и живёт в снапшоте. Разрушаемость ограничена полом — рельеф не мутирует.
- **BREAKING** (для формулировки требования, не для кода — реализации ядра ещё нет): `PHYS-1` переписывается. Было «высота — вопрос рендера»; станет «в симуляции — дискретный целочисленный уровень, в рендере — непрерывная координата». 2D-проекция для снарядов и коллизий сохраняется.
- `FOW-5` получает третий фильтр видимости: наблюдатель не видит цель на уровне выше своего.
- **BREAKING** (там же): `DET-1` определяет детерминизм через пару `(seed, inputs[])`. Начального состояния мира в этой паре нет — ни террейна, ни стартовой расстановки сущностей. Пара становится тройкой `(worldInit, seed, inputs[])`.
- В `determinism-core` вводится сквозной принцип: симуляционная геометрия — грубая, рукотворная, 2D; геометрия рендера в симуляцию не попадает и из неё не выводится. Из принципа следуют `PHYS-1`, cliff-коллайдеры, WC3-подход к мостам и будущие укрытия — вместо того чтобы обсуждать каждый случай заново.
- Редактор получает требование на редактирование террейна: кисти уровня и рампы, кисть пола.

Явно вне границ:

- Границы арены, «выталкивание за край = килл», сужение арены — отдельный change; механизм «клетка без пола» здесь вводится, политика падения — нет.
- Navigation API и pathfinding для крипов/NPC — не вводятся. Здесь фиксируются только ограничения формата, которые делают их вставимыми позже без переделки.
- Разрушаемость рельефа (мутация уровней) — отклоняется, цена отката описывается в `design.md`.
- Разделение сеток уровня и проходимости на разные разрешения (как в WC3: рельеф крупнее, проходимость мельче) — не вводится. Сетка одна.

## Capabilities

### New Capabilities

- `terrain`: height-field-модель арены — карта уровней, карта пола, `levelAt`, cliff-геометрия как производные данные, ограничения формата под будущую навигацию.

### Modified Capabilities

- `physics`: `PHYS-1` — дискретный уровень в симуляции вместо «высота только в рендере».
- `fog-of-war`: `FOW-5` — фильтр видимости по разнице уровней.
- `determinism-core`: `DET-1` — начальное состояние мира вносится в определение детерминизма; `DET-8` — принцип грубой симуляционной геометрии.
- `editor`: `ED-10` — редактирование террейна.

## Impact

- Спеки: новая `openspec/specs/terrain/spec.md`; правки `physics`, `fog-of-war`, `determinism-core`, `editor`.
- `snapshot-rewind` и `serialization`: карта пола становится снапшотящимся ресурсом; требования не меняются, но реализация обязана учесть новый мутабельный ресурс с dirty-дельтой.
- `netcode`: карта уровней передаётся один раз при подключении, карта пола — в общем потоке снапшота.
- `ecs-foundation`: `withinRadius` остаётся 2D-запросом; фильтрация по уровню выполняется вызывающей стороной, изменений в Query API нет.
- Roadmap в `docs/architecture.md`: террейн — новый этап, и он предшествует Physics (этап 13) и FoW (этап 16). Порядок этапов правится отдельно от этого change.
- Кода нет — изменение затрагивает только нормативные документы.
