## Why

CLI ядра не запускается. На Node v22.22.2 команда `npm run sim` падает ещё до первого тика:

```
SyntaxError [ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX]: TypeScript parameter property
is not supported in strip-only mode
    at engine/core-ts/src/systems/visibility.ts:131
```

`CLI-1` требует, чтобы сценарий прогонялся через CLI без рендера и сети — именно для того, чтобы воспроизвести баг из матча. Сейчас через CLI не прогоняется ни один из десяти golden-сценариев: падение происходит на загрузке модуля, до разбора аргументов.

Причина — в том, как ядро исполняется. Шага сборки нет сознательно (`bin/sim.mjs`): типы стрипает сам Node (>=22.18), а хук резолва чинит единственное, чего тому не хватает (`./x.js` → `./x.ts`). Но strip-only режим только **удаляет** типы и ничего не порождает, а parameter property (`constructor(private readonly modifiers: ModifierList)`) — это сахар, разворачивающийся в присваивание поля. Node такой синтаксис отвергает. В `src/` таких мест два: `VisibilitySystem` и `TimeScaleSystem`, обе объявляли `modifiers` через параметр конструктора.

Дефект прожил незамеченным, потому что весь набор тестов зелёный: vitest грузит `src/` собственным трансформом, который умеет весь TypeScript. Ни один тест не запускал `bin/sim.mjs` тем способом, которым его запускает человек, — отдельным процессом Node. Дефект существует независимо от работы над сетевым слоем; в `netcode-transport-mvp` он записан пунктом 11.5.

## What Changes

- `src/systems/visibility.ts`, `src/systems/time.ts`: parameter property заменяется явным объявлением поля плюс присваиванием в конструкторе. Правка чисто синтаксическая — тот же класс, те же поля, то же поведение.
- Новый `test/cli.test.ts`: `bin/sim.mjs` запускается подпроцессом штатным `node` (с погашенным `NODE_OPTIONS`), вывод разбирается как JSON, `worldInitHash` сверяется с эталоном, stdout сверяется побайтно, stderr обязан быть пуст. Без такого теста дефект вернётся с первым же новым parameter property, снова при зелёном наборе.
- `bin/sim.mjs`: в шапке фиксируется цена решения «без сборки» — ограничение на `src/` (ни parameter properties, ни enum, ни namespace) и почему выбран не флаг.
- `net-ts`: флаг `--experimental-transform-types` снимается из `package.json` и обоих shebang'ов (`bin/serve.mjs`, `bin/play.mjs`). Он был там вынужденно — `net-ts` импортирует ядро целиком и тащил его parameter properties. После правки ядра ни в `core-ts/src/`, ни в `net-ts/src/` не остаётся ни одной конструкции, не поддержанной strip-only режимом.

## Почему без правки спек

Норма `CLI-1` не меняется: она уже требует прогона сценария через CLI, и именно это требование нарушено. Дефект — в реализации, что прямо следует из `CORE-3` (`openspec/config.yaml`: «при расхождении реализации и спеки дефект — в реализации, а не в спеке»). Change фиксирует возврат реализации к норме.

Соблазн есть — дописать в `CLI-1` сценарий «CLI запускается штатным Node без экспериментальных флагов», чтобы ограничение стало нормативным, а не фольклором в комментарии. Отвергнуто: спеки этого репозитория намеренно не привязаны к реализации — `CLI-4` требует **один** набор проверок для всех реализаций ядра, а в планах вторая на Rust. Требование про флаги Node для Rust-ядра бессмысленно и засорило бы общую спеку деталью TS-тулинга. Ограничение живёт там, где действует: комментарий в `bin/sim.mjs` (почему) и `test/cli.test.ts` (проверка).

Поэтому `skip_specs: true` в `.openspec.yaml`.

## Impact

- Код: `engine/core-ts/src/systems/visibility.ts`, `engine/core-ts/src/systems/time.ts` (синтаксис), `engine/core-ts/bin/sim.mjs` (комментарий).
- Код: `engine/net-ts/package.json`, `engine/net-ts/bin/serve.mjs`, `engine/net-ts/bin/play.mjs` — снятие флага.
- Тесты: новый `engine/core-ts/test/cli.test.ts` (+4 теста; 403 → 407).
- Эталоны: **не трогаются**. Правка синтаксическая, вывод обязан совпасть побайтно — это и проверяется прогоном всех десяти сценариев через CLI.
- Спеки: не трогаются.
- Пересечение с `netcode-transport-mvp`: только пункт 11.5 его `tasks.md`, который закрывается этим change'ем. Файлы не пересекаются.
