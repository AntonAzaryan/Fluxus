## Why

Веб-клиенту нужна изоляция каденса симуляции от кадра: GC-паузы и тяжёлые кадры Three.js не должны сбивать тикер ядра и отправку ввода, а фоновая вкладка — убивать сетевой клиент (таймеры воркеров троттлятся мягче main thread). Сегодня `RenderHost` читает `WorldState` синхронно в одном потоке с рендером — топология «ядро в воркере, рендер в main» не описана ни одной спекой, хотя шов под неё уже существует: presentation-копия `TickView`, обязательная по OBS-3.

## What Changes

- Новая capability `client-shell`: клиентская оболочка веб-игры — ядро (симуляция, tick loop, `HistoryProvider`, сетевой клиент) в dedicated Worker, рендер и ввод в главном потоке.
- `RenderHost` разбивается по границе `TickView` на две части: **Extractor** (воркер, реализует `TickObserver`, единственный читатель `WorldState`, точка конверсии Q16.16 → float) и **ViewBuffer** (main, prev/curr-скольжение, snap-логика, альфа интерполяции). Подсистемы рендера (`RenderSubsystem`) не меняются.
- Канал состояния воркер → main: transferable ping-pong — пул заранее выделенных `ArrayBuffer` с плоской SoA-раскладкой, передача через transfer, возврат буфера воркеру; ноль аллокаций в устоявшемся режиме. Без `SharedArrayBuffer` — деплой не требует COOP/COEP.
- Семантика доставки раздвоена: состояние conflatable (рендеру нужен только последний тик), события reliable (аккумулируются между доставками, теряться не могут).
- Обратный канал main → worker: ввод и команды машины состояний мира (pause/rewind/seek/resume) обычными сообщениями; ввод применяется на границе тика.
- Handshake один раз до первого кадра: конфиг сцены, terrain grid, таблица визуальных kind'ов, `tickSeconds`.

Ядро (`core-ts`) не меняется: граница воркера лежит целиком снаружи `tick()`. Требования `rendering` (REND-1..8) не меняются: наблюдатель остаётся наблюдателем, точка конверсии — одна, подсистемы — за тем же контрактом.

## Capabilities

### New Capabilities

- `client-shell`: топология клиента (ядро в воркере, рендер в main), разбиение по presentation-границе, протокол канала (transferable ping-pong, conflatable-состояние против reliable-событий), handshake, обратный канал ввода и управления, независимость каденса симуляции от кадра.

### Modified Capabilities

Нет: поведение `rendering`, `tick-loop` и `netcode-transport` на уровне требований не меняется — новая capability только размещает существующие контракты по потокам и задаёт канал между ними.

## Impact

- `engine/render-ts`: `RenderHost` распадается на Extractor и ViewBuffer; `TickView` получает плоскую сериализуемую форму; подсистемы не трогаются.
- Новый пакет `engine/client-ts` (`@game-mvp/client`): воркер-хост (тикер, канал, handshake), main-обвязка (приём буферов, возврат в пул, ввод), реализация `Transport` поверх `MessageChannel` для локального сервера во втором воркере.
- `engine/net-ts`: без изменений кода; WebSocket-клиент начинает жить в воркере как потребитель.
- `engine/core-ts`: без изменений.
- Демо `render-ts/demo` переезжает на новую оболочку (или добавляется параллельное демо в `client-ts`).
