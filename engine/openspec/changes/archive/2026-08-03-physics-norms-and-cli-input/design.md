## Context

`physics/spec.md` содержит задвоенный номер PHYS-7 (два разных требования под одним заголовком) и не нормирует несколько деталей, которые уже зафиксированы в реализации (`src/systems/physics.ts`) и на которые опирается будущая Rust-реализация (побитовая парность, CLI-6). `cli-testing/spec.md` (CLI-2) требует «непустой список `inputs[]`», хотя код (`scenario.ts:78`) и тесты уже трактуют это как «поле присутствует».

## Goals / Non-Goals

**Goals:**
- Развести номер PHYS-7 без потери текста ни одного из двух требований.
- Нормировать тай-брейк hit'ов (статика раньше динамики), `ratio()` (floor + насыщение), предел дистанции ~181 для квадратичных тестов, и три детали разрешения движения (порядок осей X→Y, 64-битный `separation()`, «ход разрешения выводится из направления пересечения»).
- Синхронизировать CLI-2 с фактическим поведением `runScenario` (`inputs` — наличие поля, не непустота) и с полем `visibility`.

**Non-Goals:**
- Не меняется поведение раycast'а, разрешения движения или `ratio()` — только формулировка спеки и одна проверка в `scenario.ts`, которая уже была избыточно строгой относительно кода вокруг неё.
- Golden-эталоны не пересчитываются: наблюдаемый вывод симуляции не меняется.

## Decisions

- **Перенумерация, а не правка на месте**: старый текст под заголовком PHYS-7 «Статические коллайдеры выводятся, а не хранятся» переносится на PHYS-10 через REMOVED+ADDED (OpenSpec: перенумерация требования — это REMOVED+ADDED, не MODIFIED). Альтернатива — оставить оба требования под PHYS-7 — отклонена: заголовок Requirement обязан быть уникальным, дельта-синхронизация матчит по точной строке заголовка.
- **`inputs !== undefined` вместо `inputs.length > 0`**: правило CLI-2 — «документ содержит `inputs[]`», не «непустой массив». Пустой `inputs: []` без `players` — валидный сценарий без вводов; текущая проверка `length > 0` совпадает по стечению для типичных сценариев (пустой массив и так не подаёт кадров), но по букве спеки не должна требовать `players` вовсе.
- **64-битный `separation()` остаётся комментарием, не кодом**: TS использует `number` (double), где сумма двух Q16.16 границ не переполняется; нормируется как требование к семантике (эквивалент i64 в Rust-порту), а не как новый тип в TS — заводить `bigint` ради тождества с Rust-портом здесь не нужно (YAGNI, TS уже точен в диапазоне double).

## Risks / Trade-offs

- [Риск] Синхронизация спеки задним числом может разойтись с реализацией, если кто-то параллельно правит `physics.ts` в этой же волне → Mitigation: правки кода в этом change ограничены только `scenario.ts` и комментариями в `physics.ts`; агент не трогает поведение raycast/separation/ratio.
- [Риск] REMOVED+ADDED для PHYS-7→PHYS-10 может визуально выглядеть как потеря требования в диффе → Mitigation: текст переносится дословно, задача явно описывает перенос в tasks.md.
