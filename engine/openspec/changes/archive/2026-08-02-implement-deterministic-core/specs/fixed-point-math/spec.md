## MODIFIED Requirements

### Requirement: FP-4 Переполнение wrapping

Переполнение SHALL быть wrapping (2's complement), совпадая с Rust `wrapping_*`. В debug-сборке переполнение SHALL дополнительно ловиться assert'ом.

**Debug-сборка** — отдельный режим сборки, в котором проверки корректности расчёта включены, а в релизном режиме отсутствуют полностью (не «выключены флагом в рантайме»): в Rust это `cfg(debug_assertions)`, в TS — статически подставляемое бандлером условие `process.env.NODE_ENV !== 'production'`. Assert MUST NOT влиять на результат операции: значение и в debug, и в release одинаково завёрнуто по 2's complement, различается только наличие диагностики.

#### Scenario: Переполнение в релизной сборке

- **WHEN** результат операции выходит за границы `i32`
- **THEN** значение заворачивается по 2's complement — детерминированно и одинаково во всех реализациях

#### Scenario: Переполнение в debug-сборке

- **WHEN** то же переполнение происходит в debug-сборке
- **THEN** срабатывает assert, показывая место потенциальной ошибки расчёта, а возвращаемое значение совпадает с релизным

#### Scenario: Сверка debug- и release-прогонов

- **WHEN** один сценарий прогоняется в debug- и в release-сборке
- **THEN** состояния по тикам совпадают побитово — asserts не являются частью симуляции

## ADDED Requirements

### Requirement: FP-5 Деление на ноль насыщающее

Деление на ноль SHALL возвращать насыщение по знаку числителя: `a > 0 → INT32_MAX`, `a < 0 → INT32_MIN`, `a == 0 → 0`. В debug-сборке оно SHALL дополнительно ловиться assert'ом, не меняя возвращаемое значение (FP-4).

Обоснование: деление на ноль — ошибка расчёта, но её обработка обязана быть одинаковой во всех реализациях. Нативные варианты расходятся (в Rust целочисленное деление на ноль паникует, в TS даёт `Infinity`), поэтому поведение задаётся спекой явно. Падение симуляции недопустимо: одна кривая формула не должна ронять матч, а расхождение TS и Rust в этой точке — десинк.

#### Scenario: Формула делит на нулевой параметр

- **WHEN** система вычисляет `div(damage, 0)` при положительном `damage`
- **THEN** результат — `INT32_MAX`, симуляция продолжается, а в debug-сборке срабатывает assert

#### Scenario: Парность реализаций на делении на ноль

- **WHEN** тот же расчёт исполняется в Rust-реализации
- **THEN** она тоже возвращает насыщение, а не паникует
