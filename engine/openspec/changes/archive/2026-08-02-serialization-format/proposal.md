## Why

Этап 9. После этапа 8 форматы компонентов, prefabs и систем существуют только как TS-типы: собрать сцену можно, лишь написав код. Редактору (этап 12) и CLI с golden-файлами (этап 10) нужно ровно обратное — один JSON, из которого поднимается мир с системами, и способ выгрузить состояние мира байт в байт.

Одновременно закрывается долг этапа 0: в roadmap рядом с «формальная спецификация core» стоит пометка «JSON-схемы ещё нет».

## What Changes

- `Serializer` (SER-2) получает конкретную форму: `encode(value) → Uint8Array` / `decode(bytes) → unknown`, реализация `jsonSerializer`. MessagePack не добавляется: его единственный потребитель — рантайм-снапшоты в сети (этап 17) и кольцевой буфер (этап 14), а зависимость, добавленная за восемь этапов до первого использования, успеет устареть.
- Plain-форма мира и снапшота — тот самый единый in-memory формат из SER-1: только числа, массивы чисел и строки, из неё одинаково идут и JSON, и будущий MessagePack. Возможна благодаря ID-4 и устройству масок: внутри мира нет ни замыканий, ни `Map` с нетривиальными ключами.
- Новое SER-6: детерминированный порядок ключей при сериализации. Без него golden-файл этапа 10 не может сверяться побитово, а дифф двух прогонов показывает перестановку ключей как изменение.
- Новое SER-7: конфиг сцены — `{components, prefabs, systems}` — и загрузчик, поднимающий из него мир и `SystemRegistry`. Это и есть «формат, с которым работает редактор».
- SER-5 уточняется по месту применения. JSON Schema остаётся опубликованным контрактом для редактора и внешнего тулинга, но точкой контроля в ядре не является: загрузчик проверяет строго больше — существование компонентов и полей, связанность переменных, состав prefab'ов (SYS-3, ECS-5). Ядро при этом MUST NOT тянуть валидатор JSON Schema в рантайм-зависимости.
- Схемы генерируются из закрытых наборов ядра (`actionNames`, `operators`, типы полей), а не пишутся руками, и тест сверяет закоммиченные файлы с генератором. Руками написанная схема разошлась бы с DSL на первом же новом действии, и разошлась бы молча.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `serialization`: SER-2 — форма интерфейса; SER-5 — роль JSON Schema и точка контроля; SER-6 (новое) — детерминированный порядок ключей; SER-7 (новое) — конфиг сцены и загрузчик.

## Impact

- Код: новые `engine/core-ts/src/serialization.ts`, `src/scene.ts`, `src/schemas.ts`; экспорт из `src/index.ts`; каталог `engine/schemas/` с четырьмя `.json`.
- Скрипт `npm run schemas` в `core-ts` перегенерирует файлы; тест падает, если закоммиченное разошлось с генератором.
- Зависимостей не добавляется — ни рантайм, ни dev. Валидатор JSON Schema в тестах не используется: генератор снимает главный источник расхождения, а содержательные проверки делает загрузчик.
- Разблокирует этап 10 (CLI + golden-файлы): выгрузка мира и загрузка сцены — ровно то, чего ему не хватает.
- Не входит: MessagePack, дельта-кодирование снапшотов (этап 14), версионирование формата и миграции — до первого сохранённого контента версионировать нечего.
