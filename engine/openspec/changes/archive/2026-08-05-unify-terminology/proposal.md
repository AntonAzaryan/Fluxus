# unify-terminology

## Why

Спеки выросли до 21 capability, и сквозной словарь начал расползаться: одни и те же слова означают разные вещи («снапшот», «override», «кадр», «канонический», «жёсткая граница»), одни и те же вещи называются по-разному («plain-форма» / «плоская форма», «golden-file тест» / «эталонный тест»), а один нормативный контракт (компонент-override уровня) вообще не имеет имени в спеке, хотя в реализации и golden-сценариях оно есть (`LevelOverride`). Это затрудняет чтение спек и провоцирует изобретение новых терминов вместо использования существующих.

## What Changes

Семь согласованных переименований; поведение движка не меняется нигде, кроме одного имени метода публичной поверхности ядра:

1. **QUERY-3**: «query возвращает снапшот» → «материализованная выборка». Слово «снапшот» освобождается для единственного смысла — полного состояния мира (SNAP-1); в QUERY-3 никакой копии нет, и старое слово вводило в заблуждение.
2. **TERR-4 / ARENA-5 / ARENA-6**: компонент-override уровня получает в спеках явное имя `LevelOverride` — то, которое уже носит в реализации (`LEVEL_OVERRIDE_COMPONENT`) и golden-сценариях. Дыра «имя — конвенция ядра, но нигде не названо» закрывается.
3. **NTR-2 / NTR-13**: «кадр» на транспортном уровне → «сообщение» (заголовок NTR-13 «Формат кадра» → «Формат сообщения»). **NTR-7 / NTR-8 / NTR-11 / CLI-10**: `InputFrame` в прозе — всегда «фрейм», не «кадр». Слово «кадр» остаётся только за кадрами рендера (NET-5).
4. **NET-12**: «канонический мир / каноническое состояние / канонический baseline» → «авторитетный». «Канонический» остаётся только за зафиксированными формами записи (канонический `inputs[]`, каноническое представление для хешей).
5. **SYS-7**: `SystemRegistry.override(system)` → `replace(system)` — **BREAKING** для публичной поверхности ядра (одно имя метода; JSON-описания, снапшоты и эталоны не затронуты). Освобождает слово «override» для двух оставшихся смыслов (`overrides` у spawn, `LevelOverride`).
6. Синонимы схлопываются до одного написания: «plain-форма» → «плоская форма» (SER-2, SER-6, TERR-6, CLI-2); «Golden-file тест» в прозе → «эталонный тест», «golden-эталон» → «эталон» (SYS-8, CLI-5, CLI-7, NTR-8; `golden-файл`/`golden-сценарий`/`golden-набор` остаются именами артефактов на диске); «жёсткая граница» / «жёсткий assert» → «жёсткий инвариант (`assertInvariant`)» (FP-4, ID-1, RNG-8, DIAG-1, CLI-7).
7. **NTR-3**: «Наблюдатели (OBS-2)» → «Observer'ы (OBS-2)». «Наблюдатель» остаётся за наблюдателем матча (спектейтором, NTR-9) и наблюдателем с `Vision` (FoW); `TickObserver` в прозе — «observer».

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

Во всех случаях меняется формулировка/имя, а не поведение; SYS-7 дополнительно меняет имя метода API.

- `ecs-foundation`: QUERY-3 (заголовок и термин «материализованная выборка»), ID-1 (терминология «жёсткий инвариант»)
- `data-driven-systems`: SYS-7 (`override` → `replace`), SYS-8 (терминология «эталонный тест»)
- `terrain`: TERR-4 (имя `LevelOverride`), TERR-6 («плоская форма»)
- `arena`: ARENA-5, ARENA-6 (имя `LevelOverride`)
- `netcode`: NET-12 («авторитетный» вместо «канонический»)
- `netcode-transport`: NTR-2, NTR-13 («сообщение» вместо «кадр»), NTR-3 («observer'ы»), NTR-8, NTR-11 («фрейм» вместо «кадр», «эталоны»); плюс правка Purpose («опоздавший фрейм») напрямую в главной спеке
- `fixed-point-math`: FP-4 («жёсткий инвариант»)
- `diagnostics`: DIAG-1 («жёсткий инвариант»)
- `cli-testing`: CLI-2 («плоская форма», «эталонный тест»), CLI-5 (заголовок «Эталонные (golden) тесты»), CLI-7 («жёсткий инвариант», «эталоны»), CLI-10 («фрейм»)
- `rng`: RNG-8 («жёсткий инвариант»)
- `serialization`: SER-2, SER-6 («плоская форма»)

## Impact

- **Спеки**: 23 требования в 11 capability — только текст, ни одного изменения поведения, форматов данных или чисел.
- **Код**: `engine/core-ts/src/systems/registry.ts` — метод `override` → `replace` (плюс сообщения ошибок), ссылки в комментариях (`dsl/evaluatedSystem.ts`) и тестах. Имена полей, компонентов, JSON-схем и плоская форма снапшота не меняются — golden-эталоны остаются побитово прежними.
- **Не затронуто**: `LevelOverride` уже так называется в коде и golden-сценариях; переименования «фрейм/сообщение/авторитетный/эталон/жёсткий инвариант/плоская форма» — чисто документные.
