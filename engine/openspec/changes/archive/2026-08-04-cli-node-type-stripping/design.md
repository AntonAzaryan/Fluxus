## Context

Ядро исполняется прямо из исходников, без шага сборки. Так решено в `bin/sim.mjs`: собирать `dist` перед каждым прогоном инструмента, который зовут из тестов и из командной строки, дороже, чем не иметь артефакта сборки вовсе. Держится это на двух вещах: Node >=22.18 стрипает типы сам, а `registerHooks` дорезолвливает `./x.js` → `./x.ts`.

У этого решения есть цена, которую до сих пор не проговаривали: **strip-only режим удаляет типы, но ничего не порождает**. Значит, в `src/` запрещён любой синтаксис TypeScript, у которого есть рантайм-семантика:

- parameter properties (`constructor(private readonly x: T)`) — разворачиваются в присваивание поля;
- `enum` (не `declare`) — порождает объект;
- `namespace` с рантайм-содержимым — порождает объект.

Ограничение нигде не было записано, поэтому его нарушили: обе системы со списком модификаторов объявили поле через параметр конструктора. Это идиоматичный TypeScript — без явного запрета так и будут писать.

## Goals / Non-Goals

**Goals.** Вернуть `bin/sim.mjs` в работоспособное состояние на текущем Node, не меняя ни байта в выводе. Сделать так, чтобы повтор дефекта краснел в тестах.

**Non-Goals.** Не вводится шаг сборки. Не меняется норма `CLI-1`. Не трогаются golden-эталоны — их неизменность здесь критерий правильности, а не побочный эффект.

## Decisions

### Решение: убрать parameter properties из `src/`, а не включать `--experimental-transform-types`

Рассматривались два варианта.

**(A) Убрать сахар из исходников.** Заменить parameter property на явное поле плюс присваивание.

**(B) Добавить `--experimental-transform-types`** в npm-скрипт `sim` и shebang `bin/sim.mjs`. Так уже было сделано в `net-ts`.

Выбран **(A)**, по трём причинам, в порядке весомости.

1. **Вывод CLI сверяется побайтно.** `CLI-4`/`CLI-5` строят golden-набор на точных байтах, а `test/cli.test.ts` дополнительно требует пустой stderr. Флаг `--experimental-transform-types` печатает `ExperimentalWarning: Transform Types is an experimental feature and might change at any time` при каждом прогоне. В stdout она не попадает, но появляется в stderr любого запуска CLI и в выводе `serve.mjs`/`play.mjs` — там она уже мозолила глаза (проверено прогоном: с флагом предупреждение есть, без флага stderr пуст). Инструмент, чей вывод — эталон, не должен подмешивать в поток предупреждения рантайма.

2. **Цена варианта (A) околонулевая: вхождений всего два.** Грепом по обоим пакетам parameter properties нашлись ровно в двух местах — `VisibilitySystem` и `TimeScaleSystem`, и в обоих один и тот же параметр `modifiers`. Остальные ~45 приватных полей в `core-ts` и `net-ts` и так объявлены явно (`InputSystem`, `MatchServer`, `MatchClient`, `PhysicsWorld` …), то есть вариант (A) не вводит новый стиль, а возвращает два класса к уже господствующему в репозитории.

3. **Флаг экспериментальный по названию и по поведению.** Его семантика может измениться между версиями Node — предупреждение говорит это прямым текстом. Ставить запускаемость CLI, то есть `CLI-1`, в зависимость от экспериментального флага — заложить тот же дефект повторно, только с другим триггером.

Довод против (A) — потеря краткости — принимается: три строки вместо одной на класс. Обменивается на то, что ядро грузится штатным `node` без флагов, а это ровно то свойство, ради которого шага сборки нет.

### Решение: снять флаг и с `net-ts`

В `net-ts` флаг был вынужденным: пакет импортирует ядро целиком, вместе с его parameter properties. После правки ядра проверено, что ни в `core-ts/src/`, ни в `net-ts/src/` не осталось ни одной конструкции, не поддержанной strip-only (грепом по parameter properties, `enum` и `namespace`; собственных parameter properties у `net-ts` не было изначально).

Проверено прогоном, а не рассуждением: `serve.mjs` и `play.mjs` подняты штатным `node`, клиент подключился к серверу по WebSocket, `worldInit` совпал (`b6e5ead5`), в выводе ноль `ExperimentalWarning`.

Оставлять флаг «на всякий случай» было бы хуже, чем снять: он маскирует ровно тот класс дефекта, который этот change чинит. Пока `net-ts` запускается с флагом, новое parameter property в ядре сломает `core-ts`, но не `net-ts` — и сигнал получится противоречивым.

### Решение: регрессия — подпроцесс, а не импорт

Тест мог бы просто импортировать `runScenarioBytes`. Так он ничего бы не поймал: vitest грузит `src/` собственным трансформом, который поддерживает весь TypeScript, — именно поэтому 403 теста были зелёными при нерабочем CLI.

Поэтому `test/cli.test.ts` запускает `bin/sim.mjs` отдельным процессом через `process.execPath`. Существенны две детали:

- **`NODE_OPTIONS: ''` в окружении подпроцесса.** Иначе унаследованный извне `--experimental-transform-types` замаскировал бы поломку: тест зеленел бы там, где `npm run sim` у человека падает.
- **stderr проверяется на пустоту отдельным тестом.** Разбор stdout как JSON ловит мусор только в stdout, а предупреждения рантайма Node пишет в stderr. Без этой проверки возврат к флагу прошёл бы мимо теста.

Тест сверяет `worldInitHash` не с захардкоженной строкой, а с эталоном на диске: CLI обязан выдавать то же, что in-process прогон в `golden.test.ts` (`CLI-4`), и обновляться вместе с ним при законной смене эталонов.

## Risks / Trade-offs

**Риск: правка молча меняет поведение.** Parameter property и явное присваивание различаются порядком инициализации полей — сахар присваивает параметры до тела конструктора. Здесь это безразлично: в обоих классах `modifiers` не читается ни в теле конструктора, ни в инициализаторах полей, а присваивание поставлено первой строкой, то есть исходный порядок сохранён. Контроль — неизменность всех десяти эталонов: `git status engine/tests/golden` обязан остаться пустым, и вдобавок каждый сценарий прогнан через CLI и сверен с эталоном побайтно.

**Trade-off: ограничение на `src/` остаётся вне спеки.** Осознанно — см. proposal, раздел «Почему без правки спек». Компенсируется тем, что запрет записан в шапке `bin/sim.mjs` (почему нельзя) и проверяется `test/cli.test.ts` (что будет, если нарушить). Тест ловит нарушение в любом файле, попадающем в граф импортов сценария, а не только в двух исправленных.
