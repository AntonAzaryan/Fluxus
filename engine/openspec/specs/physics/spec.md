# Physics Specification

## Purpose

Модуль коллизий и Line-of-Sight. Минимальный по объёму, но детерминированный: от корректности `raycast` зависит FoW, а значит — то, какие данные вообще уходят клиенту.

## Requirements

### Requirement: PHYS-1 Логика в 2D, представление 3D

Игра — 2.5D: логика SHALL считаться в 2D, представление SHALL быть 3D.

Высота SHALL входить в симуляцию исключительно как дискретный целочисленный уровень террейна (`terrain` TERR-1, TERR-4). Непрерывная вертикальная координата MUST NOT участвовать в расчётах симуляции: она существует только в представлении.

Пересечения — коллизии и полёт снарядов — SHALL считаться в 2D-проекции независимо от уровня участников. Обрывы влияют на них не как перепад высот, а как статические коллайдеры (`terrain` TERR-5).

#### Scenario: Проверка попадания снаряда

- **WHEN** снаряд летит над неровным рельефом
- **THEN** пересечение считается в 2D-проекции; разница уровней стрелка и цели на попадание не влияет

#### Scenario: Снаряд с верхнего уровня по нижнему

- **WHEN** сущность на уровне 1 стреляет в сущность на уровне 0 и между ними нет коллайдера обрыва
- **THEN** снаряд попадает: высота не является препятствием сама по себе

#### Scenario: Попытка ввести непрерывную высоту

- **WHEN** система хочет вести расчёт по вертикальной координате в fixed-point (дуга снаряда, высота прыжка)
- **THEN** это отклоняется: в симуляции существует только целочисленный уровень, дуга — задача представления

### Requirement: PHYS-2 Примитивные коллизии

Поддерживаться SHALL примитивные коллизии: AABB, круги, простые формы.

#### Scenario: Коллайдер персонажа

- **WHEN** задаётся форма столкновений персонажа
- **THEN** используется круг или AABB, а не полигональная сетка

### Requirement: PHYS-3 Детерминированная физика

Физика SHALL быть детерминированной и считаться в fixed-point.

#### Scenario: Повторный прогон столкновения

- **WHEN** тот же сценарий столкновения прогоняется повторно
- **THEN** результат совпадает побитово

### Requirement: PHYS-4 Реализация через Physics API

Физика SHALL реализовываться через Physics API (DI) и SHALL быть отключаемой на уровне ядра. Для данной игры она обязательна — FoW/LoS требует raycast. Отключаемость сохраняется как свойство ядра, а не как конфигурация этой игры.

#### Scenario: Сборка ядра без физики

- **WHEN** ядро собирается для сценария без коллизий и FoW
- **THEN** оно тикает без Physics API

### Requirement: PHYS-5 Минимальный broad-phase / narrow-phase

Физика SHALL ограничиваться минимальным broad-phase / narrow-phase, без сложной динамики.

#### Scenario: Запрос на симуляцию физики тел

- **WHEN** появляется идея добавить полноценную динамику (массы, импульсы, суставы)
- **THEN** она отклоняется — модуль остаётся минимальным

### Requirement: PHYS-6 Детерминированный raycast

Physics API SHALL предоставлять `raycast(from, to, mask) → hit?` — детерминированный (fixed-point) луч для Line-of-Sight. `mask` SHALL фильтровать, по каким коллайдерам считать пересечение; для LoS — коллайдеры с тегом `blocksVision`. Луч MUST NOT самопересекаться с сущностью-источником: источник исключается вызывающей стороной или маской.

#### Scenario: Проверка видимости через укрытие

- **WHEN** между наблюдателем и целью стоит объект с тегом `blocksVision`
- **THEN** `raycast` возвращает hit, и цель не попадает в `visibleTo`

#### Scenario: Луч из центра собственного коллайдера

- **WHEN** raycast пускается из позиции наблюдателя, у которого есть коллайдер
- **THEN** собственный коллайдер не даёт ложный hit на нулевой дистанции

### Requirement: PHYS-7 Детерминированный порядок hit'ов

Порядок разрешения hit'ов в raycast SHALL быть детерминированным: сортировка по `(distance, entity.index)`, где при равной дистанции tie-break идёт по `index` из generational ID.

#### Scenario: Два коллайдера на одинаковой дистанции

- **WHEN** луч пересекает два объекта ровно на одном расстоянии
- **THEN** первым считается объект с меньшим `index`, и результат не расходится между прогонами и реализациями
