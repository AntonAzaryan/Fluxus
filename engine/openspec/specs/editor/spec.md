# Editor Specification

## Purpose

Визуальный редактор геймплея на Compose Multiplatform. Работает поверх data-driven ядра: его единственный выход — валидные JSON, которые ядро исполняет без генерации кода.

## Requirements

### Requirement: ED-1 Kotlin + Compose Multiplatform

Редактор SHALL быть написан на Kotlin + Compose Multiplatform, минимум под Desktop.

#### Scenario: Запуск редактора

- **WHEN** разработчик открывает редактор на десктопе
- **THEN** приложение работает нативно, без веб-обёртки

### Requirement: ED-2 Работа поверх data-driven ядра

Редактор SHALL работать поверх data-driven ECS-ядра.

#### Scenario: Появление нового типа компонента в ядре

- **WHEN** ядро получает поддержку нового типа поля
- **THEN** редактор оперирует им через описание схем, а не через захардкоженный список

### Requirement: ED-3 Выход — валидные JSON

Выходом редактора SHALL быть валидные для ядра JSON.

#### Scenario: Сохранение системы

- **WHEN** пользователь сохраняет собранную систему
- **THEN** записывается JSON, проходящий валидацию схемой ядра; генерация кода не требуется

### Requirement: ED-4 Редактор триггеров

Редактор SHALL предоставлять node-based или list-based редактор триггеров (Events / Conditions / Actions).

#### Scenario: Сборка реакции на событие

- **WHEN** дизайнер описывает «при смерти сущности заспавнить взрыв»
- **THEN** это собирается из блоков события, условия и действия, без ручного JSON

### Requirement: ED-5 Визуальное конструирование выражений

Редактор SHALL позволять визуально конструировать JsonLogic-выражения, без ручного синтаксиса.

#### Scenario: Формула с вложенными условиями

- **WHEN** дизайнер собирает формулу урона с несколькими ветвлениями
- **THEN** она строится визуально, а на диск уходит корректный JSON-AST

### Requirement: ED-6 Редактор component-схем

Редактор SHALL включать редактор component-схем, в том числе FoW-компонентов `Vision`/`Visibility`/`Stealth`.

#### Scenario: Добавление поля в компонент

- **WHEN** нужно добавить поле с дефолтным значением
- **THEN** это делается в редакторе схем, и обновлённая схема сразу доступна ядру

### Requirement: ED-7 Редактор prefabs

Редактор SHALL включать редактор prefabs/сущностей.

#### Scenario: Создание нового типа снаряда

- **WHEN** собирается новый prefab снаряда
- **THEN** набор компонентов и начальные значения задаются визуально

### Requirement: ED-8 Валидация в реальном времени

Редактор SHALL валидировать редактируемые данные в реальном времени.

#### Scenario: Ссылка на несуществующий компонент

- **WHEN** в системе указан компонент, отсутствующий в реестре
- **THEN** ошибка подсвечивается сразу в редакторе, а не при загрузке в ядро

### Requirement: ED-9 Встроенный runner симуляций

Редактор MAY включать встроенный runner симуляций через ядро для превью; в MVP он SHALL считаться опциональным.

#### Scenario: Быстрая проверка способности

- **WHEN** дизайнер хочет увидеть результат правки немедленно
- **THEN** при наличии runner'а он прогоняет сцену прямо из редактора; при его отсутствии проверка идёт через CLI
